# 主机隔离租约与失联撤销

## 适用范围

新隔离要求 Agent 以 root systemd 的 `alinksec-agent.service` 或 Windows SCM 的 `alinksec-agent` 服务运行，当前进程必须匹配服务 PID。Linux 要求 iptables 与 ip6tables 同时可用，命令受时间和输出大小限制。前台、容器、其他服务名、旧版本或残留旧隔离标记均不声明契约 1；平台在指令创建、实际派发及当前认证通道发送时复核。重新连接先声明当前能力，旧连接的声明不能授权新连接。

Windows 使用动态 WFP 会话，过滤 IPv4/IPv6 ALE 连接、接收授权，不修改防火墙配置文件默认策略。Linux 使用本次专属链与精确跳转，只移除属于本次隔离的规则。保留原有管理员策略；管理端点放行也不能覆盖管理员已存在的拒绝规则。Linux 保留 IPv6 邻居发现，既有业务连接不作为通用例外。管理端 DNS 地址在创建租约时有界解析并固定，不在隔离期间开放 DNS 或整个网段。

旧 Linux `isolated.json` 在启动时尝试清理旧专属规则；清理未成功不开放新契约。旧 Windows 隔离修改过全局默认策略且未记录原值，必须由管理员按原策略恢复，不猜测写回。无原生契约的 Windows 恢复指令因此拒绝；旧 Linux 保留原规则清理入口。

## 租约与独立看护

1. 原子保存私有租约记录、不可变恢复身份与当前 ID，再安装本次二进制副本对应的独立原生看护服务。接受仅回 `RECEIVED`。
2. 看护安装本次规则后进入 active。Agent 每秒经当前 mTLS 通道发送含新随机数的实时状态，平台核对能力、租约代次、修订和指令后沿同一连接回传。Agent 仅消费最新、3 秒内、一次性的匹配随机数。
3. 首次有效往返才记录隔离成功；每次有效往返把期限延后 10 秒。旧连接、旧租约、延迟或重复随机数、断开连接后的回包均不能续租。确认信号不进入离线指令队列，不创建可重放 ACK。
4. 独立看护每 200 毫秒检查期限及单次运行中的单调时钟界限。Agent 崩溃、失联、时钟倒退或本地停服触发清理；重启看护只清理已存在的隔离，不重新应用或重置期限。Linux 原生服务配置自动重试；Windows 看护退出时动态会话的本次过滤器由系统移除。
5. 操作员解除隔离也由看护清理；清理全部成功后才记录 finished、回解除成功。部分应用失败同样清理。清理失败保留 attention、错误与恢复服务，继续重试，不声称已恢复。清理操作的系统调用及调度耗时不包含在 10 秒判定期限内。

工作目录下 `isolation/leases/<ID>.json` 是持久历史，`current.json` 指向当前租约，`<ID>/identity.json` 是清理身份备份。原子写、目录同步与跨进程锁保护记录。Linux 目录属主必须匹配且仅属主可访问；Windows 使用受保护 DACL。可变记录损坏时用独立身份清理；两份身份同时损坏或管理员删除记录不在可自动恢复保证内。管理员不要并发修改服务、私有目录或专属防火墙对象。

清理完成记录与看护服务注销在同一租约锁内完成；注销前确认当前 ID，旧看护不能删除后续隔离的新服务。尚未完成清理时拒绝卸载；卸载持有隔离事务锁直到确认 Agent 服务已停止，停服失败保留工作目录。原生服务管理器、内核或主机整体失效期间，Linux 不能承诺用户态看护按时运行；主机启动时由独立服务续办原期限并清理，实际断电验收留待系统适配阶段。

## 平台状态与历史

当前认证连接的实时状态是当前隔离状态来源。租约代次、修订、待执行指令与数据库条件更新一起拒绝旧报告覆盖新指令。历史隔离成功 ACK 在后续自动解除后仍是成功历史，不能把主机重新标成已隔离。操作员解除尚未完成时也不被较旧 active 状态覆盖。

平台超过 12 秒没有收到有效 active/准备/解除状态时显示“隔离状态待确认”，保留不确定性。只有收到本机清理结果才显示正常与自动解除原因。主机页每 3 秒更新，已打开详情即使被当前筛选排除也继续同步。

自动解除、应用失败及清理失败事件保存稳定报告 ID，每次认证连接补传。数据库持久隔离结果回执与告警写入同一事务；传输去重保留期届满后重放同一事件也不重复增加告警。回执随主机删除清理。Agent 最多保留 64 份租约结果；达到上限拒绝新隔离，管理员应先导出核对再清理已完成历史。已完成看护副本在下一次隔离时清理，未完成记录不自动删除。

## 验证入口与边界

本地串行测试覆盖确认绑定、过期和倒退时钟、主进程消失、看护重启、部分应用/清理失败、损坏记录回退、卸载互斥、持久历史及补传。SQLite 集成验证实际状态与晚到 ACK、旧租约、新指令、状态待确认和永久事件去重，捕获数据库查询响应供页面演练。

CI 的 `deploy/tests/agent-isolation-native.sh` 及 Windows 同类入口仅允许可丢弃的 GitHub 托管 runner，分别在 Linux amd64、Linux arm64、Windows amd64 使用真实原生 Agent/看护服务和 mTLS。检查新连接业务阻断、原有管理员放行规则保留、手动解除、旧/延迟确认不能续期、主进程停止后恢复、看护被强制终止后撤销、证书保留与历史补传；检查 IPv4/IPv6 专属策略安装及撤销。IPv6 真实外网数据包、整机断电与完整系统矩阵仍待系统适配验收，不以规则存在代替这些结果。

完整前端产物在 CI 使用上述 SQLite 捕获响应运行 `web/test/isolation-browser.mjs`。本机只构建主机页预览，构建与浏览器检查期间暂停并最终恢复已有后端，避免 2 GiB 机器承受完整前端与后端的并发负载。最终验收状态和 CI 编号在原生演练完成后补录。
