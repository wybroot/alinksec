# Agent 配置防篡改与可信恢复

## 保护范围与信任起点

Linux 和 Windows 的 `run`、`install` 使用 `config-integrity/record.json` 留存 `agent.yml` 与最近一次经认证通道接受的 `policy.json`。运行时使用可信内容，每 2 秒比较磁盘文件的 SHA256；文件大小和 mtime 不能代替内容检查。管理地址、TLS 服务名和 CA 引用从可信配置恢复，保留已注册的证书与 Agent 身份。

安装在持有配置进程锁时创建可信记录；注册成功后清除可信记录及可写配置副本中的注册码。已有 Agent 首次运行新代码时，对原有配置和策略进行一次有界、验证后的迁移，管理员应先确认旧配置可信。迁移后，编辑原文件不会成为新的可信版本。

工作目录与记录目录收紧为私有访问。Linux 使用当前运行身份所有的 0700 目录和 0600 单链接普通文件；Windows 记录使用受保护 DACL，仅 SYSTEM/Administrators 可访问，文件所有者设置为 Administrators，以便安装账户与 SYSTEM 服务切换。Agent 运行期间持有系统文件锁，其他运行进程、安装或本地改配不能并行替换基准。

这是用户态配置留存、检测和恢复。首次迁移前内容的真实性、root/Administrator 攻陷、Agent 进程被控制、二进制或操作系统被替换不由本模块保证；SHA256 不作为针对这些权限的签名认证。管理员仍能删除整套可信状态。范围仅为配置和策略，不扩展为全部本地状态、特征库或证书的防篡改。

## 运行、离线与重启

| 情况 | 行为 |
|---|---|
| 内容改变，包括同长度、同 mtime 修改 | 继续使用可信配置；记录预期/观察摘要，安全可写时原子恢复副本 |
| 文件删除、无效 YAML/JSON | 继续使用可信配置；可恢复时重建，重启不解析损坏副本 |
| 链接、reparse point、设备、FIFO 或超限输入 | 拒绝作为配置读取，不覆盖链接目标；报告副本修复受阻 |
| 权限不再私有 | 检测并原子替换普通副本以收紧权限；不可写则保留失败状态 |
| 外部配置为只读挂载 | 可信记录决定运行参数；不能恢复副本时记为 `blocked` |
| 未接受策略时出现新的 `policy.json` | 忽略未授权文件，记录 `unapproved_file_ignored` |
| 断网 | 继续检测并持久化告警，重连使用稳定 ID 补传 |
| 运行中可信记录损坏 | 保留内存快照并尝试持久恢复；失败记录日志并重试 |
| 启动时可信记录丢失、损坏、摘要不一致或配置路径改变 | 明确失败；存在启用标记时禁止重新学习磁盘副本，须恢复完整可信状态 |

记录通过私有临时文件、同步和原子替换提交；Linux 同步目录，Windows 使用写穿透替换。YAML 上限 64 KiB，策略上限 1 MiB，可信记录上限 2 MiB，路径上限 4096 字节。Windows 仅接受本地驱动器路径，拒绝设备/UNC 路径及备用数据流。父目录和打开文件均检查链接及对象身份，不打开特殊文件进行无限读取。

平台策略先验证并提交可信记录，再应用到运行防护。`policy.json` 是可恢复副本；进程、文件、登录防护，以及主动/周期病毒检测和白名单均使用已接受内容。周期检测不会在下次哈希检查前读取外部策略关闭自己；策略版本也从可信记录恢复。

## 合法本地变更

先停止 Agent 服务，将完整新 YAML 写入独立候选文件，再执行：

```sh
alinksec-agent config apply --from /admin/agent-new.yml --workdir /var/lib/alinksec-agent
```

自定义配置路径需补充与原服务相同的 `--config <原路径>`。Windows 使用同一命令和本地绝对路径，以管理员运行。命令检查候选大小、YAML 字段和管理地址，获取同一系统锁后提交，启动服务后生效。运行中的服务会阻止该命令，无效内容不会覆盖基准，解析错误不回显候选值。外部副本不可写时，可信提交仍有效，服务会报告副本恢复受阻。

直接编辑原文件会触发恢复。已有可信配置不能再次 `install` 覆盖；首次安装网络失败可修复网络后执行 `run` 继续注册。平台策略通过现有 mTLS `PolicySync` 更新，不由本地改配命令替换。

## 事件与保留边界

事件类型为 `self_defense`，规则 ID 为 `agent-config-integrity`，名称为“Agent 配置防篡改”，处置为 `trusted_config_in_use`。详情包含稳定 ID、时间、文件类别/路径、原因、预期/观察 SHA256 和副本处理结果，不含配置正文或注册码。`restored` 表示普通副本已恢复；`blocked` 表示继续使用可信内容，但副本未能恢复。

记录保留最近 64 个事件，同一持续异常去重，超限淘汰最旧事件。事件中的路径最多保留 1024 字节，截断时标记 `path_truncated`，保证长路径转义后仍能持久化和上报。断线与退出不改变留存事件的 ID，重连可以重新发送。V018 的 `t_agent_config_event_receipt` 按认证主机和事件 ID 永久去重，回执与告警同一事务写入；通用去重期届满也不会增加同一事件的告警次数，删除主机时级联删除。该容量是有界留存，不承诺无限离线审计。

## 验证

本地真实 Agent 进程已通过 13 项：CA 验证注册、注册码清除、合法离线改配、认证策略留存、在线配置和策略恢复、断网事件落盘、坏配置及缺失策略下重启、稳定 ID 补传、证书保留、运行中改配拒绝、无效改配脱敏、合法变更重启生效。

配置与通信测试另覆盖同长度/mtime 篡改、链接目标保留、权限变化、可信记录丢失/损坏拒绝重新学习、运行中恢复、并发策略提交、持久写入失败重试、周期/主动检测白名单绕过。CI 增加 Linux amd64/arm64 真实 systemd 和 Windows amd64 SCM 场景，必须输出完成后的原生产物。最终 CI 和合并验收记录完成后补齐。
