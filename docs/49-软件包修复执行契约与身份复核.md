# 软件包修复执行契约与身份复核

本阶段为同一漏洞模块补齐执行能力识别及 Agent 本机安装前后复核。平台声明、包内字段和实际安装版本分别检查；厂商真实性、目标包发行版适用性和修复版本确认仍需后续完成。

本文件记录 Linux RPM/DEB 契约的实现阶段。后续新增的 Windows 原生更新使用独立执行契约，不开放注册表库存推导或上传 MSU 安装，见 [Windows 更新发现与自动修复](62-Windows更新发现与自动修复.md)。

## 能力和审批

软件库存协议增加 `package_repair_contract`。Linux Agent 完整采集时声明版本 1，Windows 保持 0。V011 为已有主机增加默认 0 的能力字段，两套数据库各完成 11 次迁移、仍有 50 张表；历史迁移不修改。旧 Agent、未知契约和注册表库存可以显示资产及结果，但不能自动修复软件包。采集失败仍保留此前库存和声明，失败状态会阻止修复。

创建任务和审批派发均核对当前完整库存、原检测身份、规则指纹和能力。任务保存契约版本、来源、包架构、发行版及版本、已装完整版本；旧任务缺契约时不能派发，需重新采集并创建审批。接口另返回 `execution_supported`，页面保留不支持的检测项并说明更新支持该系统的 Agent 或人工处理。单项及批量提交只包含符合条件的检测项。

## 本机执行

Agent 仅接受 RPM/DEB 契约 1，校验软件名、摘要和完整安装身份，修复记录必须与审批 finding 对应。依次执行：

1. 查询本机完整库存，要求指定名称只有一个安装，且来源、架构、发行版版本和已装完整版本与审批相同。同名多架构或跨包管理器安装会拒绝；采集不完整也会拒绝。
2. 核对磁盘余量，查询失败或少于 500 MiB 时停止；通过平台 CA 校验 HTTPS 下载并核对 SHA256。
3. 使用 `rpm -qp` 或 `dpkg-deb --show` 读取二进制包名、完整版本和架构。字段必须与审批相符，RPM 源码包拒绝。解析只读取元数据，不运行维护脚本。
4. 下载后、调用安装器前再次查询安装身份，任何变化或查询失败都停止。
5. 包管理器安装后再次查询，要求仍为同一发行版、来源和架构且达到目标完整版本，才上报 `success=true, verified=true`。RPM 保留 epoch 和 release，DEB 使用完整版本。

元数据进程需要 `prlimit`，限制 256 MiB 地址空间、10 秒 CPU/墙钟时间及 16 KiB 输出。安装进程限制 15 分钟和 64 KiB 输出；超限或超时终止进程组并报告失败，不自动回滚已发生的安装副作用。工具缺失时停止，不能绕过元数据核对。安装日志不打印带凭据的下载地址。

服务端仅接纳已经派发、属于该 Agent 的待处理记录。软件包成功缺少 `verified` 时记录失败，漏洞保留未修复；终态不能由后续重复结果覆盖。配置类结果不受该软件包复核标记影响。

## 边界与验证入口

包头证明包内名称、版本和架构，并不能证明厂商签名、回移修复内容、依赖完整性或该二进制适用于目标发行版。`--nosignature` 仅用于元数据读取，不能据此宣称签名认证。前后采样与外部包管理器操作没有统一原子锁；安装副作用及失败恢复需人工检查。注册表应用身份不能推断 MSU 适用性，Windows 自动软件包修复在本阶段关闭。

回归覆盖旧/未知契约、审批前能力丢失、身份漂移、错误包头、解析失败、安装失败、安装后查询失败、未复核成功及重复结果。原生 DEB/RPM 夹具读取实际包头，验证维护脚本未执行；受限命令验证超时、输出及内核资源限制。CI 的真实双 Agent 工作流验证完整库存、契约 1、安装前包头及身份、安装后完整身份，以及 SQLite/PostgreSQL 结果落库；重启与备份恢复检查契约持久化。生产 bundle 浏览器单独验证旧 Agent 提示与修复入口禁用。

整个漏洞模块仍在开发。接下来完成平台确认的修复目标、补丁实际适用范围、历史迁移和缺失覆盖、重新安装后的检测状态、审批权限与并发异常；本阶段不能替代这些验收。
