# Agent 升级看护与自动回退

## 适用范围

自动升级要求 Agent 以原生 `alinksec-agent` 服务运行：Linux 为 root systemd 服务，Windows 为 SCM 服务。当前进程必须与该服务的 MainPID 相同。前台进程、容器内进程、其他服务名称与旧 Agent 不声明升级契约 1，平台拒绝自动升级。旧安装首先需要人工更新到支持该契约的 Agent，再作为原生服务启动。

心跳声明 `upgrade_contract=1`，指令携带 `execution_contract=1`；平台在创建、实际派发及当前认证通道发送时复核。重新接入以当前通道的声明为准，旧连接和数据库中曾经保存的能力不能授权新连接。旧的排队升级指令需要重新创建。

## 执行流程

1. 异步接受指令，回 `RECEIVED`。平台与 Agent 均限制包体 128 MiB，上传版本标识禁止路径字符、已存物料不覆盖；通过平台 CA 验证 HTTPS 下载、核对 SHA256 与 Go OS/架构；临时文件排他创建，使用带事务 ID 的独立候选路径，不覆盖已有临时文件。
2. 把当前二进制复制到私有工作目录 `upgrade/<事务ID>/watchdog[.exe]`。记录原进程 PID/启动时间、旧/新摘要、目标版本、指令和启动期限。
3. 安装独立的 `alinksec-agent-upgrade-watchdog` 原生服务。Linux unit 与 Windows 自动启动服务均独立于 Agent；等待看护循环的就绪记录后才替换二进制。
4. 先持久化 pending 记录，再把旧文件移到 `.old`、候选移到原路径；退出当前进程，由原服务管理器启动候选。
5. 候选完成配置、身份、防护与通信初始化，成功发送经过 TLS 验证的心跳；升级期间每秒发心跳。看护核对目标版本、候选摘要、服务 PID/启动时间，以及同一通道至少 5 秒的连续心跳，才写最终成功结果。重连会重新累计稳定窗口。
6. 从准备记录起 60 秒未确认健康，独立看护停 Agent、校验并恢复旧二进制，再请求启动旧服务。期限不会因看护重启而重置。失败候选留为 `.bad-<事务ID>`，结果为失败并说明是否已回退。

60 秒是启动判定期限，不包含之后服务停止、文件恢复与启动的耗时。Windows 若正常停服超时，只在 SCM 当前 PID、实际进程映像路径及候选摘要均吻合时终止该进程，再等待 SCM 确认停止；身份不符时拒绝强杀。

## 持久化与失败处理

- `upgrade/state.json` 是当前事务；`upgrade/results/<事务ID>.json` 保存最终结果或需人工关注的回退错误。原子文件写入、文件系统同步与跨进程锁保护状态。Linux 使用目录同步，Windows 使用带写穿标志的文件移动。
- 看护是旧版本副本；候选无法启动、重复崩溃或不支持确认逻辑时，不依赖候选执行回退。独立服务在主机启动时恢复尚未完成的事务；不重置已保存的期限。
- 文件替换的任一步中断后，按摘要识别当前、`.old`、`.bad-<事务ID>` 的位置继续恢复。已提交的成功结果优先于未完成的 phase 写入，避免成功后因看护重启反而回退。
- 旧备份丢失、摘要改变、服务停止或启动失败时，不声称已经恢复。保留 rollback 状态和看护服务，原生服务恢复策略会重试，并保存需关注的错误。管理员应先检查受保护记录和服务状态，不删除尚在执行的记录。
- 升级或回退进行中拒绝平台重启和卸载，防止卸载与恢复互相覆盖。下载阶段被外部强制结束时，可能留有 `<二进制>.upgrade-<事务ID>.new`；可核对进程与事务后清理，它不会阻塞后续升级。
- 最终 ACK 与 `self_defense` 失败事件按稳定报告 ID 在每次认证连接补传；重复已接受的升级指令不重新安装。一次传输成功不删除本地结果。回退不改配置、证书、注册身份、策略或安全库。
- 结果最多保留 64 份；达到上限后拒绝新升级，管理员应先导出并确认历史结果再清理已完成记录。事务完成后的看护服务会注销；后续升级清理已完成事务的看护副本。未完成事务不清理。

本机制不恢复升级后由其他模块写入的数据，不执行主机重启或服务名称迁移。不要在升级维护窗口并发修改 Agent 服务、二进制及受保护工作目录。整机断电/重启的现场验收与原生服务的看护重启续办测试分别记录。

## 验证

本地有界串行回归覆盖健康/失联/稳定窗口、PID 复用、版本不符、替换各阶段中断、备份异常、服务停启重试、已提交结果一致性、结果补传及重复指令。服务端覆盖旧能力拒绝、当前通道绑定、离线派发复核与双数据库迁移。

CI 在 Linux amd64、Linux arm64 和 Windows amd64 上使用真实原生服务、mTLS/HTTPS 下载及实际 Go 候选：坏摘要不改变服务；正常候选由新会话确认成功；故意启动失败的候选触发自动回退；看护重启续用原期限；回退后验证证书、终态、失败事件与重放。只在可丢弃的 GitHub runner 启用原生 fixture；本机不创建生产服务。具体通过状态以模块验收记录为准。
