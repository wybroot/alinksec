# 功能真实性与可用性审查

2026-10-28，按用户反馈重新审查本地 `develop`。起点为 `168f34cc11fa712c771b6dfadf26420b7393bb0a`，工作区另有扫描排队期限修复。本文是源码链路审查，不是新的全功能实机验收；下列问题均未因记录本文而修复。历史发布、测试计数和现场验收范围保持原样。

结论：当前不能笼统称为“功能已完成、只剩现场验证”。既有真实的采集、检测和执行代码，也存在未接通的页面操作、没有可用内容的执行入口、失败被显示为空数据，以及缺失的检测能力。页面可打开、接口返回成功、指令已发送和目标机器实际完成操作是不同的验收阶段。

> 2026-10-29 起的修复与剩余缺口见 [88 · 审查缺陷修复进度](88-审查缺陷修复进度.md)。下文保留 2026-10-28 的审查证据，不代表修复后的现状。

## 已确认问题与修复优先级

P1 表示会误导安全判断或阻断主要操作；P2 表示管理功能、结果追踪或使用体验存在缺口。证据中的“当前路径”是按源码可达性判断，未在运行中的用户环境制造破坏性事件。

### F01 · P1 · 告警“处置”没有下发安全动作

- 入口：[Alerts.vue](../web/src/views/Alerts.vue) 的 `handle` 调用 `/api/alerts/{id}/handle`，随后提示“处置动作已下发”。
- 实际：[AlertQueryService.handle](../server/alinksec-service/src/main/java/com/alinksec/service/query/AlertQueryService.java) 只更新告警状态、备注、处理人和时间，没有派发 Agent 指令。忽略也使用同一结束状态，状态列显示“已处置”。
- 影响：操作者可能以为威胁已经被终止或隔离，实际只是关闭了一条记录。这是当前页面可达的错误承诺。
- 完成条件：明确区分确认记录、忽略和真实处置；真实动作必须绑定主机、目标证据、指令编号与最终回执，失败或离线不能显示完成。不能把所有告警的确认按钮直接改成无差别杀进程。

### F02 · P1 · 当前模板导入流程不能提供基线自动修复内容

- 入口：[Baseline.vue](../web/src/views/Baseline.vue) 有“一键修复所选”，但只有 `fixable` 项才能选择。
- 实际：[BaselinePackageFormat](../server/alinksec-service/src/main/java/com/alinksec/service/baseline/BaselinePackageFormat.java) 的检查项格式只有检查与 `remediation` 等字段，不接受修复步骤；[BaselinePackageService](../server/alinksec-service/src/main/java/com/alinksec/service/baseline/BaselinePackageService.java) 创建检查项时不写 `fix_spec`。
- 旧默认模板的自动修复已由 [V006](../server/alinksec-bootstrap/src/main/resources/db/common/V006__retire_legacy_baseline.sql) 清除；[FixTaskService](../server/alinksec-service/src/main/java/com/alinksec/service/fix/FixTaskService.java) 对没有 `fix_spec` 的项明确拒绝执行。
- 影响：通过当前正式导入、审核和发布流程得到的模板，不能靠这个按钮完成配置自动修复。底层执行器存在，不能证明普通用户有可用的修复内容。历史自建数据库内容不能代表新部署默认能力。
- 完成条件：先选少量明确系统范围的检查，交付受审核的修复定义、适用性判断、变更预览、备份、执行、重载与效果复核；不支持的项明确提供人工整改。不能恢复已经淘汰的通用旧脚本来充数。

### F03 · P1 · 容器采集失败可能清空旧资产

- 实际：[collector.go](../agent/internal/collector/collector.go) 在执行前将采集器加入 `Collected`；[container_linux.go](../agent/internal/collector/container_linux.go) 在 `docker ps`、`kubectl` 失败或响应解析失败时直接返回，没有独立的失败状态。
- [AssetService.replaceSnapshot](../server/alinksec-service/src/main/java/com/alinksec/service/asset/AssetService.java) 只要 `Collected` 包含 `containers`，就删除旧容器记录并写入本次列表。
- 影响：权限撤销、运行时暂不可用等情况可以形成空快照，页面把“没有取到”呈现成“没有资产”。Docker 和 Kubernetes 一方失败时也缺少分别保留旧数据的依据。端口、进程等采集器有类似直接返回路径，需逐项扩展检查；软件采集已有单独状态保护，不应一概归为同样问题。
- 完成条件：各来源分别上报成功、失败、部分结果、时间和原因；失败保留上次成功数据并标记过期，只有可信的完整空快照才能清空。验证正常清空与权限失败两种情况。

### F04 · P1 · Linux 勒索响应没有可信写入者，不能自动终止写入进程

- 实际：[attrib_linux.go](../agent/internal/guard/attrib_linux.go) 的采集初始化和运行方法为空，归因固定返回 `linux_writer_capture_unavailable`，不选择终止目标。
- [Protect.vue](../web/src/views/Protect.vue) 仍提供 `kill` / `kill_and_isolate` 策略选项。页面说明了无法核实则跳过终止，但没有把 Linux 缺失实现作为明确的平台能力边界。
- 影响：诱饵和批量变化检测、显式隔离可以工作；不能由此承诺 Linux 勒索进程已被杀死。此前移除猜测性终止是避免误杀，并没有补齐检测源。
- 完成条件：实现可核验的文件操作与进程实例关联，或在目标能力中明确禁用该动作；验收必须覆盖真实写入者、无辜旁观进程、PID 复用、事件丢失和降级。

### F05 · P1 · 进程防护覆盖远小于通用 EDR 的名称暗示

- 实际：[edr.go](../agent/internal/guard/edr.go) 每 2 秒枚举，对新 PID／创建时间匹配路径、命令行等规则；初始化已有进程只建立基线。
- 默认 [PR-0001](../server/alinksec-bootstrap/src/main/resources/db/sqlite/V001__initial.sql) 匹配 `xmrig`、`minerd`、`kdevtmpfsi`、`kinsing` 四个程序名。规则命中后的结束进程与取证有真实实现。
- 影响：短生命周期进程可能漏检，默认矿工改名可绕过，不能据此承诺反弹 Shell、提权、注入或凭据窃取的完整检测。
- 完成条件：按具体威胁交付采集来源、检测规则、适用系统、误报控制与可重复的无害场景；分别验收启动前已存在、启动后新建、短命和改名行为。

### F06 · P1 · 告警列表只查前 100 条，待处置筛选可能漏项

- 实际：[fetchAlerts](../web/src/api/index.js) 固定请求 `page=1&size=100`，丢弃服务端总数；[Alerts.vue](../web/src/views/Alerts.vue) 在这 100 条中本地筛选等级和待处置，没有翻页。
- 影响：最近 100 条之外的未处理告警无法通过“待处置”标签找到，空表不能代表没有待处理风险。
- 完成条件：服务端筛选和分页，保留总数、稳定排序及加载失败状态；至少验证第 101 条为未处理、前 100 条均已处理的情况，并覆盖处理中状态。

### F07 · P2 · 主机分组只有展示外壳

- 实际：[Hosts.vue](../web/src/views/Hosts.vue) 的“主机组”选择器没有 `v-model` 或变更处理；[fetchHosts](../web/src/api/index.js) 将每行 `group` 固定为 `—`。
- [HostQueryService](../server/alinksec-service/src/main/java/com/alinksec/service/query/HostQueryService.java) 可以列出分组及计数，但主机列表既不按组过滤，也不返回组名。
- 影响：下拉选择不能改变结果，表格无法显示实际分组。当前控制台未形成分组维护、成员管理、筛选的完整使用流程。
- 完成条件：按分组 ID 串通列表、分页总数、成员变更和权限；校验跨页、不分组主机以及组内无主机的情况。

### F08 · P2 · 升级执行存在，但页面缺少批次逐机结果

- 实际：[System.vue](../web/src/views/System.vue) 提供上传、手填 Agent ID 下发和版本分布；[UpgradeController](../server/alinksec-gateway/src/main/java/com/alinksec/gateway/rest/UpgradeController.java) 没有对应批次任务查询入口，`dispatch` 返回数量和版本。
- [upgrade](../agent/internal/upgrade) 有真实下载、校验、替换与看护实现，不能称为假升级。
- 影响：用户无法在当前升级页面逐台追踪排队、安装、重启、确认和回退原因；全局版本分布不能替代本次任务结果。
- 完成条件：提供按平台筛选的主机选择、批次与逐机记录、失败原因、版本／摘要确认及回退结果；“已下发”不作为成功终态。

### F09 · P2 · 配置修复中的服务重启步骤是空执行

- 实际：[actions.go](../agent/internal/fixer/actions.go) 的 `service_restart` 只写日志并返回成功；`chown`、`registry_set`、`audit_rule` 返回不支持。[fixer.go](../agent/internal/fixer/fixer.go) 只有独立填写 `requires_restart` 才设置待重启标记。
- 范围：旧默认模板已停用、正常新模板无修复步骤，因此不能据此声称当前标准导入流程已发生错误重启成功。执行器收到包含此步骤的内容时，该步骤确实不会执行。
- 完成条件：建立明确的“未执行／待人工窗口／已重载并复核”状态；不支持的动作在变更前拒绝。服务重启须有维护窗口与业务影响控制，不能为了让按钮有效而强行重启服务。

### F10 · P2 · 漏洞页保留无请求的配置修复成功分支

- 实际：[Vuln.vue](../web/src/views/Vuln.vue) 的 `submitFix` 在 `fixType === 'config'` 时只改本地状态并提示“配置类修复任务已下发”，没有 API 调用。
- 可达性：[fetchVulns](../web/src/api/index.js) 当前统一生成 `fixType: 'pkg'`，批量操作也只构造包修复。因此这是残留的假成功代码，不是当前正常数据下已复现的配置任务。
- 完成条件：移除这个分支及无对应定义的示例步骤，或接入经适用性审核的真实任务；以服务端任务记录和 Agent 回执判定状态。

### F11 · P2 · “最近拦截”也包含没有拦截的告警

- 实际：[ProtectRuleService.listBlocks](../server/alinksec-service/src/main/java/com/alinksec/service/protect/ProtectRuleService.java) 按事件类型取记录，没有要求 `action_taken` 为成功阻断；[Protect.vue](../web/src/views/Protect.vue) 将其命名为最近拦截记录。
- 影响：仅告警、终止失败或未执行也可能出现在“拦截”表中。即使另有动作列，标题仍不能代表实际阻断数量。
- 完成条件：区分检测事件与动作结果；阻断统计只取有成功执行证据的记录，未确认和失败分别展示。

## 后续交付标准

1. **先恢复结果可信度**：F01/F03/F06/F11。确认记录不能冒充处置，采集失败不能冒充空资产，未展示不能冒充没有风险。
2. **补可操作流程**：F07/F08；每次操作可找到任务、目标、执行状态、失败原因和恢复入口。
3. **交付少量真正可用的修复内容**：F02/F09/F10，按具体系统与配置逐项完成，不能只留下执行器和按钮。
4. **按威胁补齐检测与响应**：F04/F05，以及 SSH 日志源、Web／容器能力边界；每项都要有正常行为对照、无害触发、失败、恢复与最终状态核验。

每项记录“源码完成、局部验证、实机验证、待验环境”，不能用测试总数代替完成状态。本轮仅更新审查记录和当前完成度说明，没有修改业务代码、部署服务、推送、触发 CI 或操作用户主机防护；原有未提交扫描修复保留。继续在 `develop` 本地串行验证，保留当前内存、PSI 和磁盘保护阈值。现场 25／26／27 的其他系统、私有服务、规模和时长缺口仍待验，28 仍在本次新部署范围之外。
