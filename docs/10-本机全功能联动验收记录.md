## 实测修复

| 缺陷 | 原行为 | 修复及复测 |
| --- | --- | --- |
| REL-019 基线结果丢失与数值比较缺失 | 检查结果没有项目 ID，平台无法正确关联；内置数值操作不被识别 | 统一保留项目 ID，支持有限数值比较；自动化及内置 60 项实际执行通过 |
| REL-020 SQLite 扫描任务不能结束 | `LEAST` 不受 SQLite 支持，结果事务回滚，任务停留执行中 | 使用两种数据库均支持的 CASE；漏洞、端口、弱口令及病毒任务真实回写通过 |
| REL-021 并发读后写事务失败 | 资产报告与接口操作交错时出现 `SQLITE_BUSY_SNAPSHOT` | SQLite 使用 IMMEDIATE 事务；两个实际 JDBC 连接的并发回归及 Agent 联动通过 |
| REL-022 病毒白名单没有保护 Agent 文件 | 平台过滤结果，但 Agent 已先隔离文件 | 快照带白名单、变更后推送，Agent 在隔离前检查；快照原子写入；实际文件保留及删除白名单后的检测通过 |
| REL-023 实时扫描沿用旧特征与 clean 缓存 | 常驻引擎没有采用更新后的特征，旧缓存跳过新增命中 | 特征库缓存受互斥锁保护，引擎刷新数据库指针，持久化缓存绑定版本；不重启 Agent 的实时检测通过 |
| REL-024 实际 Agent 二进制不能上传 | Spring 默认上传上限拒绝约 20 MiB 二进制，返回内部错误 | 单文件 500 MB、请求 512 MB、临时内容落盘；超限返回 413；真实上传和包下发通过 |
| REL-025 断线事件重启后丢失 | 六条安全事件只有两条落盘，Agent 重启后只补传两条 | 断线直接持久化，断开时保存未消费业务报告；并发回归及六条实际事件重启补传通过 |
| REL-026 服务端换 IP 后网页持续 502 | Nginx 在启动时解析服务端地址，后续仍连接旧 IP | 镜像生成配置模板，默认后端为 server，Docker DNS 每五秒刷新；实际换 IP 后不重启网页即可恢复 |
