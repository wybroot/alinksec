**建议补齐顺序与验收门槛**

1. **先恢复可信与安全边界（P0）。** 修复遥测认证/启停、审批、进程实例绑定；默认不对未经验证的外部事件自动执行危险响应。同步修正文档：自写过滤器、外部遥测接收器、Linux 无归因如实标注。完成标准是绕过/伪造/越权/重放负向测试全部符合预期，而不是页面按钮能点。
2. **把已承诺功能真正串起来（P1）。** 修复主源码与测试编译、双数据库迁移、旧迁移摘要、真实规则序列化、策略发布一致性、诱饵文件安全、WAF 持久化、封禁/解封 Agent 分支、过期修复交付与最终回执；补必要控制台入口。完成标准是从空库、实际 API、原生 Agent 到目标系统效果与最终回执全链路一致，并覆盖失败、离线、重启、恢复。
3. **优先接成熟引擎。** 若主攻主机安全，先落地一个 Falco/audit 方案；若主攻业务 Web，先真实 Coraza/CRS。ClamAV/YARA 完成实际库与运行验收，Trivy 补软件依赖/镜像覆盖。ALinkSec 专注资产身份、策略审核、任务、证据、受控响应和运营界面。没有必要同时自研内核驱动、WAF 引擎和通用检测语言。
4. **把规则做成可持续交付内容。** 每条规则记录数据源、目标平台、行为语义、版本/摘要、正常对照、误报例外、检测延迟、事件丢失、允许响应和回滚方式。正则只覆盖线索时明确说明；MITRE 标签不能替代实际技术覆盖。每次更新必须测试数据库中的实际规则和最终下发内容。
5. **最后完成产品级现场验收。** 延续既有 25/26/27 清单：其他 OS/内核、Windows 长期观察、私有外部服务、完整 ClamAV 库、200 台真实主机/72 小时。记录覆盖率、误报、漏报、p95 延迟、丢事件、CPU/RSS/IO、动作成功率和撤销成功率；缺环境保持待验。28 不纳入本次新部署范围。当前机器继续串行、保留资源保护阈值，不在这台约 2 GiB 主机上堆叠引擎。

验收证据的最小单位应是“某系统/某采集源/某规则版本/某威胁与正常对照/某执行动作/某失败恢复”，而不是模块名、接口 200、组件健康或测试总数。当前最需要补的是这条证据链，以及上表已定位的真实断点。
