# 系统适配与规模验收

本组将第 25／26 项的系统稳定性、适用范围、负载证据和 CI 调度一起维护。工作流中的检查必须在同一源码提交通过；构建成功不能代替原生执行。原始日志、固定参数、每秒样本和失败记录均保留，完整结果以对应 CI 产物为准。

## 系统矩阵

| 环境 | 实际检查 | 证据边界 |
| --- | --- | --- |
| Ubuntu 24.04 amd64／arm64 原生 runner | 原有全部 Agent、systemd、隔离、配置、基线、软件包、文件事件及应用回归 | 对应 runner 的实际内核与权限；不外推其他发行版 |
| Ubuntu 22.04 amd64／arm64 原生 runner | 实际身份、安装软件盘点、私有中文状态、原生文件事件、systemd 升级／回退、隔离撤销、配置恢复 | `system-acceptance-linux-*` 包含宿主身份及真实生命周期结果 |
| Ubuntu 18.04／20.04／22.04／24.04、Debian 12、CentOS 7、Rocky 8／9 用户态，两个 Linux 架构 | 同提交静态 Agent 的实际版本；生产软件包采集器；中文目录与状态；实际 inotify 写入／重命名；关闭事件采集 | 只读、禁网、普通 UID、192 MiB 容器；记录拉取后的镜像 ID、digest 和架构；内核属于宿主 |
| Windows Server 2022／2025 x64 原生 runner | 原有完整 Windows Agent、SCM、WFP、ETW、升级、配置、登录、文件、扫描、合规及证据回传检查 | 分别保留完整产物与 OS Caption／Version／BuildNumber；不以一个版本代替另一个 |

GitHub 可用标签以[官方 runner 文档](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)为准。工作流显式固定 `windows-2022`／`windows-2025`，实际镜像版本另外记录。

CentOS 7 原生旧内核、Ubuntu 18／20 原生整机、统信 UOS、麒麟、Windows Server 2016／2019 和 Windows 10／11 仍需对应现场环境。容器结果不证明旧内核、宿主 systemd、安全策略或完整等保规则适用。Windows 更新保留真实 WUA 接口和受控安装提供者的原有检查，实际 WSUS／公网补丁安装与重启归入现场外部服务联调。

## 原生稳定性回归

- 未确认隔离租约的测试在确认规则已经应用后，受控推进到原有 350 ms 截止时间；另外检查启动时已过期的租约绝不应用规则。生产时间和恢复截止时间保持原值。
- Windows 文件归因在 DOS 设备路径映射后展开实际 8.3 名称。已有父目录可展开时，重命名／删除后的缺失叶子保持原名字。只展开短名称，不解析链接目标；解析失败保留原路径。身份、进程创建时间、原生来源、成功 OperationEnd、只读访问和多写入者限制全部保留。真实 ETW 回归使用长策略目录、短路径写入和中文文件名，原历史失败的根因仍不能仅凭这一修正追认。
- 升级测试通过共享删除的有界文件快照观察二进制，允许实际替换；JSON 使用现有安全快照读取。损坏状态立即失败，替换间隙的缺失文件保留诊断；25 秒观察上限不扩宽。持有观察句柄跨真实 rename 的回归另外验证旧快照和新路径字节。
- Windows 病毒库父目录句柄允许共享删除，旧读者继续绑定原目录身份。回归持有文件及目录描述符跨真实目录退休，验证相对打开仍读取旧库，并且文件仍拒绝并发写入。原始 native delta 失败日志继续保留，不将未知外部持有者归因给杀毒软件。
- Agent 联动启动失败立即记录进程退出码／信号；额外上传每份最多 256 KiB 的脱敏日志尾部。证书、私钥、配置、数据库和原始 fixture 目录不上传；缺日志不能解释为启动成功。

## 固定规模测试

配置位于 [`deploy/tests/profiles/scale-ci.json`](../deploy/tests/profiles/scale-ci.json)，执行前固定并记录 SHA-256。每个 cluster 架构作业使用真实受限 PostgreSQL 账号、Redis、RabbitMQ、两个 Java 进程，以及原有真实 Agent。模拟客户端分别连接两个副本；真实 Agent 继续通过既有 HAProxy 主备入口验证故障恢复。

| 参数／门禁 | 固定值 |
| --- | --- |
| 模拟 mTLS 协议客户端／真实 Agent／实际 runner | 200／1／1 |
| 预热／持续窗口／排空上限 | 15／180／30 秒 |
| 每个模拟客户端心跳／原始日志周期 | 5／10 秒，每批一行 |
| 模拟 collect 下发／实际 Agent collect | 每秒 2 次／每 10 秒一次 |
| 原始每秒样本／模拟指令／实际指令最少数 | 175／350／17 |
| 最少实际日志行 | 3000，所有成功 Send 的日志均须在 SQL 中找到 |
| 模拟 REST 下发至 DONE 落库 p95 | ≤ 1000 ms；模拟客户端不执行系统动作 |
| 实际 collect 至 DONE 落库 p95 | ≤ 5000 ms，单独统计 |
| 日志与心跳 SQL 可见 p95 | ≤ 5000 ms |
| Dashboard REST 响应 p95 | ≤ 1000 ms；另外检查新在线主机首次可见 ≤ 5000 ms |
| 单 Java RSS／驱动 RSS | ≤ 896／384 MiB |
| 收件箱未释放报告／逻辑字节 | ≤ 10000／128 MiB |

计时使用同一宿主的 CLOCK_MONOTONIC；心跳通过服务端 `last_heartbeat` 与发送墙钟建立观察对应，再以单调时钟计算持续时间。100 ms SQL 轮询测量包含观察上界。日志必须先经真实队列应用，再独立检查 SQL 中每个客户端的连续序号、UTF-8 原文、事件标识和内容 SHA-256。最终未排空、丢样本、指令失败、提前退出、失去任一副本连接、资源越界均失败；不能用均值隐藏尾部延迟。

`driver-events.jsonl` 保留发送时间和身份，`seconds.jsonl` 保留 SQL 观察、每个 Java 的实际 RSS／CPU、驱动和依赖 cgroup 总内存／CPU／进程数，`command-observations.jsonl` 保留下发与 DONE 的单调时间。`result.json` 保存分位数、固定参数、实际持续时间及清理后的模拟会话数。驱动只接受显式 fixture 门控和回环端点，不作为交付 Agent 发布。

该测试不包含 VictoriaMetrics 的持续指标负载，不证明大盘时序指标延迟，也不证明 200 台真实主机在线 72 小时、2000 台满规模或整机系统处置小于 1 秒。`longSoakAccepted` 和 `real200HostAcceptance` 明确为 false。原有集群容量拒绝、重放、同主机顺序、Redis／RabbitMQ 停启和原生 Agent 故障恢复检查全部保留；短时负载不代替物理填满全部容量的演练。

## 现场长期验收

目标仍沿用总体架构中的 200 台真实 Agent、72 小时和指标延迟要求。现场报告至少包含目标 CPU／内存／磁盘、各发行版及内核、Agent 二进制 SHA-256、真实主机数、完整 259200 秒时间范围、资产／基线／日志／指标负载、VictoriaMetrics 延迟、实际指令动作和所有重连／失败／资源原始样本。样本缺口、降载、重启与补跑均单独记录；达标前保留待验收状态。不得把 CI 参数中的 180 改成 259200 后自动认为完成了真实主机长期验收。

## 严重度契约复核

| 来源 | 原始契约 | 当前边界 |
| --- | --- | --- |
| Agent protobuf 安全事件 | INFO=1、LOW=2、MEDIUM=3、HIGH=4、CRITICAL=5 | `SecurityEventService` 保留原始数值 |
| 历史告警展示、部分基线／CVE 定义 | 1低、2中、3高、4严重，部分查询兼容5严重 | 不能将全部历史数值按 protobuf 重新解释 |
| 进程规则 | 规则1..4，在 Agent `processSeverity` 转为 protobuf | 规则值与事件值应分别审计 |
| 特征库包 | 有1..5输入 | 不能假定全部等同历史CVE1..4 |

发现现有告警展示尚未完整按来源区分非严重级别：protobuf HIGH=4、MEDIUM=3 等仍可能沿用旧展示含义。这是保留的来源契约缺口；本组未修改历史严重度，也不宣称已完成统一归一。后续修正须同时覆盖新事件、历史聚合、通知、报表和双数据库，避免全表重新解释。该项与未提供的现场系统和长期负载一起保留在验收记录中。

## CI 组织

原 `build-and-test` 的前端、Maven、Agent 和浏览器检查保留。系统原生脚本迁到同架构 `linux-native`，真实 SQLite 本机维护迁到 `sqlite-maintenance`，生产／Lite 部署及两种数据库完整维护迁到 `deployment`。每个独立 runner 从同提交构建所需成品；共享端口、容器、服务和数据库的步骤在该 runner 内顺序执行。第二次 `--no-cache` 变版本构建保留。单独的部署浏览器产物与原应用浏览器产物分别上传。

完整 CI 为本组统一执行；原有场景不因拆分减少。本机低内存约束继续只用于本机：构建／验证串行，语言堆限额和内存／PSI 看护保持启用。
