# 补丁包头核验与修复目标人工复核

> 版本基线：v0.0.4。已按本版核对「补丁包头核验与修复目标人工复核」的操作、实现引用与适用边界；历史日期及验证结果仍只对应其原始提交。版本差异见[发布说明](releases/v0.0.4.md)，全部资料见[文档索引](README.md)。

当前开发模块仍为漏洞判断与修复适用性，分支为 `vulnerability-applicability`。

## 导入与依据边界

离线补丁导入必须提供发行版标识、精确发行版版本、实际二进制包架构、包名及完整版本。系统显示名称仅用于展示，不再参与兜底匹配；没有“空系统版本即通用包”的自动修复回退。离线导入仅支持 Linux DEB/RPM，Windows MSU 仍由运维人工处理。后续新增的 [Windows 原生更新](62-Windows更新发现与自动修复.md) 使用主机当前 WUA 来源发现与审批，不通过该离线仓库安装。

平台使用系统原生工具读取真实包头并检查包名、完整版本、包来源及包架构。RPM 保留 epoch、上游版本和 release，仅规范化数值 epoch；DEB 保留完整原文。不能以原生比较结果相等代替具体二进制版本一致，例如 DEB `1.0` 与 `0:1.0-0`，或 RPM release `03` 与 `3`，都不允许替代所确认的包。

读取包头不认证发布者、包签名、发行版来源或 CVE 修复真实性。声明的发行版范围来自上传人；当前 CVE 的修复目标来自已记录来源的二进制规则声明。平台区分“包头已核验”“人工复核”与“未认证厂商声明”，不会把包内版本当作厂商修复证明。

读取进程清除继承环境、关闭输入，设置 no_new_privs、地址空间 128 MiB、CPU 10 秒、墙钟 10 秒、输出 16 KiB、单文件 1 MiB、打开文件数 32 和禁用 core。控制信息使用独立临时目录，采样限制 64 项及 4 MiB；失败时终止进程组并清理。root 服务切换至 UID/GID 65534 并清除 capabilities 和附加组。系统缺少原生工具、无法降权或超出限制时导入失败，不回退到高权限或仅信任上传字段。这些限制不构成完整文件系统或网络隔离沙箱。不会安装包或执行 maintainer scripts。运行镜像提供 `dpkg`、`rpm` 和 `util-linux`。

单个上传限制为 128 MiB，解析在单服务进程中串行进行。首次校验通过后保存不可变文件名、实际字节 SHA256、包头快照和声明范围。重复上传创建新对象，保持旧对象及任务引用；上传失败或外层事务回滚清理新文件。

## 操作步骤

在基线核查页打开“离线补丁仓库”，按真实包头填写字段并导入。选择“查看并复核”，输入 CVE，查看具体补丁 SHA256、声明范围、当前规则来源、规则指纹和受影响范围。核对发行版适用性、来源及该完整二进制版本的 CVE 修复依据，填写至少 10 字说明并明确勾选确认。

复核人从已验证登录身份读取，忽略请求正文中的伪造身份。admin/operator 可以导入、复核和撤销，viewer 仅可读；无登录身份禁止修改。记录包含具体对象、对象范围与元数据摘要、字节摘要、CVE、规则来源/指纹、复核人、时间和说明。复核表示运维人工确认，不是平台独立认证厂商证明。与当前规则范围或声明目标不对应、仍处于受影响范围、存在同范围不可评估声明的目标均不能复核。

撤销需填写原因，保留原始复核及撤销人、时间、原因。列表显示未撤销记录数量，该数量不代表当前漏洞规则仍适用。修改补丁元数据、规则或字节会使旧复核不能用于自动修复；历史包默认没有包头验证及复核，需重新导入。

## 任务创建与派发

自动修复要求完整且当前的软件身份、Linux 执行契约、当前规则证据、比已安装版本更高的完整目标版本，以及精确同发行版、版本、来源和包架构下的有效人工复核。同版本重装和降级由运维人工处理。列表保留缺少复核的结果并说明阻断原因。

创建任务固定具体补丁 ID、SHA256、对象摘要和复核记录。任务目标不保存下载凭证。派发前重新核对安装身份、检测结果、规则指纹、固定对象和复核是否撤销，并读取文件重新计算字节摘要。成功后为同一固定对象生成新的下载凭证。后续上传或复核另一个包不会替换待派发任务的对象；旧任务缺少固定对象与复核时必须重新创建。已派发 Agent 继续执行安装前后身份与包头复核，见[执行契约与身份复核](49-软件包修复执行契约与身份复核.md)。

## 验证与后续范围

使用真实 DEB/RPM 夹具验证包名、完整 epoch/release、架构、错误字段、损坏包和安全限制，不安装夹具。覆盖导入与复核分离、旧包迁移、长版本、过期上下文、规则变更、字节变化、撤销、重复上传固定对象、任务审批回滚和上传事务回滚。原生 RPM 工具在 CI 强制存在；本机没有 RPM 工具时该用例明确跳过。CI 同时检查生产 root 镜像中真实降权包头读取、真实浏览器人工复核及实际 Agent 修复流程，保留原有 SQLite/PostgreSQL 回归与迁移、重启恢复检查。

本阶段已纳入完成并合并的漏洞模块；缺失适用性／覆盖、历史重新发现、审批身份、窗口、并发及异常处理见[覆盖与派发闭环](51-漏洞覆盖历史与审批派发闭环.md)，来源退役与有界 NVD 同步见[来源治理](52-安全来源治理与有界NVD同步.md)。本文保留包头和人工复核的有限语义，不把单一声明扩大成厂商认证。
