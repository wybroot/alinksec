# 多来源可信度与冲突处理

第 18 项覆盖安全库中的文件 SHA-256、内部检测规则和整条 CVE 声明。ClamAV、原生 YARA 的私有规则库，以及已签名基线包继续使用各自的来源与发布机制。

## 管理员策略

来源等级分为未复核、已复核、优先采用；先比较等级，再比较 0 至 100 的优先级。默认均未复核，人工来源优先级为 100，其余为 0。仍相同时人工来源优先，再按来源标识选择。等级表示本地管理员的处理决定，不表示独立验证了发布者真实性。远端文档内的信任等级、置信度或审核文字不会设置本地策略。

隔离移除该来源的当前检测贡献，保留原始声明并允许后续同步，以便继续复核。暂停同步保留现有贡献；整源退役移除贡献并阻止这个来源标识再次导入。三者含义不同。人工来源也可隔离；整源退役继续排除人工来源。

保存策略需要当前有效管理员、当前策略修订号和变更原因。账号禁用、角色变更、并发保存和旧修订号在数据库事务内检查。

## 整条选择和冲突

选择整条对象，不拼接不同来源的字段。自动处理规则如下：

| 情形 | 处理 |
|---|---|
| 来源等级或优先级不同 | 采用排名最高的来源 |
| 同级同优先级的 CVE 适用规则不同 | 暂停采用，等待管理员复核 |
| 同级同优先级的内部规则正文不同 | 暂停采用，等待管理员复核 |
| 同一哈希的名称、严重程度不同 | 显示差异，按来源排名采用一条声明 |
| CVE 标题、说明、严重程度、引用说明不同，但适用条件一致 | 显示内容差异，按来源排名选择完整公告 |
| 当前选中公告已撤销 | 保留撤销声明，不自动回填较低来源 |
| 没有可用来源 | 暂停采用，保留原始声明和历史 |

CVE 适用条件包含软件、系统、发行版、包来源和架构、版本条件、修复版本及依据的类型、判断与包范围。引用者、引用地址和说明文字保留在内容摘要中；它们本身不构成适用范围冲突。重复规则和规则排列顺序不改变自动冲突判断。声明文字变化仍会使绑定旧内容的人工决定失效。

管理员可以指定一个未隔离、未退役的当前来源，暂停采用该条目，或恢复自动选择。撤销声明仍不能借指定来源转成有效的受影响规则。

指定来源和暂停采用都绑定当时所有当前候选的规范化内容摘要、适用摘要、来源策略及其修订号。候选内容、来源集合、撤销状态或策略变化后，条目保持暂停，直到重新复核或恢复自动选择。相同内容再次同步不会仅因入库时间变化而使决定失效。恢复自动选择保留递增决定修订号，旧客户端不能在重置后重复使用旧修订。

## 事务、修复和下发

导入、退役、来源策略与条目决定共用现有数据库目录锁。来源策略或决定、有效 CVE、特征包版本、待下发状态及审计在同一事务内提交。存储、容量或发布失败会回滚全部变更，并清理未提交的包文件；已验证的旧版本继续可用。

候选依据或策略变化会使关联补丁复核失效，并终止旧漏洞结果的当前有效性，即使最终选中的软件范围指纹没有变化。补丁复核、修复任务创建与派发、下载授权均实时检查当前来源选择。迁移前已经存储的冲突无需等下次重新导入才会阻止自动修复；历史原始依据不被补写为新审核结论。

新的暂停状态不会生成可修复的当前漏洞结果。覆盖统计在存在暂停采用的 CVE 时保守标记为未知，并明确记录暂停数量；这会影响所有包的覆盖解释，不能据此确认某个包不受影响。无来源声明的旧记录仍保留原有的历史语义。

特征推送与资产重评的待处理标记持久化保存。提交后执行，并在服务重启、配置移除、全部来源暂停或一次下发失败后继续重试。清除标记时检查已处理的发布编号与规则修订，避免清掉并发提交的新任务。推送成功表示完成当前分发尝试，离线 Agent 仍须连接并正常接收更新；已经在离线主机执行的动作不能由服务端追溯撤回。

OpenCTI 页面区分通过本来源筛选的候选数量与全局最终选择；逐条指标依据显示当前是否采用该来源。来源隔离、条目暂停或另一来源胜出均不能继续显示为本来源有效贡献。

## 容量与审计

- 每条对象最多 128 个当前来源。新导入超过边界时整笔回滚。旧数据已超过边界时暂停采用，仅展示前 128 个候选，并标明摘要不完整；仍可逐源退役，降到边界内后再复核。
- 来源策略最多 128 个，条目处理记录最多 10000 个。恢复自动选择保留原记录及递增修订号。
- 单次来源策略最多重选 50000 条 CVE，超过时拒绝整次操作。单条原始公告继续受 256 KiB 边界约束。
- 每个来源策略或条目最多保留最近 50 条治理记录，单条快照最多 64 KiB。快照记录策略、处理前后状态和候选摘要，不承诺永久保存每个候选的全部历史原文；当前原始声明继续可查，原有 CVE 导入审计保持原语义。
- 签名发布按来源候选分组流式处理，PostgreSQL 在事务内使用游标；内部规则继续受 2000 条、2 MiB 等现有发布限制。列表分页最多 100 条，审计分页最多 50 条。

迁移 V031 增加来源策略、条目决定、治理事件和待下发状态四张表。SQLite 与 PostgreSQL 均为 31 个迁移、90 张业务及迁移表。

## 验证入口

`SourceTrustIntegrationTest` 在 SQLite 与 PostgreSQL 执行相同的策略、冲突、候选绑定、隔离、过期决定、撤销墓碑、事务回滚、并发旧修订及持久重试测试。`VulnerabilityWorkflowIntegrationTest` 补充真实 DEB 固定对象、补丁复核与旧下载令牌的来源授权验证。接口测试检查认证账号绑定及三角色写权限。

`web/test/source-trust-browser.mjs` 使用数据库实际捕获的响应验证生产页面、管理员操作、只读角色、手机布局、错误展示及迟到响应。页面故障和异常原文形状明确作为浏览器注入场景记录。最终验收还须完整功能分支 CI、产物摘要和截图核对，以及合并后精确 main 的同等核对；实现期间的单项通过不代替这些步骤。
