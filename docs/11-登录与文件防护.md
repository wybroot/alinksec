# Linux 登录与文件完整性防护

> 适用版本：v0.0.1；更新日期：2026-10-02。本文引擎与真实联动验收仅适用于 Linux。受控主机安装原生 Agent，默认策略仅告警；发布包及服务安装见 [部署文档](06-部署文档.md)。

`PR-0002` 文件完整性防护和 `PR-0003` SSH 登录防护默认启用，仅告警。
平台「主机防护」配置保存后，通过现有全量策略和 ACK 通道下发；离线 Agent
重连后补同步，重启使用已持久化策略。内置规则启动时幂等补齐，保留已编辑配置。

## 文件完整性

- 默认监控 `/etc/passwd`、`/etc/group`、`/etc/shadow`、`/etc/sudoers`、`/etc/ssh/sshd_config`。
- 每 5 秒检测内容、权限、属主、删除、创建和符号链接替换；不递归扫描目录。
- 配置绝对文件路径，最多 64 个；单文件最多 1 MiB。超限或不可读的初始文件告警，不能作为可恢复基准。
- 首次启用建立基准，基准元数据及内容位于 Agent 私有工作目录，权限分别为目录 `0700`、文件 `0600`。事件只报告路径、摘要、权限和错误，不报告文件内容。
- `alert` 只告警；显式增加 `restore` 才自动恢复。恢复校验基准摘要，保留权限与属主，在原目录原子替换；目标变成符号链接时不修改链接指向的文件。
- 重启保留基准；父目录解析位置或设备/inode 身份变化时拒绝恢复到新目录。相同的持续篡改状态抑制重复告警。
- 合法调整流程：停用对应规则、完成文件修改、重新启用。停用删除对应基准，重新启用建立新基准。
- 事件类型 `file_tamper`，结果 `alert_only`、`restored` 或 `restore_failed`。

策略示例：

```json
{
  "file_rules": [{
    "id": "PR-0002", "name": "关键文件完整性防护", "enabled": true, "severity": 3,
    "match": {"platforms": ["linux"], "paths": ["/etc/ssh/sshd_config"], "max_file_bytes": 1048576},
    "actions": ["alert"]
  }]
}
```

## SSH 登录

- 读取 `/var/log/secure`、`/var/log/auth.log` 中 OpenSSH 的 `Failed`/`Accepted` 登录记录，支持 RFC3339 和传统 syslog 时间。只采集 journald 而不写这两个文件的环境需先配置日志落盘。
- 同一规则、同一来源的失败记录按滑动窗口计数。默认 300 秒内 5 次失败告警，告警间隔 300 秒；不同来源独立计数。
- 信任 IP/CIDR 和排除账户不参与检测；超出检测窗口的历史日志不计数。
- 异常时段检测默认关闭。开启后只对成功登录告警，使用选定时区的允许小时区间：起始包含、结束不包含，可跨午夜；`0` 至 `24` 表示全天。时区使用 `Local`、`UTC` 或 IANA 名称，例如 `Asia/Shanghai`。
- 显式增加 `block_ip` 才封禁爆破来源；仅限制配置的 TCP SSH 端口，不隔离整台主机。需要 Agent 拥有 `iptables`/`ip6tables` 操作权限；默认端口 22、时长 600 秒。
- 特殊地址和管理服务器地址不能被封禁；解析管理地址失败时拒绝封禁并报告 `block_failed`。正常心跳管控不受影响。
- 封禁记录在操作防火墙前持久化。重启重新应用未到期规则，不延长期限；到期后每 5 秒检查解除。停用规则、改为仅告警、调整端口或加入信任来源时解除对应封禁。
- 使用独立 `ALINKSEC_LOGIN` 链；不清空其他防火墙规则。权限错误、部分执行失败和解除失败保留真实失败结果及清理重试状态。授权卸载清除本链及私有状态。
- 失败检测事件 `login_crack`，异常时段事件 `login_anomaly`；结果 `alert_only`、`blocked_ip` 或 `block_failed`。
- 上限：16 条登录规则、1024 个检测桶、128 个封禁来源；窗口 1–3600 秒、阈值 2–100 次、告警间隔 1–86400 秒、封禁 5–3600 秒、最多 16 个端口。

策略示例：

```json
{
  "login_rules": [{
    "id": "PR-0003", "name": "SSH 登录防护", "enabled": true, "severity": 3,
    "match": {
      "platforms": ["linux"], "window_sec": 300, "failure_threshold": 5,
      "cooldown_sec": 300, "block_duration_sec": 600, "ssh_ports": [22],
      "trusted_ips": ["192.0.2.0/24"], "user_exclude": ["backup"],
      "off_hours_enabled": true, "allowed_start_hour": 8, "allowed_end_hour": 20,
      "timezone": "Asia/Shanghai"
    },
    "actions": ["alert"]
  }]
}
```

## 验证

Agent 单元测试覆盖窗口、冷却、例外、时区、跨午夜、持久化、到期、策略解除、失败重试、部分封禁清理及管理地址保护；文件测试覆盖权限恢复、删除、符号链接、重启基准、合法变更和损坏基准。服务端测试覆盖配置拒绝、默认规则幂等和不同文件/来源的告警聚合，聚合保留 fingerprint 和最新处置结果。

`deploy/tests/agent-workflow-local.sh` 使用一个受限临时 Agent，调用 `protection-workflow.mjs` 验证真实日志上报、文件恢复与容器内防火墙规则、重启和到期解除。浏览器验收检查文件及 SSH 配置保存、刷新持久化和移动端布局。运行前停止其他验收场景，并按 [验证说明](../deploy/tests/README.md) 设置临时环境。

本轮能力范围为 Linux 文件及 SSH 日志。Windows 交叉编译通过，不代表 Windows/RDP 真机功能验收。
