# 报表增强与历史快照

第 19 项，分支 `reporting-enhancements` 从已合并并验收的主线 `144fe3cf` 创建。第 18 项 PR #27 的功能分支 CI39955904856 和精确主线 CI39960735809 均完成 15 作业、52 类产物验收，本地主线同步后才开始本项。

## 使用

系统管理 → 合规报表，选择日期、直接归属分组、Linux / Windows 后生成预览。日期默认最近 30 个自然日，最多 366 天；统一使用 `Asia/Shanghai`，结束日全天包含在内。筛选变化会清空旧预览，失败不会继续显示上一份统计。分组包含直接归属的主机，全部分组包括未分组主机。

管理员和操作员可保存当前统计为历史快照。所有已认证角色可以查看、下载 CSV / Excel / JSON / 打印版 HTML，或使用浏览器“打印／另存 PDF”。浏览器打印只包含报表，不包含控制台导航、编辑按钮、历史或计划表。PDF 由浏览器生成，字体和分页取决于打印环境；服务端提供可独立保存的 HTML，无外部字体、脚本、图片或网络依赖。

即时导出会比较预览中的统计摘要，数据变化时要求重新预览；下载时会重新生成文件并注明生成时间。历史快照固定数据、名称和生成时间，各种格式都从同一份已核验 JSON 生成。保存操作会重新读取数据库并显示实际保存的快照。

## 统计口径

| 部分 | 口径 |
|---|---|
| 主机资产 | 生成时快照，排除 `deleted=true` 或状态 4 的主机；在线、离线和其他状态分别计数 |
| 基线 | 区间内每台主机最后分配的任务，按任务创建时间和 ID 排序；较新未回报任务不会被较早通过任务代替。旧汇总缺少不可变分配清单时全部列为旧证据 |
| 自动检查项 | 预期清单中的通过、不通过、执行异常、旧证据和待回报分别统计；通过率分母为全部预期项，无分母时不显示 100% 或虚构通过率 |
| 漏洞 | 发现记录的创建时间在区间内，按等级和处置状态统计。同一 CVE 可有多条记录；历史匹配标记可能已过期，不代表当前适用或修复成功 |
| 漏洞覆盖 | 生成时的软件采集、评估状态，区分未扫描、旧资产、旧规则、来源选择待重新评估。零发现、未采集、无适用规则都不能证明安全 |
| 告警 | 首次发生时间在区间内；处置状态截至生成时。告警条数与合并发生次数分列，忽略不计为已处置，严重性 5 单独显示为危急 |
| 来源待处理 | 全平台 CVE 声明目录的冲突、复核、隔离、暂停、撤销和退役数量；标明独立于主机筛选，不推断受影响主机数 |
| 趋势与明细 | 每个自然日补零；汇总覆盖所有所选主机，主机明细最多 500 台并明确显示实际总数及截断情况 |

报表的自动检查通过率不等于等保认证结论。等保 2.0 的条款复核仍在原有基线流程进行，报表不把人工条款、异常、缺失或旧数据自动改判为通过。资产范围和处置状态都是生成时数据库视图，不是历史时刻资产或历史处置状态的还原。

PostgreSQL 使用可重复读事务取得一致视图；SQLite 沿用 IMMEDIATE 事务。日期范围使用 UTC 半开边界，兼容 SQLite 秒及毫秒精度的时间文本，避免结束日漏计或恰好开始时刻被排除。

## 历史与容量

V032 在 common / deploy 中逐字相同，增加报表事务锁、历史快照和定时计划三表，总计 32 个迁移、93 张表。快照保存完整 JSON 和 SHA256；读取时先校验摘要，摘要不一致禁止导出。文件名使用固定 ASCII 名称，日期和自定义名称不参与响应头拼接。

历史保留 30 天，全平台最多 200 份，每份 JSON 最多 2 MiB。过期记录不再展示或下载，后台轮询以及新建时会清理过期记录。容量满时明确失败，管理员可以删除旧快照；不悄悄覆盖尚未过期的记录。历史分页每页最多 50 条，界面使用 20 条。导出内容不使用公开或预签名 URL。

CSV 使用 UTF-8 BOM、标准双引号转义与 CRLF，防止主机名中的逗号、双引号、换行破坏列结构；可能被表格软件解释为公式的文本前置单引号。XLSX 把文本写为 `inlineStr`，数字按数值写入，不生成公式、宏或外部链接。结构参考 [Microsoft SpreadsheetML 文档](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/structure-of-a-spreadsheetml-document)。HTML 和生产页面均对原始字段作文本转义，下载提供 `no-store`、`nosniff`、内容 SHA256 和限制脚本的 CSP，浏览器核对下载字节摘要。

## 定时生成

管理员可设置每日、每周一、每月 1 日北京时间 09:00 生成，统计过去 1 至 366 个完整自然日，窗口结束于计划日的前一天。编辑需要当前修订号，成功后重新计算下一次执行时间。

计划、到期时段和执行结果持久化在数据库。后台每分钟检查，每轮最多执行四条，串行生成；同一时段的快照提交与下一执行时间更新在一个事务中完成，并有 `(schedule_id, scheduled_at)` 唯一约束。两个执行者不会为同一时段提交两份快照。停机错过多个时段时合并生成一份，以原定到期时段确定统计窗口，然后跳到当前时间之后的下次执行。

失败不会保存半份报表，会记录可见状态并等待五分钟后重试，连续三次失败停用。当前有效管理员可用新修订号修改并重新启用。计划所有者是最后保存计划的管理员账号，账号停用或失去管理员角色后立即停用计划。定时产物进入已认证的历史列表，通知渠道没有自动外发报表的行为。

管理员和操作员保存快照、管理员修改计划或删除快照时，会再次锁定并检查数据库中的当前账号与角色，不能仅靠旧 JWT 中的角色完成操作。计划写接口和快照删除还有基于 Spring 实际匹配路由的 JWT 权限检查。

## 验证

`ReportingIntegrationTest` 在真实 SQLite 和 PostgreSQL 受限应用账号上运行相同场景，包括日期、过滤、结束日、秒精度边界、新任务未回报、异常和旧证据、覆盖过期、CSV / HTML 注入、工作簿 XML、快照变化和篡改、角色变更、到期、容量、回滚、日历、重启、双执行者和重试。原始 JSON 响应与四种文档保留为实际数据库捕获。

`ReportControllerTest` 使用真实 Spring MVC 路由和 JWT 拦截验证登录、角色、认证账号来源、摘要、下载头及预览变化拒绝。原有 JWT、SQLite 迁移和整个模块回归继续运行。

独立的 `report-documents.py` 使用 openpyxl 读取两个数据库导出的实际 Excel，检查七张工作表、原始中文和恶意文本、数值、无公式，以及 CSV、HTML、JSON 的一致性。

`reporting-browser.mjs` 在打包后的生产页面上验证统计、四种真实下载、摘要拒绝、管理员计划修订、操作员与只读角色、自然日筛选、快照保存、失败清空、卸载后晚到响应和手机宽度。保存真实打印 PDF，再用 `pdftotext` 核对中文、统计口径和控制台排除，保留桌面与手机截图。最终功能分支和合并主线各自的完整 CI 与原始产物验收仍是完成条件。
