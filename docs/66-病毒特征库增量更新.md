# 病毒特征库增量更新

内置 SHA256／内部 JSON 规则库支持相邻已发布版本的增量更新。平台仍保留完整 ZIP；新 Agent 在本地基库内容一致时使用差量，无法使用差量时下载完整目标包。旧 Agent 继续接收原有全量命令。ClamAV 数据库及原生 YARA 本机规则源码、固定摘要和管理员配置入口沿用各自流程，参见文档 64、65。

## 发布与选择

人工导入、远端同步及来源退役继续共用来源合并、有效性检查和发布事务。平台按 SHA256 排序输出哈希，生成完整目标包，并与上一份已发布完整包比较。差量记录新增、属性变更和删除的哈希，内部规则 JSON 整体替换；来源撤销或优先级变化造成的删除、检出名及严重程度变化都会进入差异。不会把近期情报列表解释为完整基库。

只有差量压缩体小于全量的 80%，且至少节省 256 字节时才保存差量。首版、旧包缺失／损坏／格式不适用、小包以及差量生成或存储失败均可发布完整包；完整包发布失败仍回滚来源数据和版本，不启用半成品。全量和差量产物与版本记录一同接受事务提交或回滚清理，正常完成或失败后删除构建临时文件。仅为上一版生成一个差量，不构造多跳补丁链。

Agent 在认证心跳中报告 `signature_update_contract=1`。投递及离线重放时，服务端重新读取能力、本地主机上报的基库版本和当前最新发布版本；符合条件才附加差量。未知能力只得到全量路径，新能力但基库不符得到有内容固定值的全量路径。更新命令保留完整包地址和 SHA256，新增目标内容摘要及可选差量地址、包摘要、基库版本和内容摘要。

## 内容身份和格式

内容摘要为以下 ASCII 字符串拼接后的 SHA256：`sha256(manifest.json)`、`sha256(hashes.txt)`、`sha256(rules.json)`，各成员摘要均为 64 位小写十六进制，顺序固定，不加分隔符。比较完整原始字节；旧包缺少可选规则文件时使用空字节的摘要。版本号也包含在 manifest 的固定内容中。

差量 ZIP 仅允许以下五个根文件，不允许重复条目、目录、链接或其他路径：

| 文件 | 内容 |
|---|---|
| `delta.json` | `contract=1`、`base_version`、`base_content_sha256`、`target_version`、`target_content_sha256` |
| `manifest.json` | 完整目标包中的原始 manifest 字节 |
| `hashes.txt` | 新增或变更的 `sha256 name severity` 行，哈希升序、无重复 |
| `removed.txt` | 要删除的基库 SHA256，每行一个，升序、无重复 |
| `rules.json` | 完整目标包中的原始内部规则 JSON 字节 |

服务端和 Agent 使用有界排序流计算和应用哈希差异，避免为合并再创建整份哈希字典。Agent 检查删除对象确实存在，拒绝乱序、重复、删除与新增重叠及未知删除；新目标沿用完整库的有效性、数量、内部规则编译和容量校验。规则不采用原生 YARA 语言。

## 下载、回退和切换

下载使用注册时获得的平台 CA、HTTPS 和既有短期资源令牌。令牌分别绑定当前发布的完整包或差量键；不能互换，旧发布对象失去下载授权。离线命令投递重新生成令牌，不把对象存储凭据下发给 Agent。

Agent 先核对实际本地内容，不能只凭版本标签应用差量。本地缺失或内容不符时直接使用全量包；差量下载、包 SHA256、格式、重建或目标校验失败时，最多再尝试一次完整包。两条路径共用 10 分钟总下载期限，下载限速 2 MiB/s，单包最多 20 MiB；已知超大响应立即拒绝，未知长度响应也受实际字节上限和取消控制。不接受重建部分结果，失败不把旧库标记为新版本。

解压总量及重建目标均最多 64 MiB，哈希最多 250,000 条，内部规则最多 2,000 条／2 MiB。所有校验在受限临时目录中进行。完整目标的版本及内容摘要均吻合后，才切换目录并使进程内特征快照失效；已经持有的旧内存快照不被就地修改，后续检测重新加载新库。清洁文件缓存不能绕过新增哈希。

目录切换沿用旧目录备份与新目录更名。进程若在中间中断，下次读取前检查当前目录，必要时恢复结构有效的旧目录；已有完整有效的新目录则清理旧备份。这是进程中断恢复，不作为任意存储故障或掉电持久性的证明。正常失败清理下载和暂存文件；极端中断遗留的无引用暂存文件仍需运维观察。

内容已经一致时不重新下载；标签一致但实际字节不同的命令仍执行修复。终态 ACK 保存 `mode`、目标版本、内容摘要、下载字节数及固定回退原因，不包含下载 URL 或令牌。更新成功只证明本地库切换成功，不证明已完成主机扫描或恶意软件覆盖。

## 界面、迁移和验证

“安全库管理”显示完整包大小，以及可用差量大小和适用基库；没有差量时明确显示全量更新。页面说明自动回退及旧 Agent 行为，状态加载失败隐藏旧版本详情，并保留重试入口。只读角色可以查看这些信息，导入权限保持原有角色约束。

V025 为主机增加增量能力字段，为发布版本增加目标内容摘要及差量元数据；旧记录默认没有差量信息。SQLite 自动执行迁移；PostgreSQL 仍先运行迁移脚本，再使用应用角色启动服务。历史清理同时删除版本对应的两种包；有效令牌引用完整包或差量时均延后清理，排队更新继续触发保守保留。

验证包含 SQLite／PostgreSQL 的真实发布事务、差量选择、逐主机投递复核、最新版本限制、下载令牌、重复投递和双产物回滚。Linux amd64／arm64 使用 Java 发布器的真实产物交给 Go；Windows amd64 使用独立 Python 无害格式夹具。三平台验证覆盖真实 TLS、原生文件切换及实际 Agent 注册／mTLS／心跳／更新／回执／新哈希扫描隔离／重启。独立格式夹具不是连接生产情报源的证明。

CI 保存 `signature-validation-linux-amd64`、`signature-validation-linux-arm64`、`signature-validation-windows-amd64`，包括原始包、内容及包摘要、原生重建结果和实际 Agent 证据；双架构生产页面检查保留桌面及手机截图。任意大库的吞吐、峰值内存、长期运行和断电恢复仍由后续规模与系统适配验收确认。
