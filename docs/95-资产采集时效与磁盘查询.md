# 资产采集时效与磁盘查询

日期：2026-11-23。基线：已验收主线 `ec9ebc4`（PR #47）；产品版本仍为 v0.0.4，未发布新版本。本批推进 BKL-017 的逐类别观察历史与磁盘查询，不将整个 BKL-017 或现场系统覆盖判为完成。

## 行为与来源

六类资产的软件、端口、进程、账户、磁盘和容器分别保存最近一次尝试的序号、状态、错误、主机采集时间及平台接纳时间；另保存最近一次完整报告的序号、主机采集时间和接纳时间。完整报告及资产替换在同一事务提交。排序仍使用 Agent 持久序号，不使用两端墙上时间；失败、部分、不支持、软件明细校验失败和被拒绝的旧序号均不推进完整历史。容器部分成功可以更新成功来源，完整历史仅代表最近一次全来源完整报告，不能把混合新旧来源说成同一时间的快照。

新增 V038 只追加字段，PostgreSQL 与 SQLite 使用相同定义。既有迁移不改写；旧记录没有足够信息回填完整历史，新增字段保留 0。零序号报告不建立完整历史，界面显示未知，不能从旧资产行或最近失败时间推断成功时间。

磁盘从现有 `DiskInfo`、`t_asset_disk` 接入 `GET /api/hosts/{agentId}/disks` 和主机详情。接口沿用主机资产只读权限；记录挂载点、文件系统、总容量和已用容量。完整磁盘列表超过 10,000 项、空／超长／含 NUL 的挂载点、重复挂载点、非法容量、已用大于总量等情况记为 `failed / invalid_disk_inventory`，保留旧磁盘，不影响同报告的其他有效类别。部分、失败和不支持仍保留原清单，完整空集合才清理消失的挂载。

页面为六类资产显示尝试和完整报告时间；请求失败有明确提示，缺少状态的空集合不再宣称“未发现资产”。磁盘有独立表格；进程达到现有 500 条展示上限会提示。软件、进程和高风险账户视图仍有各自范围，不能据它们推断全部系统对象均已评估。

## 调度与覆盖边界

当前 `Client.collectLoop` 在启动约 15 秒后尝试首次资产采集，统一资产周期默认 6 小时，由 `collect_interval` 配置；资源反馈可能延长周期。`CmdCollectNow` 可指定类别，仍受暂停、忙碌和最小间隔约束；没有包数据库 mtime 自动触发，也没有独立每分钟进程／磁盘资产刷新。10 秒和 60 秒指标采集与资产清单不同。页面时间不表示实时一致性承诺，未假设所有部署都使用默认周期，也不凭默认值给所有主机判过期。

本批不修改采集器字段覆盖。进程字段读取失败、端口所属进程解析、不同系统权限与容器来源覆盖仍需后续逐项补齐；六类完整状态表示该采集器现有声明的枚举结果，不证明每个字段和目标系统均完整。BKL-017 保持 `IN_PROGRESS`，其他待办原状态保留，F25／26／27 现场延期及第 28 项全新部署 N/A 不变。

## 验证与验收

修复前，新数据库回归实际得到磁盘接口 HTTP 404。修复后验证六类完整历史、部分失败保留、主机时钟回退、旧序号拒绝、磁盘非法输入和成功空集合；既有软件事务回滚回归继续约束资产、采集状态和去重共同提交。

Go 枚举夹具保留受控枚举、真实当前进程信息及本地文件系统用量，注入枚举失败和成功空集合，生成协议原件。该夹具不是所有操作系统／权限组合的原生覆盖证明。数据库测试将协议原件经过真实 SQLite／PostgreSQL 和 REST 导出；浏览器回放捕获响应，另将缺少元数据与读取失败明确列为模拟页面边界。完整生产前端包和非本机平台由精确提交的 CI 验证，不能将页面回放称为真实网络全链路现场验收。

本机按 AGENTS.md 串行验证、限制内存并清理自建容器；保留既有用户服务。精确候选、合并主线 CI 及原始产物验收以本批 PR 的提交／运行链接与摘要为准，不复用基线 CI 作为新提交通过证据。
