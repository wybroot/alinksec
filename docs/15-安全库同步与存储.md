# 安全库同步与存储

> 版本基线：v0.0.4。已按本版核对「安全库同步与存储」的操作、实现引用与适用边界；历史日期及验证结果仍只对应其原始提交。版本差异见[发布说明](releases/v0.0.4.md)，全部资料见[文档索引](README.md)。

人工导入与远端同步共用校验、分源保存和发布流程。远端失败、非法规则、超出容量或上传对象存储失败时，保留已发布版本。Agent 继续使用本地库。交付时须导入可信基础库；仅开启近期情报同步并不等于初始化完整病毒库。

具体平台选型、认证、MISP/OpenCTI 原生配置与备用导出脚本、Vulnerability-Lookup 转换步骤见 [开源安全平台对接指南](16-开源安全平台对接指南.md)。原生适配器包括 MISP、[OpenCTI](71-OpenCTI原生指标接入.md)、NVD、MalwareBazaar，以及 [Ubuntu USN、Debian Tracker、Red Hat CSAF、Microsoft CVRF](70-厂商漏洞公告原生接入.md)；其他平台通过规范文件桥接，不能直接填写其认证 API 地址。服务台调度管理和基线后续路线见 [安全数据接入与演进](17-安全数据接入与演进.md)。

## 数据源与更新

控制台“安全库管理”可查看病毒库版本、内部规则数、已管理漏洞信息、含比对规则的漏洞数和远端检查状态。管理员可以手动同步、启停计划、调整频率或恢复部署默认值；管理员、运维角色可以人工导入；只读角色不能写入。三种角色均可查看最近 50 次执行记录。源地址和认证信息只由部署配置提供，不通过接口返回；OpenCTI 页面展示已固定的审核标签、阈值和本地严重程度。

服务默认读取 `./data/libraries.yml`，容器中为 `/app/data/libraries.yml`。可通过 `ALINKSEC_LIBRARY_CONFIG` 指定其他路径。配置示例为 [libraries.example.yml](../deploy/libraries.example.yml)，所有源默认关闭。Docker 环境可把实际配置文件复制到 `server-data` 对应目录，重启服务使配置生效；源密钥也可直接写在权限受控的配置文件中，避免把秘密写入镜像或仓库。

| type | 数据与语义 |
|---|---|
| `hashes` | HTTPS 文本列表，每行 `sha256 threat_name severity`；名称和严重程度可省略。新增、去重、累积，空响应不清除已有数据。 |
| `signature-zip` | 与人工导入相同的 ZIP 格式；更新时替换该远端源自身的内容，保留其他源。支持 ETag/Last-Modified 条件请求。 |
| `misp` | 认证调用 `/attributes/restSearch`，按审核标签导出已发布、可用于检测、通过 warninglist 筛选的完整 SHA256 文本；替换该源快照。建议每 30 分钟。 |
| `opencti` | 只读 GraphQL 完整可见指标集合，严格审核标签/检测状态/置信度/有效期/单一 SHA-256 模式筛选；完整空集合可撤销本源，已知到期由服务端独立撤出。见[原生接入](71-OpenCTI原生指标接入.md)。 |
| `malwarebazaar` | [官方 API](https://bazaar.abuse.ch/api/) 的 `get_recent&selector=time`，用 `Auth-Key` 认证；只拉哈希与家族信息，累积发布，不下载恶意样本。建议每 30 分钟。 |
| `cve-json` | HTTPS JSON 数组，与人工漏洞导入格式相同；按 CVE 更新，人工修订优先。 |
| `nvd` | [NVD 2.0 API](https://nvd.nist.gov/developers/vulnerabilities)，按修改日期分页；完整窗口的入库和游标原子提交，超容量逐次缩窗，失败不前移，重试有两分钟重叠。建议每两小时。 |

MalwareBazaar 的近期 API 只覆盖最近 60 分钟，首次部署以及断档超过该窗口时，需要通过全量哈希源或人工包补齐。页面明确标注该覆盖范围；继续使用已有库并不能补回遗漏情报。首次 NVD 同步默认覆盖最近 7 天修改的数据，可配置 `initial-days`（1～120）；这不是 NVD 全历史导入。单次窗口条数超过上限时自动缩小日期范围，完整提交较早前缀后逐次推进；最小窗口仍超容量则拒绝，不跳过记录。2026-10-03 实测最近 30 天有 23,942 条修改记录，7 天有 7,391 条，因此示例采用 7 天以适应默认单次 1 万条限制；实际数据量会变化。

所有后台源串行同步。OpenCTI 使用单请求默认 10 秒、全轮最多 180 秒的独立边界；其余通用下载连接超时 10 秒、读取超时 15 秒、单次下载总时间最多约 120 秒；禁止跟随重定向，避免凭据转发。正式远端源须用 HTTPS。保留回环 HTTP 供本机测试。最近成功检查和新版本发布时间分别显示：成功检查但无新增数据不误报为更新失败。

通用 `hashes`、`signature-zip`、`cve-json` 仅支持 HTTPS GET，没有可配置认证头；`api-key` 仅用于 MISP、OpenCTI、NVD、MalwareBazaar；四种厂商公告原生源使用公开接口并拒绝配置密钥。MISP 或完整非空 ZIP 可撤销本源消失的哈希；累积源不自动撤销。除 OpenCTI 的已知过期撤出外，禁用源保留有效数据；通用空包不清空来源。OpenCTI 只有完整认证集合通过校验后才可按空集合撤销本源。管理员可显式退役来源，包括部署已移除的来源；退役保留原始记录并退出有效库，最后特征来源退役会发布受控清空版本。详见[来源治理](52-安全来源治理与有界NVD同步.md)。桥接任务需独立监控上游更新时间，文件服务可达不代表上游导出成功。

控制台保存的启停状态和间隔优先于部署配置，存入数据库，重启后保留；恢复部署配置后重新使用 YAML 默认值。源地址或密钥变更仍需重启服务。每分钟选择最早到期的源，所有源串行执行；连续失败后指数延后重试，最长延后至一天（原始间隔超过一天时仍使用原始间隔）。成功后恢复正常间隔，手动同步可提前重试。NVD 最小间隔两小时，其他源至少五分钟，最长七天。暂停不取消已开始的任务，服务重启中断的记录会明确标记并等待重试。

## 病毒特征格式

ZIP 根目录包含 `manifest.json`、`hashes.txt`、可选 `rules.json`。只接受这三个文件，拒绝重复文件、非法哈希、计数不一致、不能编译的内部规则和空库。`manifest.json` 示例：

```json
{"db_version":"vendor-20261003","hash_count":1234,"rule_count":0}
```

`hashes.txt` 每行 `SHA256 检出名 严重程度`，严重程度为 1～5，检出名不能含空格。内部规则沿用 [rules.go](../agent/internal/virusscan/rules.go) 的 JSON 格式，此 JSON 格式不接受原生 YARA；原生入口使用[本机固定摘要源码](65-原生YARA引擎与规则证据.md)。页面标签改为“内部检测规则”。包本身的 SHA256 由发布流程计算并下发，不要求在 ZIP 内声明 ZIP 自身哈希。

人工导入替换人工源，远端同步不能覆盖人工源；相同哈希和规则名优先采用人工数据。升级后首次同步会把既有有效病毒包纳入人工源。发布时生成合并后的整包，并在有足够节省时生成相邻版本差量；新内容才生成新平台版本和推送。新 Agent 验证基库及目标内容摘要，差量失败回退完整包，见[增量更新](66-病毒特征库增量更新.md)。保留厂商版本号用于首次独立人工导入；合并发布使用平台生成的版本号。

## 漏洞导入和比对

人工导入和 `cve-json` 使用以下 JSON 数组：

```json
[
  {
    "cve_id": "CVE-2026-12345",
    "title": "厂商安全公告标题",
    "severity": 3,
    "cvss": 7.5,
    "affected": [
      {
        "name": "实际软件包名",
        "os": "Agent 实际上报的 os_version",
        "source": "dpkg",
        "ranges": [">=1.0", "<1.2"],
        "fixed_version": "厂商针对该系统确认的完整修复版本"
      }
    ]
  }
]
```

新导入规则默认精确匹配软件名；`os`、`source` 存在时必须一致。`ranges` 的条件全部满足才命中；也兼容单条件 `vrange`。更新成功后串行重新比对资产。匹配过程逐条消费可比对 CVE，排除 `affected: []` 的信息记录，避免把全部漏洞描述同时加载到内存。

NVD 默认只同步漏洞信息。只有显式配置 `products`，并且上游 CPE 条件是受支持的简单 OR、非取反应用条件时，才生成受限的比对规则。涉及 AND、嵌套环境等复杂条件时不猜测适用性。映射必须指定软件名、系统和非 RPM/DPKG 的软件来源，防止把上游版本直接套用到发行版回移修复上。NVD 生成规则不推测 `fixed_version`，因此不会直接支持一键安装某个猜测补丁。

初始化的 20 条历史样例仍保留以兼容既有部署，它们不计入“已管理漏洞信息”和“含资产比对规则”的统计。生产部署应以厂商确认的正式规则更新替换。当前已提供原生对照的 RPM／DPKG 完整版本比较、明确范围的厂商公告转换和离线 XCCDF／OVAL 执行，分别见[版本语义](45-RPM-DPKG完整版本比较与epoch保留.md)、[厂商公告](70-厂商漏洞公告原生接入.md)及[标准解释器](68-XCCDF与OVAL原生解释.md)。Windows 更新由目标机 WUA 使用其实际配置的 WSUS／公共源；具体补丁安装与重启仍须现场验证，不存在任意源的全量补丁自动镜像承诺。

## 存储、容量与保留

默认 `alinksec.libraries.storage.backend: local`，病毒包和补丁包仍使用原持久化目录。可配置 `s3` 使用已有 S3 兼容服务，通过 AWS SDK 上传、流式下载和删除。需要设置 `endpoint`（AWS 可省略）、`bucket`、`region`、`access-key`、`secret-key`，桶须预先存在。配置字段见 [application.yml](../server/alinksec-bootstrap/src/main/resources/application.yml)。

Agent 下载仍经平台原有 CA 和下载令牌端点；不把存储凭据交给 Agent。S3 启用后，既有本地文件继续可读，新文件写入对象存储。切回本地模式前需迁回 S3 文件；对象存储不可用时 Agent 已安装的本地库仍可检测，新 Agent 的下载会失败并等待恢复。

默认下载和解压总大小上限 64 MiB、合并哈希上限 25 万条、规则上限 2000 条、单次漏洞导入上限 1 万条；NVD 的多页下载也受累计 64 MiB 限制。超过上限保留旧库并标记失败，不能静默截断。Agent 仍使用内存哈希索引，不能仅因启用了对象存储就无限提高容量。

每天尝试清理病毒发布包，至少保留最新 10 个版本以及最近 7 天版本；有效下载令牌引用的包保留。存在待发或执行中的特征更新指令时，保守延后历史清理。当前版本始终保留。临时下载与构建文件在完成或失败后清理；补丁清单中的文件不自动过期，避免破坏任务引用。平台数据库、人工数据和正在使用的包均应纳入备份。

## 升级与验证

SQLite 按迁移注册表自动应用截至 `V036` 的适用迁移，安全库与计划分别始于 `V002`、`V003`，不修改已发布迁移。PostgreSQL 使用既有 `deploy/migrations/run-migrations.sh` 流程执行安全库和调度迁移并授予应用角色 DML 权限；先完成迁移再启动新版服务，不给应用账号 DDL 权限。

自动化验证包括 SQLite 新库及重复迁移、人工/远端合并和人工优先、条件请求、不变内容不重复发布、空/坏库及容量超限回退、对象存储上传失败回退、临时文件清理、NVD 保守映射和角色权限。真实 MalwareBazaar 同步需要部署方认证密钥，本地回归使用 HTTP 协议响应验证，不伪造已经连接了有密钥的生产数据源。
