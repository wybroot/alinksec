# 防护能力与开源实现差距

> 本文记录 ALinkSec 对照 Elkeid Driver、Falco、Wazuh Active Response、OWASP CRS 四个开源参照的能力差距分析与分批实现计划。历史修复记录保留于"历史记录"节，不作为当前能力的证明。

---

## 一、开源参照能力速览

以下是四个开源组件的核心防护机制，作为后续差距分析的对照基线。

### 1. Elkeid Driver（字节跳动内核采集层）

**层次：** Linux 内核（Kprobe hook），纯采集，无内置检测规则。

**默认启用的内核事件钩子：**

| 事件 | 采集内容 |
|---|---|
| `execve`（59） | argv、执行路径、stdin/stdout 的 FD、SSH 环境变量、`LD_PRELOAD`、**完整 pid_tree 父链** |
| `connect`（42） | sa_family、目标/源 IP 端口 |
| `bind`（49） | 本地绑定 IP 端口 |
| `rename`（82） | 文件改名前后路径及文件系统 ID |
| `link`（86） | 硬链接创建（旧路径 → 新路径） |
| `ptrace`（101） | 仅 PTRACE_POKETEXT/POKEDATA；目标 PID、地址、数据 |
| `setsid`（112） | 会话创建（常见持久化手段） |
| `memfd_create`（356） | 内存文件创建（无文件落盘恶意软件指标） |
| `dns_query`（601） | UDP 53/5353 DNS 解析请求 |
| `update_cred`（604） | **old_uid≠0 且 new_uid=0 时**触发，记录完整凭据对和 pid_tree |
| `privilege_escalation`（611） | 提权事件，含旧凭据组、新凭据组、pid_tree |
| `load_module`（603） | 内核模块加载路径 |
| `create_file`（602） | 文件创建时关联的网络 socket（网络→文件落盘关联） |

**默认关闭但可启用：**
- `open`（文件打开）、`mprotect`（仅 PROT_EXEC）、`kill`（信号发送）、`file_write`（需配置 watchlist 路径）、`port_scan_detection`（端口扫描检测）

**反 Rootkit 检测（始终开启）：**
- `/proc` 文件系统钩子检测、系统调用表篡改、隐藏内核模块、IDT 钩子

**每条事件的公共字段：** uid、exe、pid、ppid、pgid、sid、comm、namespace 感知的 nodename（裸机主机名 / 容器名 / Pod 名）、pns、root_pns

**关键限制：** 仅采集原始遥测数据，无内置检测逻辑；不支持阻断；需要配套 Agent 和后端规则引擎；Linux 内核 2.6.32–6.3，不支持 Windows。

### 2. Falco（CNCF 运行时安全）

**层次：** 内核 syscall（eBPF CO-RE 或 kmod）+ 插件（CloudTrail、K8s Audit）；检测并告警，无内置阻断。

**默认规则覆盖的威胁类别（Stable 等级，开箱即用）：**

| 威胁类别 | 具体检测内容 |
|---|---|
| 提权 | 特权容器、setns 命名空间变更、非 sudo/root 程序调用 setuid |
| 敏感文件访问 | `/etc`、SSH authorized_keys、`/proc/*/environ`、shell 配置文件读写 |
| 可疑进程生成 | 容器内出现 shell（sh/bash/zsh）、SSH 工具、数据库进程启动意外子进程 |
| 容器逃逸指标 | 特权容器执行 mount、setns 跨 namespace |
| 持久化机制 | crontab 修改、authorized_keys 写入、shell 历史删除、`/dev` 下创建文件 |
| 网络异常 | 系统进程意外建立网络连接、容器内使用 netcat/nmap/tcpdump/socat |
| 凭据访问 | 非 SSH 程序读取 SSH 信息、读取 `/proc/*/environ` |
| 供应链攻击 | Log4Shell、XZ/liblzma 后门等 CVE 专项规则 |
| Kubernetes | kubectl cp 数据泄露、unshare 提权 |

**事件丢失处理：** 内核侧 ring buffer 满时会丢弃事件；Falco 提供可配置丢失响应（log/alert/exit），默认不处理；高负载下存在检测覆盖缺口。

**告警输出：** stdout、文件、syslog、HTTP endpoint、gRPC（falcosidekick 转发 50+ 目标）；规则携带 MITRE ATT&CK 技术标签。

**关键限制：** 纯检测，无内置阻断；不能检测 HTTP 应用层内容；不支持 Windows；事件丢失无回放机制。

---

### 3. Wazuh Active Response（规则触发自动响应）

**层次：** 主机日志分析 + Agent 执行，检测后触发响应，响应有延迟（秒级）。

**触发机制：** 任意 Wazuh 规则（SSH 爆破、FIM 变更、漏洞检测、自定义日志解码器）均可触发响应；规则可指定触发条件（规则 ID / 规则组 / 告警级别）。

**内置响应动作（Linux）：**

| 脚本 | 动作 |
|---|---|
| `firewall-drop` | iptables DROP 封禁攻击来源 IP |
| `host-deny` | `/etc/hosts.deny` 封禁 |
| `route-null` | 黑洞路由 |
| `disable-account` | 禁用 Linux 用户账户 |
| 自定义脚本 | 任意 shell/Python/Go/C 脚本，接受告警 JSON（stdin） |

**撤销机制（timeout_allowed）：** 支持定时自动撤销（如封禁 600 秒后自动解封），响应结果审计写回 Wazuh 事件。

**执行位置：** local（产生告警的 Agent 本地）/ server / defined-agent / all（广播全部 Agent）。

**关键限制：** 事后响应，无法在攻击发生前阻断；无内置进程终止脚本；iptables 在 nftables 为主的新系统需要兼容层；容器/Kubernetes 无内置响应脚本。

---

### 4. OWASP CRS（Web 应用防火墙规则集）

**层次：** HTTP 应用层，内联拦截，需 WAF 引擎（ModSecurity / Coraza）驱动。

**覆盖的攻击类别（规则文件）：**

| 规则范围 | 攻击类别 |
|---|---|
| REQUEST-930 | LFI 本地文件包含（路径穿越、`/etc/passwd`） |
| REQUEST-931 | RFI 远程文件包含 |
| REQUEST-932 | RCE 远程代码执行、命令注入 |
| REQUEST-933 | PHP 注入 |
| REQUEST-934 | Node.js 注入 |
| REQUEST-941 | XSS（反射型、存储型、DOM、SVG、HTML5） |
| REQUEST-942 | SQL 注入（50+ 规则，包含盲注、时间盲注、堆叠查询） |
| REQUEST-944 | Java 应用攻击（Log4Shell/JNDI、反序列化） |
| REQUEST-921 | HTTP 请求走私、Header 注入 |
| REQUEST-913 | 扫描器指纹（sqlmap、nikto、nmap、burp suite） |
| RESPONSE-951/952/953 | 响应体中 SQL/Java/PHP 错误信息泄露 |

**异常评分模型：** 每条规则命中增加评分；CRITICAL 规则得 5 分；阈值默认 5，单条关键规则命中即拦截；支持偏执级别（PL1–PL4）调整检测力度与误报率。

**运行模式：** DetectionOnly（仅记录日志）/ On（拦截）。

**WAF 引擎选项（与 Go 平台兼容）：**
- **Coraza**（Go 原生，可嵌入 Go HTTP 中间件）
- ModSecurity v3 + Nginx 反向代理

**关键限制：** 不能独立运行，必须嵌入 WAF 引擎；不含认证/授权检测；不做 API Schema 验证；PL2 以上需要大量误报调优；不支持 E2E 加密流量（需在 TLS 终结点工作）。

## 二、当前实现现状 × 开源参照差距矩阵

> 标记说明：✅ 已实现 / ⚠️ 部分实现/存在缺口 / ❌ 未实现

### A. 进程行为检测（对照 Elkeid Driver + Falco）

| 能力项 | 开源参照 | 当前状态 | 差距说明 |
|---|---|---|---|
| 进程枚举 + 规则匹配 | Elkeid execve hook | ✅ `edr.go` 每 2 秒轮询 `gopsutil` | 两次轮询间已退出的短命进程漏检 |
| 短命进程检测 | Elkeid execve + Falco syscall | ⚠️ `execaudit.go` 消费 auditd exec 日志（默认关闭） | 需目标主机安装 auditd、配置规则、Agent 有读权限；未集成内核探针 |
| 完整 pid_tree 父链 | Elkeid（每条事件携带） | ❌ | 当前仅记录单层 ppid，无完整祖先链 |
| 进程创建时网络 socket 关联 | Elkeid create_file（602） | ❌ | 无法将进程创建的文件与当时持有的网络连接关联 |
| 提权检测（uid 0→非0 / 非0→0） | Elkeid update_cred（604）/ privilege_escalation（611） | ❌ | 无内核级凭据变更钩子 |
| 内存注入检测（ptrace POKETEXT） | Elkeid ptrace（101） | ❌ | 无 ptrace 事件采集 |
| 无文件攻击（memfd_create） | Elkeid memfd_create（356） | ❌ | 无内存文件创建事件 |
| 内核模块加载检测 | Elkeid load_module（603） | ❌ | 未采集 |
| DNS 请求采集 | Elkeid dns_query（601） | ❌ | 未采集 |
| Rootkit 检测（/proc hook、syscall table 篡改） | Elkeid 反 Rootkit（700-703） | ❌ | 未实现 |
| 容器感知（事件携带容器名/Pod 名） | Elkeid pns/nodename、Falco container.* 字段 | ❌ | 当前容器清点独立，进程事件不携带容器上下文 |
| 反弹 Shell 检测 | Falco 默认规则（shell 在容器内 / 通过非交互 bash 网络重定向） | ⚠️ `execaudit.go` 提供命令行线索规则 | 仅匹配命令行字符串线索，无网络 + 进程 + 父链的联合检测 |
| 持久化检测（crontab 写、authorized_keys 改） | Falco stable 规则 | ❌ | 无对应规则；文件监控侧覆盖部分路径，但无持久化语义 |
| 事件丢失感知与上报 | Falco drop_handler（log/alert/exit） | ⚠️ `execaudit.go` 上报 `source_unavailable_or_gap` | 仅覆盖 audit 日志来源；轮询方式本身无法感知丢失 |

**当前进程防护核心限制：** 轮询型枚举覆盖不到短生命周期进程；仅依赖文件名和命令行正则，默认规则仅匹配 4 个矿工名称；无内核级采集源，无法获得 pid_tree、凭据变更、内存操作等上下文。

### B. 文件完整性与勒索防护（对照 Elkeid + Falco）

| 能力项 | 开源参照 | 当前状态 | 差距说明 |
|---|---|---|---|
| 受保护文件改变检测 | Elkeid file_write watchlist / Falco 敏感文件规则 | ✅ `filemon.go` 5s 轮询 SHA256 + 属主 + 权限 | 是改后检测，非写入前阻止；仅覆盖明确配置路径 |
| 文件修改事件告警 + 可选恢复 | Falco 告警 / Wazuh FIM + Active Response | ✅ 支持 alert / restore 响应 | 无法在写入前拦截；基准需可信首次建立 |
| 修改者进程身份关联 | Elkeid rename/file_write 携带 pid_tree | ❌ Linux：`attrib_linux.go` 明确返回 `linux_writer_capture_unavailable` | Linux 无可信写入者归因；Windows ETW 实现独立 |
| 诱饵文件篡改检测 | （无直接参照，ALinkSec 自研） | ✅ `guard.go` 60s 健康检查 | 满足基本场景 |
| 加密速率检测（批量 rename + 文件内容变化） | （无直接参照，ALinkSec 自研） | ✅ `ratemon.go` 窗口内 churn 计数 | 慢速变化不触发；触发时已发生损坏 |
| inotify/fanotify 事件驱动（代替轮询） | Elkeid 内核级采集 / Falco eBPF | ⚠️ `filewatch` 包已接入文件系统事件通知 | 通知仅作为触发补充检查的信号，核心逻辑仍依赖定时轮询 |

| SSH `authorized_keys` 写入检测 | Falco 默认规则 | ⚠️ 同上，需显式配置 | — |

### 第二批：进程行为检测深化（对照 Elkeid execve + Falco stable 规则）

> **目标：** 在不引入内核驱动的前提下，尽可能补齐可验证的检测能力；明确剩余缺口。

| 子项 | 实现方案 | 完成条件 |
|---|---|---|
| **B01** pid_tree 父链采集 | Agent 进程枚举时递归读取 `/proc/<pid>/status` 的 PPid 字段，构建最多 8 层的祖先链，写入安全事件 detail | 测试：父链长度 ≤8、PID 复用不拼接错误链、字段不含敏感内容 |
| **B02** 进程启动时网络连接关联 | 枚举进程时读取 `/proc/<pid>/net/tcp*`，记录当时持有的监听/已建立连接，附加到进程事件 | 测试：正常进程无误报、网络命名空间隔离下的容器进程标记 unavailable |
| **B03** 默认规则扩展（反弹 Shell 线索） | 参照 Falco stable 规则，补充：非 sshd 进程执行 ssh/scp/sftp、bash -i 或 sh -c 带重定向、常见 C2 框架命令行线索 | 测试：触发合成无害命令、正常 bash 交互不误报；规则有启用/禁用开关 |
| **B04** 持久化检测规则 | 覆盖：crontab 写入（/var/spool/cron、/etc/cron.*）、authorized_keys 修改、bash 历史删除（文件监控规则 + 进程规则联合） | 测试：正常 crontab -e、异常进程写入区分 |
| **B05** 容器进程标记 | 进程枚举时读取 cgroup 路径，判断是否在容器内，附加 container_id 字段（docker ps 补全名称） | 测试：容器内进程标记正确、宿主机进程不标记 |
| **B06** 已有 audit 输入完整验收 | 在测试 Linux 主机完成 auditd 安装、规则配置、轮转、短命/改名程序检测端到端场景 | 测试：短命进程退出后仍能匹配；改名程序匹配 exe 路径；正常命令不误报 |

**技术约束：** 不引入内核模块、不 insmod；不使用 ptrace 附加目标进程。上述方案均为用户态实现，存在固有局限（短命进程窗口、`/proc` 读取竞态），须在实现说明中明确。

### 第三批：文件防护与勒索响应增强（对照 Elkeid file_write + Falco 敏感文件规则）

| 子项 | 实现方案 | 完成条件 |
|---|---|---|
| **C01** 默认敏感路径配置 | 参照 Falco stable 规则，提供内置默认文件监控路径集（`/etc/passwd`、`/etc/shadow`、`/etc/sudoers`、`~/.ssh/authorized_keys`、`/etc/crontab`、`/etc/cron.d/`），用户可在策略中追加或豁免 | 测试：新部署无需手动配置即覆盖身份文件；豁免路径不告警 |
| **C02** 文件监控触发 → 修改进程关联 | fanotify FAN_CLOSE_WRITE 模式（Linux 5.1+）记录触发进程 PID，附加到告警的 writer_pid 字段（不保证 kill 可靠性，仅作证据） | 测试：正常业务写入、异常进程写入分别记录；PID 复用场景标记 uncertain |
| **C03** Linux 勒索响应能力声明修正 | 在前端策略配置页面，当用户选择 Linux `kill` 或 `kill_and_isolate` 时，弹出明确提示："Linux 当前不支持可信写入者归因，kill 动作仅执行告警和取证，隔离部分按策略执行"；在服务端接口文档和审计日志中记录此限制 | 测试：策略保存后前端显示限制说明；告警事件包含 `kill_not_supported: true` 字段 |
| **C04** 文件恢复与写入者证据结合 | 响应事件中始终附加 writer_pid（可信 / uncertain / unavailable）；隔离决策仅由平台或规则驱动，不依赖 writer_pid 判断 | 测试：多种来源场景下证据字段完整 |

### 第四批：响应规则自动化（对照 Wazuh Active Response 机制）

> **目标：** 建立告警→自动响应的规则配置能力，参照 Wazuh 的 rule-condition→action 映射模型。

| 子项 | 实现方案 | 完成条件 |
|---|---|---|
| **D01** 响应规则配置模型 | 在平台新增"响应规则"实体：条件（告警类型、等级、规则 ID、主机标签）→ 动作（封禁 IP、主机隔离、进程终止）→ 执行位置（仅本主机）→ 超时自动撤销（可配置分钟数） | 测试：规则创建、条件评估、动作派发、超时撤销全程审计 |
| **D02** 封禁 IP 响应闭环 | SSH 爆破告警自动触发 `block_ip` 指令（现有实现），将封禁执行结果和撤销时间写为独立安全事件 | 测试：爆破告警 → 封禁 → 指定时间后撤销 → 状态可查；管理服务器 IP 不得封禁 |
