## 逐项核查

| 能力 | 当前如何工作 | 实际缺口 |
| --- | --- | --- |
| 进程防护 | [edr.go](../agent/internal/guard/edr.go) 每 2 秒枚举进程，对新出现的 PID／创建时间匹配程序路径和命令行正则，命中后按规则告警或结束进程树，并采集父链 | 两次枚举之间执行并退出的短命令会漏掉；启动和策略更新时已有进程只建基线。默认规则主要匹配四个矿工文件名，改名可绕过，不能据此覆盖反弹 Shell、提权、注入、凭据窃取或持久化 |
| 关键文件完整性 | [filemon.go](../agent/internal/guard/filemon.go) 接收文件通知并每 5 秒复核，比较内容摘要、权限和属主；显式 `restore` 时使用私有基准恢复 | 默认仅告警；是修改后的检测／恢复，不是写入前阻止。仅覆盖明确配置的有限文件，首次建立的基准需要可信；缺少写入者证据和面向业务的合法变更审批流程 |
| SSH 登录 | [loginmon.go](../agent/internal/guard/loginmon.go) 从 OpenSSH 日志按来源、窗口和阈值计数；默认 300 秒 5 次，显式 `block_ip` 才按端口限时封禁 | 默认仅告警；仅 journald 无文件落盘时存在采集缺口。分布式低频猜密、成功登录后的攻击行为不在该阈值规则覆盖内 |
| Windows 远程登录 | [windowslogin](../agent/internal/windowslogin) 读取安全事件，按策略中的登录类型、端口、来源计数并可限时封禁，另上报读取覆盖状态 | 依赖系统审计、读取权限和真实事件范围；不能泛化成域控、所有认证协议或所有 Windows 版本均已防护 |
| 勒索诱饵／速率 | [guard.go](../agent/internal/guard/guard.go) 将诱饵摘要变化、完整配置窗口内批量文件变化分别作为触发；事件通知辅助诱饵核验。按策略告警、终止或隔离，保存证据；Windows 写入者使用 ETW | 未触碰诱饵或慢速变化可能不触发。发生损坏后才判断，不保证零文件损失。Linux 原归因可能误杀，本轮已移除推测性终止，但可信写入者采集尚缺；不能称为完整勒索阻断 |
| 病毒／恶意文件 | [virusscan](../agent/internal/virusscan) 使用 SHA256、内部规则，可选原生 YARA／外部 ClamAV；文件通知和补查触发核验，按明确策略隔离并绑定摘要 | YARA 构建、ClamAV 服务及库需实际就绪，默认 Agent 不自动具备。已知特征检测无法替代行为检测；当前事件后扫描不保证执行前拦截，小型无害库测试不证明真实检出率 |
| Web 攻击 | [网络事件分类](../server/alinksec-service/src/main/java/com/alinksec/service/alert/SecurityEventTaxonomy.java) 和大屏能接收、聚合与显示检测源上报的 SQL 注入、XSS 等事件 | 没有实际新增 WAF、HTTP 攻击检测器或业务进程 RASP；没有检测源时就没有这类检测。仅显示分类不能算已防护 |
| 基线／漏洞 | 已有配置核查、包身份与厂商公告匹配、受控修复／审批及回执 | 风险发现、修复和持续攻击阻断是不同能力；配置合规或软件版本匹配不能证明运行时攻击已阻断 |
| 容器／Kubernetes | 现有 Agent 采集 Docker／本节点 Pod 资产 | 资产可见不等于已具备容器逃逸、特权操作、运行时攻击或 K8s 审计关联检测 |
| 系统组件健康 | [ComponentHealthService](../server/alinksec-gateway/src/main/java/com/alinksec/gateway/server/ComponentHealthService.java) 检查 API/JVM、数据库、gRPC、存储、证书、VictoriaMetrics 与集群依赖 | 可用性检查不证明这些服务抵御了攻击。Nginx、数据库、Redis、RabbitMQ 等各自的网络暴露、身份权限、版本和审计需另核查；本轮没有将健康结果作为安全防护验收 |

策略保存、下发成功、开关开启、心跳正常、组件健康、产生过一次告警，分别只能证明对应环节，不能合并成整机“已全面防护”的结论。

## 本轮先修复的错误处置

原 Linux 勒索归因只要发现进程持有受影响文件**同目录**的句柄，就可能将其认定为写入者；找不到句柄时退回最近启动进程。文件读者、备份、同目录业务和无关新进程都可能被错误选择。即使恰好持有目标文件的可写句柄，也不证明它完成了触发窗口内的恶意修改。

当前 [attrib_linux.go](../agent/internal/guard/attrib_linux.go) 明确返回 `unavailable / linux_writer_capture_unavailable`，不产生终止目标；公共响应记录跳过终止原因，不伪报成功。告警、文件证据和显式配置的主机隔离仍走既有流程；隔离租约与失联撤销机制保持生效。本轮不对真实主机执行隔离测试。

这项修复取消了不可靠的响应，**没有新增 Linux 内核写入者传感器**。配置为 `kill` 的 Linux 勒索策略当前只能告警和取证，必须在部署说明中明确；既有独立进程规则与人工处置不受这条勒索归因路径控制。

回归使用独立临时目录和测试子进程，检查无关新进程、目标文件只读者、同目录其他文件读者以及真实写入者。缺少可信操作事件时均不得猜测终止目标；诱饵和速率响应必须继续报告真实动作、证据和缺口。测试先检查归因目标再调用响应，避免缺陷复现时误杀主机进程。具体执行结果记录于本地 `.tmp/protection-depth/`，尚未执行的检查不按通过记录。

## 开源实现的具体参照

本次查阅以下官方文档和仓库（2026-10-26）。它们是核查参照，未据此声称当前产品已经集成。既有[开源安全平台对接指南](16-开源安全平台对接指南.md)中的 MISP／OpenCTI 主要提供情报数据，不能代替主机传感器和响应实现。

| 参照 | 应落实到本项目的环节 | 不能直接推断的能力 |
| --- | --- | --- |
| [Elkeid Driver](https://github.com/bytedance/Elkeid/tree/main/driver) | 从实际 execve、connect、提权等内核事件获得进程及上下文；规则基于行为和关联，而非仅文件名 | 各 hook 有独立默认开关；[社区说明](https://github.com/bytedance/Elkeid#elkeid-community-edition-description)明确完整检测仍需要策略建设。引入采集器不等于引入全部内部检测能力 |
| [Falco 内核事件](https://falco.org/docs/concepts/event-sources/kernel/)及[项目说明](https://falco.org/docs/) | 事件驱动采集、运行时规则、容器上下文，并将事件丢失作为覆盖问题处理 | Falco 主要检测和告警；需要另接经过核验的响应，不能把告警自动等同阻断 |
| [Wazuh Active Response](https://documentation.wazuh.com/current/user-manual/capabilities/active-response/index.html) | 将已解码事件、规则条件和具体动作关联，保留执行与恢复结果 | 响应效果取决于规则和动作本身，安装模块不能代替场景验收 |
| [OWASP CRS](https://coreruleset.org/docs/) | 真实 HTTP 流量经过兼容 WAF 引擎，执行规则、记录命中与实际放行／拒绝，再接入主机归属和告警 | 仅上传访问日志、识别攻击类型字符串或画出来源 IP，不等于 WAF；还需要误报调优、请求边界和可信代理来源处理 |

## 补强顺序与完成条件

1. **可信采集与安全处置**：补 Linux 写入／重命名操作和进程实例关联；终止前核验进程身份、受保护进程和策略状态。对读取者、PID 复用、多个写入者、采集丢失和已退出进程有明确拒绝结果。上面的误杀修复只是这一项的第一步。
2. **进程行为检测**：接入可验证的事件源，处理短进程、已有进程、来源中断和丢弃计数，再补反弹 Shell、持久化、异常父子链、下载执行与提权等有上下文的规则。每条规则需给出攻击触发、正常业务例外和响应证据，不能继续只增加矿工名称正则。
3. **Web 与服务组件**：为实际受保护的站点接入 WAF＋CRS 或明确的业务探针；分别验证检测模式、阻断模式、正常请求、可信代理、超限和规则更新回退。数据库、Redis 等服务另按自身认证／权限／暴露面核查，不套用 Web 防护名称。
4. **逐主机生效证据**：把有效策略版本、实际采集范围、规则数量、引擎依赖、最后成功采样、丢失／失败和动作结果连接起来，区分告警、检测后处置和访问前阻止；无法证明的状态显示未知或降级。

后续能力只有在真实无害场景触发、正常业务不误伤、失败与恢复有结果后才接受。现有本机资源限制、串行验证、不推送／不触发 CI 的维护要求继续适用；现场 25／26／27 不因本轮源码回归改为通过。

## 本轮本地验证

- 使用原实现的 Go 源码覆盖映射复现上述 4 种场景，全部在执行响应前发现不可信终止目标；没有执行原实现的杀进程回调。最终回归测试源码也完成了该复现。
- 修正后的 Linux 防护包 25 项顶层测试通过；新增 4 个子场景分别检查诱饵和速率两种响应，均保留告警／证据／跳过原因，子进程继续响应探测。现有文件恢复、登录窗口／封禁状态、管理地址保护和真实文件通知测试同时通过。可选 ClamAV／原生 YARA 测试跳过，测试子进程入口单独运行时跳过；未运行 Windows 原生回归或真实主机隔离。
- 21 项前端单元测试串行通过。首次前端测试因 full memory PSI 达 6.19% 自动中止并保留记录；清理本轮临时 Go 编译缓存、停止后端后复验通过，仍使用可用内存 512 MiB／full PSI 5%／磁盘 2 GiB 的原保护线。
- 后端每次均恢复原容器，HTTPS `/api/health` 返回成功。本轮没有替换现有预览镜像或运行中 Agent，没有重跑完整前后端构建、浏览器与跨平台／现场验收，也没有推送、触发 CI 或发布。

本地执行、资源保护、原容器恢复和源码摘要记录在 `.tmp/protection-depth/`。这些结果仅接受本轮误杀修正及相关回归，不接受上表尚缺的完整防护能力。
