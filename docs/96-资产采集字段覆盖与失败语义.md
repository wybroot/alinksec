# 资产采集字段覆盖与失败语义

日期：2026-11-24。基线：已合并主线 `a154bbf`（PR #48）；产品版本仍为 v0.0.4，未发布新版本。本批继续在 `feat/bkl-017-collector-field-coverage` 推进 BKL-017 的采集器字段级失败报告、端口进程归因完整性、Linux 容器来源状态与超限看护，以及 Windows 账户与软件注册表边界校验；不将 BKL-017 或现场系统覆盖判为完成，F25／26／27 现场延期与第 28 项全新部署 N/A 保持不变。

## 采集改进与错误契约

1. **端口监听与进程归因（[collector.go](../agent/internal/collector/collector.go) `collectPorts`）**：
   - `listConnections("inet")` 继续仅采集 TCP `LISTEN` 与本地 UDP 绑定；非监听连接（即使 `Pid <= 0`）忽略且不降级。
   - 按 PID 缓存名称及查询错误（`portProcCacheEntry`），同一失败 PID 被多个监听端口复用时仍保留失败判定，不再将首次查询失败后的后续端口误标为 `COMPLETE`。
   - 监听端口仍保留观测行以供诊断，但只要存在未归因端口即按优先级将 `ports` 状态降级为 `PARTIAL`：
     - `port_process_permission_denied`：权限不足读取进程信息（兼容 `os.ErrPermission`、`process.ErrorNotPermitted`、`EACCES`/`EPERM` 及 Windows `Access is denied.` 包装错误）；
     - `port_process_unattributed`：Socket `Pid <= 0`（如内核态 socket 或非特权环境无法映射 inode）；
     - `port_process_lookup_failed`：PID 查找异常或返回空白进程名。
2. **进程字段覆盖与瞬态退场区分（`collectProcesses`）**：
   - 通过 `processReader` 读取 `Name()`、`Exe()`、`CmdlineSlice()`、`Username()`、`MemoryInfo()`，不再静默丢弃字段错误。
   - 采样与读取间隙已退出的瞬态进程（`ErrorProcessNotRunning`、`os.ErrNotExist`、`ESRCH`、`ENOENT` 且非内核线程/僵尸形态）直接跳过，避免生成空行或误降级。
   - Linux 内核线程或僵尸进程缺失 `/proc/<pid>/exe`（`ENOENT` 且参数列表与 `RSS` 均为空）、未映射容器 UID（`user.UnknownUserIdError` 保留为 `uid:<id>`）、以及 Windows 内核伪进程（`pid == 0 || pid == 4`）不可读取字段，均保留观测行且不误标为字段失败。
   - 其余权限受限或普通读取失败、空进程名保留可读部分字段并将 `processes` 状态降级为 `PARTIAL`（`process_fields_permission_denied` 或 `process_fields_incomplete`）。
3. **磁盘挂载去重与用量校验（`collectDisks`）**：
   - 跳过重复挂载点，拒绝空白、含 NUL、超 1024 字节的挂载点、含 NUL 或超 128 字节的文件系统类型以及 `Used > Total` 的异常用量（`PARTIAL / invalid_mount_usage`），不可读或容量为 0 的挂载保持 `PARTIAL / mount_unreadable`。
   - 与服务端 `AssetService.validDisks` 协同，单条异常分区不再导致整包被服务端否定，同时保留先前完整库存直至全部挂载可读。
4. **Linux 容器来源隔离与 `docker inspect` 截断修复（[container_linux.go](../agent/internal/collector/container_linux.go)）**：
   - 为 `docker`（10s）、`docker inspect`（5s）与 `kubectl`（10s）增加独立进程组超强杀（`Setpgid` + `SIGKILL`）和 8 MiB 输出上限（`containerOutput`），防止外部运行时或控制面挂起阻塞采集循环。
   - 修复 `fillContainerDetails` 使用 `strings.TrimSpace` 裁掉末尾空 `\t` 列的问题（改用 `strings.TrimRight(string(out), "\r\n")`），避免镜像未显式设置 `Config.User` 时丢失第 7 列并漏判 `runs_as_root`；支持 `user:group` 格式提取用户名；`inspect`、JSON 标签解析或输出列数失败时整源回退，不将该源写入 `ContainerSources`。
   - 显式分离缺失（`exec.ErrNotFound`）与查询/解析/`localHostname()` 失败：Docker 与 Kubernetes 均未安装报 `UNSUPPORTED / container_runtime_unavailable`；一源完整而另一源缺失或失败报 `PARTIAL` 并在 `ContainerSources` 仅声明成功源（匹配服务端 [AssetService.java](../server/alinksec-service/src/main/java/com/alinksec/service/asset/AssetService.java) 逐源部分替换契约）；存在失败源且无完整源时报 `FAILED`（不让缺失源掩盖失败源，组合原因截断在 `collectionStatus` 的 128 字节上限内）。
5. **Windows 本地账户与软件注册表边界（[account_windows.go](../agent/internal/collector/account_windows.go)、[software_windows.go](../agent/internal/collector/software_windows.go)）**：
   - `Win32_UserAccount` 扩展读取 `Name, Disabled, PasswordRequired, Lockout, SID`，在整表通过非空、控制字符、长度与大小写不敏感去重校验前不发布 `snap.Accounts`；对可登录且 `PasswordRequired=false`（`UF_PASSWD_NOTREQD`）的本地账户标记风险，明确该字段反映账户策略标志，不等同 SAM 口令哈希破解。
   - Windows 注册表软件清单按 `DisplayName + "\x00" + DisplayVersion` 去重（匹配服务端唯一性键以保留同软件多版本并去重 WOW6432Node 映射），跳过枚举间隙消失的孤立子键，区分 `registry_permission_denied`、`registry_query_failed` 与 `registry_output_invalid_or_limited`；`parseWinDate` 改用 `time.ParseInLocation("20060102", ...)`，拒绝 `"20240231"` 等非法日历日期。

## 兼容与边界

- 协议、数据库迁移（`V038`）、服务端接纳规则及控制台状态组件均无需变更；所有状态码（`COMPLETE`、`PARTIAL`、`FAILED`、`UNSUPPORTED`）、容器来源（`docker`、`kubernetes`）与长度 <= 128 字节的错误码均落在现有契约范围内，`PARTIAL` 与 `FAILED` 均不推进 `succeeded_sequence`。
- `PARTIAL` 用于字段不完整、部分挂载不可读或容器单源失败时，服务端仍保留上一次完整资产列表而更新尝试状态与时间，页面不将缺口误报为“全部资产完整”。
- Windows 宿主自身安全边界保持不变：内核/PPL 保护进程、域控制器/Active Directory 全局账户口令策略及 Docker Desktop Windows 引擎（保持 `UNSUPPORTED / unsupported_platform`）不在本批声明范围内。
