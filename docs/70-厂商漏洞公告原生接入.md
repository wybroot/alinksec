# 厂商漏洞公告原生接入

模块 16 增加四种发布方原生格式，不再要求先转换为平台 `cve-json`。来源计划、失败退避、执行历史、撤销和退役沿用安全库管理。所有示例源默认关闭，部署配置见 [libraries.example.yml](../deploy/libraries.example.yml)。

| 类型 | 原生发现与文档 | 当前形成的依据 |
| --- | --- | --- |
| `ubuntu-usn` | Canonical `/security/notices.json` 分页与单份 USN JSON | 公告、CVE、各发行版修复包和源码/二进制标识；不把公告中所有包与所有 CVE 交叉生成受影响范围 |
| `debian-tracker` | Debian `/tracker/data/json`，请求 gzip 压缩完整快照 | 仅提取显式配置的源码包，其发行版状态、修复版本和紧急程度保留为元数据 |
| `redhat-csaf` | Red Hat CSAF 2.0 `changes.csv` 与 RHSA JSON | 产品状态及包信息；有完整二进制身份和部署产品映射时，仅形成明确的相等 EVR 状态规则 |
| `msrc-cvrf` | Microsoft CVRF v3 `/updates` 与 `/cvrf/YYYY-Mmm` JSON | 产品标识、状态、KB、构建号和 CVSS 元数据；不据此生成主机补丁适用性或已安装结论 |

官方格式和接口依据：[Canonical API 源码](https://github.com/canonical/ubuntu-com-security-api)、[Debian Tracker 说明](https://security-team.debian.org/security_tracker.html)、[Red Hat Security Data](https://access.redhat.com/security/data)、[Microsoft 官方 API 项目](https://github.com/microsoft/MSRC-Microsoft-Security-Updates-API)。发布方可能修订历史文档，原件摘要随抓取记录保存，不把固定示例 URL 当作永不变化的版本。

## 身份与适用性

空 `url` 使用示例中的官方 HTTPS 默认地址；也允许部署指定 HTTPS 镜像。明文 HTTP 仅接受既有回环集成测试地址。镜像来源明确显示为“部署配置的镜像地址”。不跟随重定向，不读取公告内任意外部 URL，不执行公告 HTML、命令或补丁，不接受这些来源的 `api-key`。Microsoft 的月度文档路径由严格验证的月份 ID 构造，不跟随上游 `CvrfUrl`。

原生入库的 `provenance.ingestion=native_vendor_advisory`，含发布方、格式和实际原件记录/摘要。`verification=parsed_transport_document`、`signature_verified=false` 表示已解析并记录传输来源，**没有验证厂商密码学签名**。官方 HTTPS、文档 SHA-256、管理员映射均不等于签名验证。人工 `cve-json` 导入仍不能自带平台 `provenance`。

Red Hat 的 `product_reference` 必须指向可解析的 `pkg:rpm/redhat/...` 二进制包，NEVRA 名称、purl 版本和架构必须一致；排除 `src`/`nosrc`。`default_component_of` 或 `installed_on` 关系的目标产品必须有明确的 `vendor-products` 映射。发行版 ID、版本和架构沿用 Agent 的字面身份，不推断发行版家族或兼容系统。

`known_affected` 生成该完整 EVR 的 `=EVR` 受影响声明；`fixed` / `known_not_affected` 只生成该 EVR 的不受影响声明。**仅有修复版本不能证明所有更早版本受影响**，本模块不生成 `<fixed` 规则，也不填自动修复目标。未知状态、未知关系、源码包及未映射产品保留为元数据。既有规则引擎继续阻止冲突声明参与自动修复。

Debian 数据的包名是源码包名，不能直接对应二进制资产库存。USN 可能同时列出多个 CVE 和多个发行版，公告包列表缺少逐 CVE 范围和架构时不交叉推断。CVRF 中 KB、产品标识和固定构建不能替代 [Windows Update 原生查询](62-Windows更新发现与自动修复.md)；Microsoft 文档也可能涉及非 Windows 产品。

## 发现、续传与保留

`initial-days` 为既有 1～120 天范围，默认 7 天。USN 每页最多 20 项，`vendor-pages` 默认 5、最大 10；页面显示这是有界近期发现，不宣称完整历史覆盖。Red Hat 按索引修改日期选择 RHSA，忽略 RHBA/RHEA；Microsoft 按索引修改日期选择月份。已接受的历史文档仍定期复查，不因退出近期发现窗口而删除。

每源索引最多 4 MiB、32768 个候选；超限失败并保留已导入数据。每轮最多 16 个请求、180 秒、64 MiB 响应总量，单请求最多 30 秒且不跟随重定向。默认每轮处理 2 份文档，可设置 1～4。成功轮次还有待检查文档时，下一轮最早一分钟继续；失败沿用来源计划退避。索引发现时间与文档内部发布时间分别记录，避免日期不同导致重复检查阻塞队列。停用计划停止发起新任务，当前轮次可以完成；退役时数据库锁阻止后续文档提交。

单份传输原件默认最多 32 MiB。Debian 官方支持 gzip，按收到的压缩字节保存并计算摘要；流式解压最多 256 MiB，未选中的源码包不构造 JSON 树。配置必须显式列出 1～100 个 `vendor-packages`。下载为 gzip 时文件扩展名为 `.json.gz`，下载响应使用附件和 `nosniff`，不作为网页执行。

首次同步固定来源的类型、地址、包/产品范围、发现窗口和页数。后续改变这些字段会拦截同步，并在页面显示配置冲突；需先退役旧来源，再用新 ID 配置新范围。修改启停和同步间隔不改变身份。这样不会把旧范围的声明冒充新范围数据。

每份公告的一次版本导入在同一数据库事务内完成：归档原件/摘要、替换该文档的当前 CVE 贡献、汇总同源各文档贡献、更新安全库及治理记录。后续文档失败保留前面已经提交的成功文档，并保留待处理进度；不宣称整轮原子。单条汇总声明仍受既有 256 KiB、200 条规则限制，同一 CVE 最多合并 64 份当前文档、1000 项元数据，超限整份候选回滚。每源贡献最多 100000 条、原件版本记录全局最多 50000 条，达到上限明确失败。

文档删去某个 CVE 时，仅撤销该文档的贡献；其他当前文档仍贡献相应声明。没有当前贡献时保留 `native_presence=not_reaffirmed` 的元数据，不生成受影响规则，也不推断已修复或厂商撤回。跨来源仍按现有整条 CVE 选择规则工作；多来源可信度与冲突策略属于模块 18。

默认原件内容总容量 256 MiB，可设置 32 MiB～1 GiB；每份公告保留最近 2 个原件版本，可设置 1～10。旧版本的原件体可以清理，版本摘要、来源和审计记录保留。超总容量的导入回滚，既有原件保持不变；不会为了腾空间静默删除其他当前公告。达到容量时需调整受控部署容量或使用更小的来源范围。原件保存在 SQLite/PostgreSQL 数据库中，随数据库备份；它们不使用病毒包本地/S3存储目录。

## 控制台与接口

安全库管理的原生来源显示当前文档数和待检查数。“厂商公告”查看原件版本、CVE/包状态数量和发现进度；原件详情显示传输来源、SHA-256、元数据边界、当前贡献 CVE（最多 200 条）及原件是否仍保留。历史版本不表示当前全部贡献仍生效。

所有登录角色可读取列表、详情和原件。同步、计划及退役沿用管理员权限，服务端按 Spring 解析后的路由校验，包含编码路径和矩阵参数的权限用例。原件下载由服务端复核保存摘要，浏览器同时核对详情中的摘要和响应头；异常时拒绝导出。

| 方法 | 路径 |
| --- | --- |
| GET | `/api/libraries/sources/{id}/advisories?page=1&size=20` |
| GET | `/api/libraries/sources/{id}/advisories/{documentId}` |
| GET | `/api/libraries/sources/{id}/advisories/{documentId}/raw` |

分页最多每页 100 条。不存在、已清理原件或摘要不符返回明确错误。原件下载使用 `Cache-Control: no-store` 和 `X-Content-SHA256`。

## 验证范围

专用 CI `vendor-advisories` 从四个官方地址捕获真实原生字节、大小和 SHA-256，直接运行适配器测试，保留公共原件和解析结果；不是把人工 `cve-json` 当作厂商原生样本。专用 CI 不允许真实样本测试跳过。

`VendorAdvisoryIntegrationTest` 使用回环 HTTP 和真实数据库事务，覆盖按文档合并、分批续传、304、重定向拒绝、大小限制、格式失败、回滚、身份固定、退役、原件保留/篡改、只读角色和原生 RPM 精确版本比对。完整 CI 在 SQLite 和 PostgreSQL 应用角色上运行。生产前端构建用实际 SQLite REST 响应验证公告页、原件下载、摘要拒绝、移动端和只读控制；不可用、清理和下载篡改场景是明确的浏览器故障注入。

这些验证不代表所有历史公告都已导入、所有发行版都已覆盖、厂商签名已验证，或真实受管主机已完成补丁安装。正式发布和生产启用仍需单独指令。
