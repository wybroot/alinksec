# 安全来源治理与有界 NVD 同步

本模块在 `security-source-governance` 分支，将公告撤销、来源退役和 NVD 修改窗口拆分整组实现并验收。分支从已完成的漏洞模块提交 `927078b` 创建，依赖 PR #4；没有合并或发布该 PR。V014 保留原始来源数据，追加来源生命周期、原文治理记录、本地撤销标记和 NVD 窗口提示。

## 公告撤销与恢复

单批次拒绝重复 CVE，单条规范公告原文最多 256 KiB，说明最多 65536 字符，防止治理历史分页加载无界原文。规范 `cve-json` 文档可以声明 `status: "withdrawn"`，必须提供非空 `withdrawal_reason` 且 `affected` 为空。未提供状态时按有效声明处理。NVD 的 `REJECT`、`Rejected`、`REJECTED` 记录规范化为已撤销公告，保留元数据，不产生推测规则或补丁。

管理员可在安全库的各来源公告中撤销本地效力，填写原因。操作绑定该来源、CVE、当时原文 SHA-256 和已登录 UID；旧摘要、未登录、已停用或降权的账号、空原因和重复操作拒绝。接口不接受客户端自报操作人。后续远端刷新不会覆盖本地撤销标记；恢复需要管理员针对当前原文另作明确决定，上游仍已撤销的声明不能本地恢复。

来源选择仍按整条 CVE：人工来源优先，其余按来源标识排序。选中声明已撤销时保留该优先位置并清空有效规则，不自动改用较低优先来源。退役整个来源后才从其余来源重新选择。该策略不合并不同发行版范围，也不认证厂商可信度。

当前规则失效会立即使旧 finding 的 `current_match` 失效、使覆盖修订号变化，并撤销该来源公告对应的补丁人工复核。历史结果、原始匹配依据及已完成修复引用保留；撤销不等于已修复。即使恢复同样规则，也不能重新使用被撤销的补丁复核。创建、审批、派发、离线重放和下载凭证继续应用现有固定对象校验。

## 来源退役与特征清空

暂停同步保留有效数据。退役则取消该来源当前效力、阻止导入及自动/手动同步。恢复部署默认计划或重新添加相同 YAML 来源标识不能撤销退役；后续重新接入使用新的来源标识。部署配置中已移除、但仍有数据的来源也在治理列表中可见。人工来源不支持整源退役，使用逐条公告撤销或重新导入。

退役、原始数据保留、治理记录和有效库重算在同一数据库事务中完成。有效 CVE 来源选择共用数据库修订行锁，特征发布共用发布行锁；导入和退役共用来源行锁；下载期间发起退役会明确拒绝，完成后可重试。存储发布失败或外层事务回滚时，保留原有效版本、来源状态和游标，并清理已写入但未提交的候选文件。

特征库发布排除已退役来源，保留其他来源与人工优先的数据。最后一个特征来源退役时，平台可生成具有新版本、零哈希和零规则的受控清空包。一般空文件/空包导入仍拒绝，空远端响应不会清空来源。Agent 既有安装流程能够原子替换该清空包并刷新缓存；零特征表示缺少检测依据，不表示主机安全。

队列发送/重放前核对当前最新特征版本，并重新签发下载凭证；过时版本不会再次派发，旧版本下载凭证在新版提交后失效。已经下载到本地的内容或已经开始的操作无法通过平台回收；离线 Agent 在收到更新前可能沿用旧库。版本心跳和定时推送继续补送最新库，不把平台提交成功当作每台 Agent 已更新。

## 有界 NVD 同步

沿用 [NVD 修改日期分页接口](https://nvd.nist.gov/developers/vulnerabilities)，每个请求同时给出开始和结束日期，保留被拒绝记录。日期跨度最多 119 天，重试/后续窗口有两分钟重叠。第一次默认从最近 7 天开始，可配置 1～120 天；这不是全历史覆盖。

窗口条数超过单次导入容量时，逐次减半结束日期，保存缩小后的窗口提示。总下载仍受默认 64 MiB 限制，每次最多 64 个请求，五分钟后不发起新请求。页面间和缩窗重试均遵循有 Key 700ms、无 Key 6s 的请求间隔。下载器另有连接、读取及流总时限；五分钟预算不强制截断已经开始的单次请求。

只提交一个完整窗口：逐页索引和总数一致，CVE 不重复，页/文档格式合法，全部页完整下载且没有超限。完整窗口的声明、原文历史和游标同一事务提交。坏页、分页总数变化、重复公告、存储/事务失败都不前移游标；已经成功提交的较早窗口不被后续失败回滚。空的完整窗口可前移游标，不删除已有公告。

缩窗提示可以在失败后保留，避免下次重试同样超大的范围。最小推进窗口为 121 秒，确保两分钟重叠之后仍有进展；该窗口仍超容量则明确失败，不能静默截断或跳过日期。页面展示已完成日期和下次窗口上限。较长断档分多次检查推进，成功只说明所显示的窗口完成，不代表已经追上当前时间。首次初始化之前的历史、上游自身延迟和已超出修改窗口的数据仍需独立补库。

## 验证入口

`LibraryGovernanceIntegrationTest` 在真实 SQLite/PostgreSQL 上检查来源退役、优先公告撤销、本地恢复、原文历史、事务回滚、并发导入及最后特征清空。`VulnerabilityWorkflowIntegrationTest` 检查撤销后的审批、恢复后旧离线任务及已签补丁凭证失效；`LibraryIntegrationTest` 用实际 HTTP 分页检查缩窗、坏页、重复和总数变化、空窗口及长断档。`agent/internal/virusscan/retirement_test.go` 安装真实 ZIP，检查旧哈希在清空版本安装与缓存刷新后消失。

本机按 AGENTS.md 串行使用 384 MiB 可用内存阈值、256 MiB Java 堆及 full PSI 10% watchdog。跨架构、原生 Windows、两个数据库和生产页面的最终验收绑定最后提交的集中 CI；尚未完成的检查不能作为已通过证据。
