# 复查进程与过载补证

日期：2026-11-22。基线为已验收主线 `35d9e0f`；分支 `test/review-runtime-boundaries` 仅处理 [89 号核对](89-复查缺陷关闭证据核对.md)剩余 P1 的 REV-002／004／009。产品目标仍为 v0.0.4。本批验收完成前，三项保持 VERIFY。

## 指定场景

- REV-002：测试类路径中的事务包装器在生产业务分发完成后、提交前阻塞；另一个场景在生产事务提交后、gRPC 持久回执发出前阻塞。父进程通过独立连接确认业务与去重的可见状态，再以 SIGKILL 终止真实 JVM。相同数据库、证书和 Agent 工作目录重启后，实际原生 Agent 从生产持久队列补传同一无害日志；业务和去重均恰好一份，显式重复重放仍不重复生效。夹具使用生产 `OfflineQueue.Push` 注入已知身份的无害报告；不是原生日志采集来源验收。报告已完整到达服务端并执行业务，由事务断点证明。
- REV-004：通过真实 REST 创建隔离管理员，分别执行登出、禁用、降权和改密；旧令牌请求读取及缺少业务层账号校验的规则修改入口均被拒绝。重启真实 JVM 后再次执行矩阵，并确认签名密钥不变、未撤销的管理员会话仍有效；新 viewer 会话不能写，新密码会话可使用。相同矩阵在两个真实集群副本上执行，由一个副本撤销、两个副本验证，并重启其中一个副本。
- REV-009：两个明确标记为合成协议负载的客户端，通过真实 mTLS 向生产指标接收路径持续发送多块批次及超大样本。HTTP 下游先延迟 6.2 秒，超过生产 5 秒期限，再恢复为立即响应。同期使用实际原生 Agent 观测心跳与采集指令完成，记录真实登录、业务提交回执、队列计数及每次 HTTP 发送体；恢复后排空队列。

故障控制类仅在 `src/test/java/review/runtime`，通过测试启动器显式加载；不进入生产 jar，也不增加产品故障接口。业务分发、事务实现、会话鉴权、Agent 通信／队列和指标转发均使用生产代码。独立观测 REST 仅存在于该夹具进程，绑定回环地址；其输出不是产品 API。

## 固定资源与可用性目标

单场景串行启动最小服务集：Java 容器 640 MiB、256 MiB 语言堆和一个 CPU，实际 Agent 容器 192 MiB；PostgreSQL 场景另需 256 MiB 容器。原生构建保留一个 worker、256 MiB 堆和 RSS／内存压力看门狗。开始前检查可用内存，运行时在可用内存低于 384 MiB 或 full PSI 超过 10% 时停止；保留原有用户服务和数据。

指标负载固定为两个生产者、每 100 ms 一批、每批 256 个多标签样本及一个超大样本，持续至少 30 秒；第 15 秒切换下游恢复。队列记录数不得超过 4096、总字节不得超过 8 MiB，HTTP 发送体不得超过 256 KiB；必须实际出现丢弃、拒绝和发送失败计数，并观测恢复后的成功发送与队列清空。

本场景在执行前固定的可用性目标：登录和可靠业务回执 P95 不超过 3000 ms，最大不超过 8000 ms；原生采集指令完成时间及所观测心跳最大间隔不超过 8000 ms。原始逐次数据与固定参数一并归档；这是指定资源及负载下的短时软件验收，不扩展为生产规模、长期压力或现场 SLA。

## 执行与范围

本地串行验证已通过 SQLite 与 PostgreSQL 两个场景及原始记录复核。SQLite 登录 P95 约 365 ms、业务回执 P95 193 ms、原生采集指令约 1.34 秒完成；PostgreSQL 对应约 369 ms、194 ms、1.82 秒。两个场景各完成五个会话撤销矩阵、真实 JVM 重启和两个事务退出断点；均无 OOM，验证容器全部清理。本地结果明确标记为未提交工作树，不能替代提交后的完整 CI。可靠队列十个顶层用例及其子用例的普通、race 检查均通过。

首次本地 SQLite 夹具在种子管理员尚未初始化时登录失败，随后在观测记录中发现隐式 GET 请求的方法读取错误；两次记录均保留，修正夹具后完整场景通过。最终验收还要求 CI 重跑原始回滚／可靠回执回归、两架构 SQLite、PostgreSQL、两架构集群真实重启与跨副本矩阵，并在 Windows 2022／2025 原生主机重跑十个可靠队列用例。原始归档须核对来源提交、运行编号、ZIP 摘要及内容；完成精确完整 CI 后再更新三项关闭状态。
