# 模块完善计划

开发按模块顺序推进：一个功能模块对应一条分支，在该分支完成实现、系统适配、异常处理和验证后，再整理 PR。当前 PR 保持草稿；合并和新版本发布留到功能完成后统一安排。

## 当前模块：基线

分支：`baseline-template-review`。

已经完成模板包导入、版本差异、审核、指定主机测试、发布、撤回、按 Agent 系统和版本选模、任务快照和角色权限。继续完善以下方面，完成后再进入下一模块：

| 范围 | 完成条件 |
|---|---|
| 模板内容 | Linux、Windows 的检查项、适用范围、来源和人工处置说明明确；未支持规则可追溯；不把基础候选包宣称为完整合规标准 |
| 系统适配 | 混合系统逐台选择适用模板；未覆盖、旧 Agent、未知系统和版本不产生虚假的通过结论 |
| Agent 执行 | 检查串行执行；文件和命令读取有资源上限；异常与不合规结果分开显示；超时不会阻塞后续任务 |
| 审核发布 | 测试必须完整，执行异常明确阻止发布；说明和证据保留；发布、撤回和任务创建之间有一致的事务约束 |
| 结果与历史 | 并发回报不会丢进度；重复回报不改变已接受证据；任务定义和结果能够追溯；晚到结果与超时状态一致 |
| 修复 | 检查与修复定义对应，权限和审批有效；错误、过期或已撤回定义不提供自动修复 |
| 体验与验收 | 角色、桌面和手机流程完整；SQLite/PostgreSQL、Linux amd64/arm64 与原生 Windows 的相关检查通过 |

当前加固已覆盖有界执行、明确执行状态、异常与旧结果禁止发布、首份完整证据保留、并发进度、超时补传、较新任务证据优先，以及修复 API 的系统/启用状态/定义校验。跨平台生产包和 PostgreSQL 验收以当前源码的 CI 结果为准，完成加固验收后仍继续留在本分支审核模板内容。

旧 Linux 全部 60 项已完成源码内容审核和安全处置：V006 停用不可靠参考模板，修正当前乱码和人工说明，取消旧自动修复，保留历史证据；8 项进入明确范围的新观测候选，2 项在独立 Ubuntu 24.04 OpenSSH 包中查询指定连接的配置，7 项在独立 Ubuntu 24.04 本地身份包中核对元数据与明确账户范围，2 项在独立 Ubuntu24.04 passwd PAM 包中核对已支持口令链的质量与新口令散列，1 项在独立login PAM包中核对已支持认证链的失败锁定参考，2 项在独立systemd包中观察auditd/rsyslog当前单元状态，3 项在独立固定日志元数据包中核对审计目录和btmp/wtmp，35 项记录尚未实现原因。通用观测包仍明确列出自身未包含的52项，不扩大其覆盖。默认 Linux/Windows 包升级为版本 2，收窄产品/版本并注明确切观察边界；旧失败默认值选择器已移除。详见 [内容审核记录](20-旧基线模板内容审核.md)。

下一步依次完善：服务/审计及其他产品策略，再扩展确切产品的其他认证链；剩余35项的实现按各自产品范围推进。产品条件见 [OpenSSH 配置核查](21-OpenSSH配置核查.md) 、[本地身份文件核查](22-本地身份文件核查.md) 、[PAM口令链核查](23-PAM口令链核查.md) 、[PAM登录失败锁定核查](24-PAM登录失败锁定核查.md) 与 [systemd服务状态核查](25-systemd服务状态核查.md)。继续完善的内容为按实际产品实现剩余规则的有效配置解析，并取得对应发行版和 Windows 版本的原生证据；不把部分参数观测宣称为完整基线。每一批实现都用该提交的跨平台 CI 记录验收，PR 保持草稿。独立 GitHub runner 上没有依赖的 CI 作业并行执行（Linux 双架构 max-parallel=2）；同一 runner 的共享状态检查和本机约 2 GiB 下的重验证仍串行。基线模块整体尚未完成，不进入后续模块。

## 后续模块：依次实施

1. 漏洞判断与修复适用性：软件来源、发行版和软件包架构；RPM/DPKG 完整版本比较；回移修复判断；明确公告、可比对规则、资产命中和已确认修复版本的区别。现有宽松比较器及 RPM 采集丢失 epoch 已记录，尚未修改实现。
2. 安全来源治理：公告撤销、来源退役、NVD 大修改窗口拆分，按需要接入厂商公告、Vulnerability-Lookup 或 OpenCTI。
3. 检测能力和部署完善：按需要独立评估 ClamAV/YARA、持续负载及更完整的交付流程。

各模块开始前再细化范围。当前基线模块完成之前，这些待办只保留记录，不交叉实施。
