# 主机详情、组件健康与全量真机验收

本轮在 `develop` 开发，发布版本基线为 v0.0.4。只保留 `main`、`develop` 两条分支；原分支来源与合并关系、分支归档由本机验收记录保留。本轮不自动合并主线或发布版本。

## 主机详情

桌面详情面板最大 1120 px，窄屏适应 96vw。概览包含 CPU／内存最新值、运行时长、开机时间、系统／内核／架构、CPU 型号和核心数、总内存、时区、虚拟化、Agent 与策略版本、IP／MAC、最近心跳、磁盘容量及采集时间。软件、容器、进程、监听端口与风险账户分标签查看。软件仍显示前 500 条并明确数量上限。

心跳携带实际硬件信息，首次 CPU 采样只预热。服务端按认证 Agent 身份保存最新运行信息及每分钟最后一次采样，定时清理超过一小时的历史，包括离线主机。有效 0% 保留为 0%，缺失／无效采样和断线缺口显示未知，不补零。旧 Agent 可继续连接；获取新增硬件及有效空闲采样需要更新 Agent。详情每 15 秒刷新性能，离线或采样超过 90 秒会提示过期。

该功能使用 V037 的 `t_host_runtime`、`t_host_metric`、`t_asset_disk`，兼容 SQLite 和 PostgreSQL。更新前保存数据库、证书、JWT、上传物料和部署配置成套备份。已迁移后的数据库不能直接回退旧镜像。

VictoriaMetrics 仍提供全量时序和长期存储。新版详情的基本性能不依赖它。启用后需同时验证健康接口与实际指标写入／查询；健康接口正常不能证明有指标。

## 组件健康

系统管理 → 组件健康，仅管理员访问；接口为 `GET /api/system/health`。页面每 30 秒刷新，服务端只读检测缓存 10 秒。检查 API/JVM、数据库只读查询、gRPC、本地存储权限／可用容量、服务端证书、VictoriaMetrics，以及集群模式的 Redis、RabbitMQ 与协调就绪状态。

状态分正常、需关注、异常、未启用。可选依赖未启用时不发起连接，且不计为正常；检测失败不返回连接串、凭据或原始异常。页面刷新失败保留上次结果并标记过期。信息仅属于响应请求的服务端实例，其他副本见服务集群页。

## 监控大屏

大屏按接口实际统计范围展示：告警级别分布为全部待处置告警；病毒检出数为近 30 日检出记录；趋势按首次发生日期统计病毒告警和带响应动作记录的告警，不将 `alert_only` 等动作声明当作已成功阻断。能力目录展示内置功能与说明，主机总防护开关数取完整汇总，不推断每个引擎的运行状态。最近基线任务缺少评分时显示未知；分类图仅展示最近完成任务实际返回的分类，没有结果时显示空状态，不补六项零分或推断风险等级。

`/screen` 中的实时安全事件流循环滚动，表头固定；鼠标悬停、键盘聚焦或点击暂停按钮可以停住阅读。零条事件显示空状态，一条事件静态展示，多条事件循环回放。数据仍每 30 秒从真实接口刷新，新事件高亮；刷新失败保留上次数据并提示更新暂不可用。

中央地球只显示有定位依据的真实端点。SSH／Windows 登录暴破与异常登录，以及已接入检测源上报的 Web 攻击、SQL 注入、XSS、命令注入、路径穿越、SSRF、远程执行、端口扫描等网络攻击，均读取实际采集的 `detail.source_ip`；来源未知仍计入攻击事件。目标来自服务端登记的 Agent 身份及主机 IP；文件、进程与 Agent 状态事件按本机事件归属展示。没有来源、缺少任一端点定位或查询失败，不生成攻击连线、不推算坐标、不填零。可定位的链路使用球面弧线，与大洲、端点共用三维旋转和背面遮挡；首次载入的历史告警不播放攻击流光，仅后续观测到新的告警或次数／时间更新时播放一次；新事件的定位尚未返回时最多等待 65 秒，补齐后播放一次，历史事件仅补定位不重播。右侧可查看实际来源、目标、发生时间、累计次数和动作；定位信息标明 IPIP 城市近似或资产登记，IP 位置不代表攻击者物理位置。动画上限为 30 帧、像素倍率最多 1.5，支持暂停，隐藏页面、离开路由或系统减少动态效果时停止。

新增只读接口 `GET /api/dashboard/screen-situation`，读取最新 20 条实际告警并补充定位状态。前端最多绘制前 10 条有双端定位的网络链路，定位服务失败不影响实际告警列表。离线与商业查询共用 `GeoLocationProvider` 适配接口，在服务端后台串行执行，界面请求不等待第三方；队列最多 64，缓存最多 2048 条，成功缓存 24 小时，失败缓存 5 分钟并退避 60 秒，每 2 秒最多发起一次查询。仅查询字面量公网 IPv4／IPv6，内网、回环与保留地址不外发。固定使用 HTTPS 官方地址、不跟随重定向、限制响应 16 KiB，连接和读取设有超时。

默认使用离线完整 MMDB 文件，部署时由运维独立下载，应用不将整库装入 Java 堆；使用单个内存映射读取器，同时支持 IPv4 和 IPv6。当前本机已从 [DB-IP 官方](https://db-ip.com/db/download/ip-to-city-lite) 下载 2026-10 City Lite 完整发布库（126,998,165 字节，7,786,864 条范围），验证官方 SHA1 后安装；这是免费 City Lite 的全部发布内容，覆盖与精度低于商业库，不等于商业全量库。大屏提供 DB-IP 署名链接，定位结果带数据来源与版本。私网目标需按实际 Agent ID 登记资产位置；未登记显示未知，不按内网 IP 猜城市。

使用 `python3 deploy/update-geoip.py --month YYYY-MM --sha1 <厂商页面SHA1SUM> --destination data/geoip.mmdb` 更新。脚本固定从厂商 HTTPS 下载完整 gzip 流，边解压边计算摘要，不缓存整库；内存压力、磁盘、大小、时限、gzip 或校验失败均中止并保留现用文件。成功后原子替换。复制 `deploy/geoip.example.yml` 为服务端 `data/geoip.yml`，设置 `provider: offline`、`database-file`。管理员 `GET /api/system/geoip` 查看库版本、年龄、IPv4/IPv6、加载状态，`GET /api/system/geoip/lookup?ip=<字面量IP>` 做独立定位诊断（不生成业务攻击事件）；`POST /api/system/geoip/reload` 重新读取配置路径中的新库并清除定位缓存，无需重启。该接口不接受远程 URL／任意文件路径，复用 `/api/system` 管理员鉴权；新库无法打开或不符合城市格式时，继续使用旧读取器并返回更新失败。超过 45 天提示更新。文件更新需使用原子替换，禁止就地截断正在映射的库；需要持久回滚时先将旧发布另存为版本文件。

商业接口已提供 IPIP 适配：设置 `provider: ipip` 直接使用，或保持离线主库、设置 `fallback-provider: ipip` 仅在离线未覆盖／不可用时查询。需配置有经纬度权限的有效 Token 文件；`token-file` 不返回前端、不写日志或仓库。也支持 `ALINKSEC_GEOIP_PROVIDER`、`ALINKSEC_GEOIP_DATABASE_FILE`、`ALINKSEC_GEOIP_FALLBACK_PROVIDER`、`ALINKSEC_GEOIP_TOKEN_FILE`。商业请求每 2 秒最多一次；没有 Token 时不外发，真实 IPIP 上游查询待验。接口与字段依据 [IPIP 官方文档](https://www.ipip.net/api.html)，IPv6 权限取决于套餐。新增厂商可实现 `GeoLocationProvider` 并登记前端来源标签，球面绘制无需修改；IPIP 专有 IPDB 文件解析器尚未集成。

SSH 检测来自既有 Linux 登录日志防护，Windows 登录来自既有安全事件防护。Web 类分类与接入契约已经支持；当前没有新增 WAF 引擎，也没有将普通访问日志当攻击告警。检测源通过既有认证 Agent 上报 `RptSecurityEvent`，`type` 使用 `web_attack`／`sql_injection`／`xss`／`network_attack` 等已支持类型，`detail.source_ip` 填检测实际观察到的客户端地址；不能直接相信未验证的 X-Forwarded-For。目标归属取认证 Agent 和资产表。不同来源 IP 的 Web 告警分开聚合；缺来源也保留攻击记录。Web 来源检测的真实现场接入仍需相应日志检测器／WAF，不能以受控事件验证宣称已覆盖真实 Web 攻击检测。

离线定位改动阶段已完成完整离线库的 IPv4／IPv6 实际服务查询、无凭据商业服务不外发、管理员维护入口未登录拒绝、坏库继续使用旧读取器与恢复热加载、实际 HTTPS 产物摘要核对；受控页面检查 13 项通过，包含 SSH／Web 分类、真实球面端点与新攻击等待定位后一次流光。真数据页面已实际渲染并留存截图，但本机内存压力保护中止了最后的完整浏览器复核，保持待验；不增加阈值或继续反复启动浏览器。

后续统计口径修正通过 21 项串行前端单元测试、完整本地前端构建及 6 项实际 ECharts SVG 渲染检查，覆盖未知评分、真实零分、实际核查数量和分类图空／有／空切换时清除旧结果。SVG 检查未启动浏览器，不替代上述待验的完整浏览器流程；新增浏览器断言随源码保留待执行。

本批改动按用户要求先做本地验证，不推送或触发 CI；CI 留到生产发布阶段。低内存环境可在 `web` 下运行 `npm run build:local`，将共用依赖先预打包，再以 256 MiB Node 堆和单个 esbuild 工作线程构建完整前端，产物位于 `web/.tmp/local-dist`。构建前停止应用服务并启用资源监测，结束后恢复服务；该命令本身不替代主机资源保护。使用 `ALINKSEC_SCREEN_DIST=.tmp/local-dist node test/screen-browser.mjs` 验证动画、暂停、空数据、刷新失败及减少动态效果行为，支持 `ALINKSEC_SCREEN_CAPTURE` 重放本机只读接口采集。生产标准构建命令仍为 `npm run build`。

## 全量验收标准

真机验收还发现旧生成证书缺少 SKI／AKI 扩展，Python 严格 TLS 校验会拒绝连接。新生成的 CA、服务端和 Agent 证书均补齐密钥标识，并验证 OpenSSL 严格链校验。已有 PKI 不自动重签；修复旧部署须先备份整套 PKI，核对原 CA／证书公钥和用途，保持 SAN、有效期及身份，并同步客户端 CA 信任。不得通过关闭证书校验来验收通过。

用户于 2026-10-26 恢复全面真机验收，之前延后的现场项目重新列入待验。必须覆盖每个模块的成功、失败、权限、恢复和界面流程，分别记录当前源码的自动化回归、本机真实功能和其他现场环境。CI、模拟接口边界测试、组件在线以及单台短时运行均不能替代完整现场结论。

| --- | --- |

本机不具备 Windows／全部 Linux 发行版与 ARM64 真机、200 台真实主机、私有 OpenCTI／WSUS 等完整条件；相应项目保持待验，不能以 CI fixture 验收代替。当前完整结果记录在本机 `validation-records/develop-host-detail-health/full-functional-acceptance.json`，历史发布证据不回写为本轮通过。

本机验证必须串行并监测可用内存、内存压力及磁盘。用户要求磁盘达到 98% 时暂停并清理无用数据；构建提前保留至少 2 GiB。清理本轮可重建临时文件和缓存，保留业务数据、证据、凭据与回滚材料。
