# 主机详情、组件健康与全量真机验收

本轮在 `develop` 开发，发布版本基线为 v0.0.4。只保留 `main`、`develop` 两条分支；原分支来源与合并关系、分支归档由本机验收记录保留。本轮不自动合并主线或发布版本。

## 主机详情

桌面详情面板最大 1120 px，窄屏适应 96vw。概览包含 CPU／内存最新值、运行时长、开机时间、系统／内核／架构、CPU 型号和核心数、总内存、时区、虚拟化、Agent 与策略版本、IP／MAC、最近心跳、磁盘容量及采集时间。软件、容器、进程、监听端口与风险账户分标签查看。软件仍显示前 500 条并明确数量上限。

心跳携带实际硬件信息，首次 CPU 采样只预热。服务端按认证 Agent 身份保存最新运行信息及每分钟最后一次采样，定时清理超过一小时的历史，包括离线主机。有效 0% 保留为 0%，缺失／无效采样和断线缺口显示未知，不补零。旧 Agent 可继续连接；获取新增硬件及有效空闲采样需要更新 Agent。详情每 15 秒刷新性能，离线或采样超过 90 秒会提示过期。

该功能使用 V037 的 `t_host_runtime`、`t_host_metric`、`t_asset_disk`，兼容 SQLite 和 PostgreSQL。更新前保存数据库、证书、JWT、上传物料和部署配置成套备份。已迁移后的数据库不能直接回退旧镜像。

VictoriaMetrics 仍提供全量时序和长期存储。新版详情的基本性能不依赖它。启用后需同时验证健康接口与实际指标写入／查询；健康接口正常不能证明有指标。

## 组件健康

系统管理 → 组件健康，仅管理员访问；接口为 `GET /api/system/health`。页面每 30 秒刷新，服务端只读检测缓存 10 秒。检查 API/JVM、数据库只读查询、gRPC、本地存储权限／可用容量、服务端证书、VictoriaMetrics，以及集群模式的 Redis、RabbitMQ 与协调就绪状态。

状态分正常、需关注、异常、未启用。可选依赖未启用时不发起连接，且不计为正常；检测失败不返回连接串、凭据或原始异常。页面刷新失败保留上次结果并标记过期。信息仅属于响应请求的服务端实例，其他副本见服务集群页。

## 全量验收标准

用户于 2026-10-26 恢复全面真机验收，之前延后的现场项目重新列入待验。必须覆盖每个模块的成功、失败、权限、恢复和界面流程，分别记录当前源码的自动化回归、本机真实功能和其他现场环境。CI、模拟接口边界测试、组件在线以及单台短时运行均不能替代完整现场结论。

| 范围 | 应覆盖的业务 |
| --- | --- |
| 接入与资产 | 注册、mTLS 身份、重连补传、资产完整性、分页筛选、硬件与性能 |
| 主动防护 | 策略同步、登录／文件／勒索事件、封禁与解除、隔离失联恢复、弱口令覆盖 |
| 病毒检测 | SHA256／ClamAV／YARA、特征库更新、扫描、白名单、文件隔离／恢复 |
| 漏洞与修复 | 公告与情报同步、适用性、包身份、审批／维护窗口、实际安装和结果复查 |
| 基线与合规 | 包审核／测试／发布／撤回、等保范围、XCCDF／OVAL、混合系统与异常 |
| 系统与运维 | 权限审计、通知、升级回退、卸载、报表导出、日志取证、备份恢复、双数据库与 TLS |
| 集群与规模 | 跨副本通信、队列与故障恢复、200 台真实 Agent 和 72 小时要求 |
| 前端操作 | 全部模块桌面／手机页面、真实数据、缺失／失败／过期状态 |

本机不具备 Windows／全部 Linux 发行版与 ARM64 真机、200 台真实主机、私有 OpenCTI／WSUS 等完整条件；相应项目保持待验，不能以 CI fixture 验收代替。当前完整结果记录在本机 `validation-records/develop-host-detail-health/full-functional-acceptance.json`，历史发布证据不回写为本轮通过。

本机验证必须串行并监测可用内存、内存压力及磁盘。用户要求磁盘达到 98% 时暂停并清理无用数据；构建提前保留至少 2 GiB。清理本轮可重建临时文件和缓存，保留业务数据、证据、凭据与回滚材料。
