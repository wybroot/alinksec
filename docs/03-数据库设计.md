# ALinkSec 数据库设计（PostgreSQL 17 + VictoriaMetrics + Redis + RabbitMQ + MinIO）

> 版本：V1.0（设计评审稿）
> 日期：2026-08-25

## 1. 存储分治总览

| 存储 | 承载数据 | 保留策略 |
|------|----------|----------|
| PostgreSQL 17 | 资产、策略、任务、告警、审计、系统配置 | 永久（审计按需归档） |
| VictoriaMetrics | 时序指标（CPU/内存/磁盘/网络/进程数） | 90 天（`-retentionPeriod=90d`） |
| Redis | 在线状态、待推指令、限流、去重 | TTL 自动过期 |
| RabbitMQ | 业务上报消息（异步削峰） | 消费即删，死信队列保留 24h |
| MinIO | 事件证据、报表导出、升级包/安装包 | 按桶策略 |

**数据流转**：

```
Agent 上报
 ├─ metrics      → gateway 聚合 → VM（Prometheus 文本格式 /api/v1/import/prometheus）
 ├─ heartbeat    → gateway → Redis（在线态）
 ├─ ack          → gateway → PG（t_command 状态更新）
 └─ 其余业务上报 → RabbitMQ → consumer → PG（批量入库）
```

## 2. PostgreSQL 业务库（库名：alinksec）

> 约定：所有表含 `created_at`/`updated_at`（TIMESTAMPTZ，默认 now()）；JSONB 字段用于策略/详情等半结构化数据，避免频繁 DDL。

### 2.1 资产域

```sql
-- Agent/主机
CREATE TABLE t_agent (
  id             BIGSERIAL PRIMARY KEY,
  agent_id       VARCHAR(64)  NOT NULL UNIQUE,      -- UUID，证书 CN
  hostname       VARCHAR(255) NOT NULL,
  ip             VARCHAR(64),                       -- 主通信 IP
  os_type        SMALLINT     NOT NULL,             -- 1=linux 2=windows
  os_version     VARCHAR(128),
  kernel         VARCHAR(128),
  arch           VARCHAR(16),
  agent_version  VARCHAR(32),
  machine_id     VARCHAR(128),                      -- 防重复注册
  group_id       BIGINT       REFERENCES t_host_group(id),
  status         SMALLINT     NOT NULL DEFAULT 0,   -- 0待激活 1在线 2离线 3禁用 4已删除
  protect_enabled BOOLEAN      NOT NULL DEFAULT TRUE,
  policy_version VARCHAR(32),
  cert_serial    VARCHAR(64),
  last_heartbeat TIMESTAMPTZ,
  tags           JSONB        NOT NULL DEFAULT '{}',
  created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
  updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now()

CREATE INDEX idx_agent_group ON t_agent(group_id);
CREATE INDEX idx_agent_status ON t_agent(status);
CREATE UNIQUE INDEX uq_agent_machine ON t_agent(machine_id) WHERE machine_id IS NOT NULL;

  id          BIGSERIAL PRIMARY KEY,
  name        VARCHAR(128) NOT NULL UNIQUE,
  parent_id   BIGINT,
  description VARCHAR(512)

-- 软件资产（快照式：agent 维度全量替换更新）
CREATE TABLE t_asset_software (
  id           BIGSERIAL PRIMARY KEY,
  agent_id     VARCHAR(64) NOT NULL,
  name         VARCHAR(255) NOT NULL,
  version      VARCHAR(64),
  vendor       VARCHAR(255),
  install_time TIMESTAMPTZ,
  source       VARCHAR(32),              -- rpm/dpkg/registry
  updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_sw_agent ON t_asset_software(agent_id);
CREATE INDEX idx_sw_name  ON t_asset_software(name, version);

CREATE TABLE t_asset_port (
  id        BIGSERIAL PRIMARY KEY,
  agent_id  VARCHAR(64) NOT NULL,
  port      INTEGER NOT NULL,
  protocol  VARCHAR(8)  NOT NULL,        -- tcp/tcp6/udp
  bind_addr VARCHAR(64),
  process   VARCHAR(255),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE(agent_id, port, protocol, bind_addr)
);

-- 进程资产（快照式；命令行中的口令/令牌参数由 Agent 脱敏后上报）

CREATE TABLE t_asset_account (
  id          BIGSERIAL PRIMARY KEY,
  agent_id    VARCHAR(64) NOT NULL,
  name        VARCHAR(128) NOT NULL,
  uid         INTEGER,
  gid         INTEGER,
  shell       VARCHAR(128),
  login_enabled BOOLEAN,
  last_login  TIMESTAMPTZ,
  risky       BOOLEAN DEFAULT FALSE,     -- 空口令/UID0非root等
```

### 2.2 基线核查域

```sql
CREATE TABLE t_baseline_template (
  id          BIGSERIAL PRIMARY KEY,
  code        VARCHAR(64) NOT NULL UNIQUE,   -- DJBH2.0-LINUX / CIS-UBUNTU-2204
  name        VARCHAR(128) NOT NULL,
  standard    VARCHAR(64),                   -- 等保2.0 / CIS
  os_type     SMALLINT NOT NULL,
  version     VARCHAR(32) NOT NULL DEFAULT '1.0',
  item_count  INTEGER NOT NULL DEFAULT 0,
  enabled     BOOLEAN NOT NULL DEFAULT TRUE
);

-- 核查项：check 为 JSONB，Agent 端引擎解释执行（热更新，无需升级 Agent）
CREATE TABLE t_baseline_item (
  id          BIGSERIAL PRIMARY KEY,
  template_id BIGINT NOT NULL REFERENCES t_baseline_template(id),
  code        VARCHAR(64) NOT NULL,          -- BL-LINUX-0001
  name        VARCHAR(255) NOT NULL,
  category    VARCHAR(64),                   -- 身份鉴别/访问控制/安全审计/入侵防范/...
  severity    SMALLINT NOT NULL,             -- 1低 2中 3高 4严重
  check       JSONB NOT NULL,                -- 核查规则（格式见 04-Agent设计 §4）
  remediation TEXT,                          -- 整改建议（人读）
  fix_spec    JSONB,                         -- 可自动执行的修复步骤（格式见 05-扩展能力 §3.2）
  enabled     BOOLEAN NOT NULL DEFAULT TRUE,
  UNIQUE(template_id, code)
);

CREATE TABLE t_baseline_task (
  id           BIGSERIAL PRIMARY KEY,
  task_no      VARCHAR(64) NOT NULL UNIQUE,
  name         VARCHAR(128),
  scope        JSONB NOT NULL,               -- {"group_ids":[],"agent_ids":[]}
  template_ids BIGINT[] NOT NULL,
  status       SMALLINT NOT NULL DEFAULT 0,  -- 0待执行 1执行中 2完成 3部分失败 4取消
  progress     SMALLINT NOT NULL DEFAULT 0,  -- 百分比
  created_by   BIGINT,
  started_at   TIMESTAMPTZ,
  finished_at  TIMESTAMPTZ,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 结果明细（核查一次写一条；2000台×60项 = 12万行/任务，按 task_id 分区可后续演进）
CREATE TABLE t_baseline_result (
  id          BIGSERIAL PRIMARY KEY,
  task_id     BIGINT NOT NULL,
  agent_id    VARCHAR(64) NOT NULL,
  item_id     BIGINT NOT NULL,
  passed      BOOLEAN NOT NULL,
  actual      TEXT,
  checked_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_bl_result ON t_baseline_result(task_id, agent_id);
CREATE INDEX idx_bl_result_fail ON t_baseline_result(task_id) WHERE passed = FALSE;

-- 汇总（报告页直查，避免扫明细）
CREATE TABLE t_baseline_summary (
  task_id      BIGINT NOT NULL,
  agent_id     VARCHAR(64) NOT NULL,
  total        INTEGER NOT NULL,
  passed_count INTEGER NOT NULL,
  failed_count INTEGER NOT NULL,
  score        NUMERIC(5,2) NOT NULL,       -- 合规分 = passed/total*100
  checked_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY(task_id, agent_id)
);
```

## 3. VictoriaMetrics 指标设计

### 3.1 指标命名与标签

> 前缀统一 `alinksec_`，Prometheus 规范。label 固定携带 `agent_id`（必需）与 `hostname`（冗余，便于直查）。

| 指标名 | 类型 | 额外 label | 说明 |
|--------|------|-----------|------|
| `alinksec_cpu_usage` | gauge | — | 总使用率 %（10s） |
| `alinksec_cpu_load1/5/15` | gauge | — | load（10s） |
| `alinksec_mem_used_bytes` | gauge | — | 已用内存（10s） |
| `alinksec_mem_total_bytes` | gauge | — | 总内存（快照，60s） |
| `alinksec_swap_used_bytes` | gauge | — | swap 使用 |
| `alinksec_disk_used_bytes` / `alinksec_disk_total_bytes` | gauge | `mount` | 磁盘使用（60s） |
| `alinksec_disk_read_bytes_total` / `write` | counter | `device` | 磁盘 IO 累计（10s，rate() 计算） |
| `alinksec_net_rx_bytes_total` / `tx` | counter | `iface` | 网卡流量累计（10s） |
| `alinksec_process_count` | gauge | — | 进程数（10s） |
| `alinksec_agent_up` | gauge | — | 服务端侧心跳写入，1/0（辅助判定，非 Agent 自报） |

**基数控制**：2000 台 × 平均 25 序列 ≈ 5 万序列，VM 单机轻松承载；mount/iface 数量大的机器在 Agent 侧过滤虚拟网卡与 tmpfs 挂载点（可配置白名单）。

### 3.2 写入与查询

- **写入**：gateway 将 `MetricSample` 转 Prometheus 文本格式（`name{labels} value ts`），POST `/api/v1/import/prometheus`，500 条或 100ms 批量刷写。
- **查询**：服务端通过 `/api/v1/query`（即时）、`/api/v1/query_range`（区间，如大盘趋势图）以 MetricsQL/PromQL 查询，典型查询：
  - 实时：`alinksec_cpu_usage{agent_id="xxx"}` 
  - 趋势：`avg_over_time(alinksec_cpu_usage{agent_id="xxx"}[1h])`
  - TOP：`topk(10, alinksec_cpu_usage)` 
- **保留**：单机 `-retentionPeriod=90d`；容量 ~50GB 内（详见总体设计 §6.3）。

## 5. RabbitMQ 拓扑

```
Exchange: alinksec.report (topic, durable)
 ├─ routing report.asset.#     → q.asset     （资产快照入库）
 ├─ routing report.baseline.#  → q.baseline  （基线结果/修复结果入库）
 ├─ routing report.scan.#      → q.scan      （扫描结果入库）
 ├─ routing report.virus.#     → q.scan      （病毒扫描结果入库）
 └─ routing report.security.#  → q.security  （安全事件 → 告警引擎）

Exchange: alinksec.notify (topic)
 └─ routing notify.#           → q.notify    （通知发送，重试3次后死信）

DLX: alinksec.dlx → q.dead（保留24h，人工排查消费失败）
```

- 消息体：proto 序列化后的业务 payload + envelope（agent_id、report_id、ts）。
- consumer 手动 ACK；失败重回队列 2 次后进死信。
- q.security 消费者即**告警引擎**：聚合去重（5min 窗口同源累加 count）→ t_alert upsert → 投递通知。

## 7. 容量与性能预估（2000 台满配）

| 项 | 估算 |
|----|------|
| t_baseline_result | 12 万行/次全量核查任务；保留最近 N 次任务明细（默认 10 次，job 清理） |
| t_alert | 常态 < 1000 行/天（聚合后）；detail JSONB 单行 < 16KB |
| t_audit_log | < 5000 行/天 |
| VM | 5 万序列，~250-500MB/天，90 天 ≈ 25-50GB |
| PG 总量 | 常态增长 < 100MB/天（结果/告警明细），年增量 < 40GB |
| RabbitMQ | 峰值 6000 msg/s（扫描任务集中上报时），队列堆积上限保护（q长度>5万触发告警） |

**索引与查询优化要点**：

- 大盘首页只查 Redis 在线态 + VM 聚合，不扫 PG。
- 基线/扫描结果页查 summary 表，点进详情才查明细。
- `t_baseline_result` 若单表超过 5000 万行，按 `task_id` 转 PG 原生分区表（设计已预留）。
