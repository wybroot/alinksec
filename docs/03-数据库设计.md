# ALinkSec 数据库设计（PostgreSQL／SQLite + VictoriaMetrics）

> 版本基线：v0.0.4。已按本版核对「ALinkSec 数据库设计（PostgreSQL / SQLite + VictoriaMetrics）」的操作、实现引用与适用边界；历史日期及验证结果仍只对应其原始提交。版本差异见[发布说明](releases/v0.0.4.md)，全部资料见[文档索引](README.md)。

## 当前存储与迁移基线

已发布 v0.0.4 不新增数据库迁移，版本化迁移截至 V036。当前未发布 develop 追加 V037：`t_host_runtime` 保留最新心跳与硬件，`t_host_metric` 保留一小时的分钟采样并定时清理离线主机历史，`t_asset_disk` 保存实际磁盘快照；SQLite 启动前迁移，PostgreSQL 先通过部署迁移入口应用。不要用旧镜像覆盖已经迁移的数据库；回滚应恢复成套备份。PostgreSQL 初始结构在 [001_init.sql](../deploy/sql/001_init.sql)，部署迁移在 [deploy/migrations](../deploy/migrations)；SQLite 初始结构和共用／方言迁移由 [db](../server/alinksec-bootstrap/src/main/resources/db)与应用迁移注册表管理。实际字段、索引、外键、约束和权限以这些源码为准，不再复制会过期的早期 DDL。

| 存储 | 当前用途 | 边界 |
| --- | --- | --- |
| PostgreSQL 17 | 业务、任务、回执、来源、日志和集群持久事实 | 单实例或可选应用集群；数据库 HA 由部署方提供 |
| SQLite WAL | 同一业务模型的单实例轻量部署 | 本地文件、外键和锁等待；不放在 NFS／SMB，不启用集群 |
| VictoriaMetrics | 标准模式的时序指标，默认保留 90 天 | 轻量模式默认关闭；规模与一秒目标仍待现场验证 |
| Redis（集群可选） | 会话租约、配置绑定及登录限流 | 单一 HA 端点，非 Redis Cluster／Sentinel 自动发现 |
| RabbitMQ（集群可选） | SQL 收件箱 ID 的 durable quorum 提示 | 不是业务事实存储；提交后确认、丢提示由 SQL 恢复 |
| server-data／可选已有 S3 | PKI、JWT、安全库、补丁、升级包及证据 | 对象存储配置只覆盖支持的物料；PKI 与共享目录仍按部署契约保存 |

## 初始化与权限

全新 PostgreSQL 部署先运行初始 SQL，再由[迁移脚本](../deploy/migrations/run-migrations.sh)按顺序执行版本并建立受限应用角色。应用账号不使用超级用户／DDL 权限；迁移在维护窗口由独立身份执行。SQLite 在业务 Bean 使用数据库前校验并应用迁移；已发布迁移保持不可变。

当前交付以全新部署为范围，真实旧生产库升级演练未执行；迁移回归不代替现场升级。备份／恢复必须同时包含数据库、server-data、Web TLS 和配置；恢复前后核对 JWT 与 CA 一致性，见[成套恢复](54-部署维护与成套恢复.md)与[启动检查](81-发布后启动凭据核查.md)。

## 持久事实与并发

- `t_command` 保存任务下发事实；报告按认证主机、任务成员、指令与执行契约核验。隔离、配置、登录、更新和取证使用各自稳定回执身份，业务写入和已处理记录在事务内提交。
- 模板包、逐主机预期、检查定义、来源摘要与历史结果保持快照；条款复核采用追加版本。旧结果、异常、未知范围不产生新的通过证据。
- 软件资产保留完整版本、来源、发行版、架构及采集完整性；漏洞命中、补丁复核和修复执行绑定同一安装身份。
- 安全来源、信任／冲突、撤销和游标分别持久保存；报表与证据有界保留，原始日志按权限、大小和期限控制。
- 集群 SQL 保存部署配置、节点、会话代次、可续期工作租约、自然时间槽及报告收件箱。消费串行与业务事务保护幂等；容量满和依赖故障拒绝接纳，不静默丢弃。

## 指标与查询

指标由生产指标服务写入 VictoriaMetrics；指标名、标签及聚合以[实现](../server/alinksec-service/src/main/java/com/alinksec/service/metrics)与协议为准。即时和区间查询显式使用 `latency_offset=1ms`，保留历史毫秒精度；近期样本可见性联调不能推出一秒大盘或长期规模已验收，见[查询修正](78-告警等级与采集查询修正.md)。

## 集群协调与存储拓扑

Redis 键使用 `alinksec:<deployment-id>:` 命名空间，分别管理 Agent 路由租约、登录窗口与固定配置。当前没有早期设计中的通用 Redis 待推命令队列或完整策略缓存协议。RabbitMQ 队列为 `alinksec.<deployment-id>.reports`，只发送 SQL 收件箱标识，不沿用早期多 exchange／多业务队列草案。

具体上限、重试、失败清单、配置摘要与共享 POSIX 存储要求见[集群指南](../deploy/cluster/README.md)。生产跨机高可用需要数据库、Redis、RabbitMQ、共享存储和入口各自消除单点。MinIO 不是必需组件；可选 S3 的迁回和失败保留见[安全库存储](15-安全库同步与存储.md)。

## 容量与验收

容量由结果保留、日志上限、物料大小、指标基数和实际负载决定，不沿用早期设计中的“2000 台已可承载”估算作为结论。两个数据库的迁移、事务、权限和 API 由完整 CI 覆盖；200 台真实主机／72 小时、目标系统和外部 HA 仍按[系统与规模验收](76-系统适配与规模验收.md)记录现场证据。
