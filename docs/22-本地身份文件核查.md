# Ubuntu 24.04 本地身份文件参考核查

独立候选 [identity/linux-baseline.json](../deploy/baseline/packages/identity/linux-baseline.json) 版本 1 增加七项原始规则。它限定 Ubuntu 24.04，观察 Agent 当前文件及用户命名空间内的 `/etc/passwd`、`/etc/shadow`、`/etc/group` 和 `/etc/gshadow`。不调用 Shell、getent 或 NSS 网络查询，不覆盖 LDAP、SSSD、其他身份源、PAM 生效链或其他命名空间。

| 原始编号 | 参考要求 | 边界 |
|---|---|---|
| 0009 | passwd/shadow 不含空口令字段 | 锁定标记不是空字段；检查字段不证明实际认证接受空口令或口令算法有效 |
| 0011 / 0013 | passwd/group 的权限位不超过 0644，UID/GID 均为 0 | 更严格模式也满足上限；特殊位参与比较 |
| 0012 / 0014 | shadow/gshadow 的权限位不超过 0640、UID 为 0、属组为本地 shadow GID | 用本地 group 解析 shadow，不硬编码 GID 或统一改为 root 组 |
| 0015 | UID 1 至 999 的 shell 字段为内置 nologin/false 路径 | root 和范围外账户不在本项；空 shell 按默认 /bin/sh 视作未满足 |
| 0016 | 本地 passwd 的 UID 0 名称列表恰好只有 root | 不证明外部身份源或全部提权授权安全 |

阈值是本项目参考策略，不是完整等保、CIS 或 STIG 认证。合法的 sync/shutdown 等其他受限命令也不在本候选的 shell 集合内，可能出现明确不合规；管理员应评估实际用途。本候选不证明账户完全锁定，也不提供自动 chmod/chown、口令修改或 shell 修复。

## 定义与不可变范围

`local_identity_file` 只允许四个固定路径，`operator=subset` 表示实际权限不能有上限之外的位。`owner=0` 使用数值 UID；`group=0` 使用数值 GID，`group=shadow` 从本地 group 读取。它要求路径本身为普通文件，拒绝符号链接；权限与 ACL 查询使用同一个文件描述符。即使模式为 0000，元数据检查也不要求读取内容；其他内容检查无法读取时仍返回 error。

```json
{"type":"local_identity_file","target":"/etc/shadow","perm":"0640","owner":"0","group":"shadow","operator":"subset","timeout_ms":5000}
```

扩展 POSIX 访问 ACL 存在，或无法确认其状态时返回 error，不把普通权限位当作完整有效访问权限。本项不解释路径目录链、MAC 或其他 ACL 机制。元数据查询依赖 Linux procfs 获取所持描述符的 ACL，不输出文件内容。

`local_accounts` 只允许 empty_password、uid0_accounts 和 system_shells 三个选项。UID 范围是 system_shells 的必填定义字段；变更范围影响候选摘要、审核差异、下发和任务快照，不能借用旧版本测试证据。

```json
{"type":"local_accounts","target":"/etc/passwd","option":"system_shells","operator":"eq","expected":"0","uid_min":1,"uid_max":999,"timeout_ms":5000}
```

允许的 shell 字段固定为 `/usr/sbin/nologin`、`/sbin/nologin`、`/bin/false`、`/usr/bin/false`。仅比较字段值，不执行该路径或证明其实际内容。指定范围没有账户时，会明确显示 checked=0；这不证明服务账户存在或认证安全。

## 错误与敏感字段

读取有 8 MiB、16384 行、单行 16 KiB 和检查超时上限，使用不阻塞特殊文件的打开方式。缺失、权限不足、链接、目录、FIFO、空文件、重复名称、字段数或 UID/GID 无效、shadow 孤立账户、passwd 的 x 缺少 shadow 记录，以及读取期间修改/替换均返回 error。不能把读取失败变成空集合通过。多个文件依次读取，没有全数据库的原子快照；这是一次有明确范围的文件观察。

空口令检查同时检查两文件的空字段，保留名称与数量。解析器不保留口令字段或哈希到结果结构；错误只标注文件、行号和固定原因，不回显原始行。scope、UID 范围、检查数量、违规名称以及文件权限/数值属主/属组进入 actual；页面同时保留 actual 与失败说明。

上线前按 [审核流程](18-基线模板审核与系统适配.md) 确认实际文件、shadow 组、命名空间与账户范围，更新服务端和 Agent，再导入、审核、测试和评估证据。需要调整 UID 范围时，复制 [identity-definitions.json](../deploy/baseline/identity-definitions.json)，修改包及来源版本，用现有 build-package.py 生成独立候选。本包不自动导入或发布，没有新增迁移。

## 来源与验证

文件格式及解释依据 Ubuntu 24.04 的 [passwd](https://manpages.ubuntu.com/manpages/noble/man5/passwd.5.html)、[shadow](https://manpages.ubuntu.com/manpages/noble/man5/shadow.5.html)、[group](https://manpages.ubuntu.com/manpages/noble/man5/group.5.html) 和 [ACL](https://manpages.ubuntu.com/manpages/noble/man5/acl.5.html) 手册。UID 和权限上限是本项目的显式参考选择。

原生测试绑定所提交的七项候选，在临时文件中验证更严格模式、特殊位、数值属主/属组、缺少 shadow 组及扩展 ACL；另读取当前机器七项只读观察，不要求 CI 主机全部合规。本机受 UID 映射和 ACL 写入能力限制，两个权限夹具交给 CI 的 root 测试执行，CI 要求它们真正通过。Ubuntu 24.04 两架构的原生范围由当前提交 CI 确认；本机 Ubuntu 26.04 的观察只验证引擎行为。REST/浏览器完整回报仍为明确标注的协议夹具。

旧 60 项现在有 8 项通用观测、2 项独立 SSH、7 项独立本地身份文件候选及 43 项尚未实现。通用包版本 4 自身仍列出未包含的 52 项，并指向独立候选；逐项记录见 [docs/20](20-旧基线模板内容审核.md)。
