## 实现和证据范围

REV-010 使用生产应用和真实 HTTP 区分 `/api/health` 存活与 `/api/ready` 业务就绪。SQLite 以外部事务持有真实写锁；PostgreSQL 停止并重新启动同一个独立数据库容器，保留私有数据目录和受限应用角色。并发发送 16 次就绪请求，核对非成功响应、响应耗时、单探测线程及最多一个排队任务，恢复后使用原管理员会话读取核心接口并核对 CA／JWT 材料。探测线程数通过测试类路径中的私有采样文件观测，不绕过停库时同样依赖数据库的鉴权过滤器。

完整维护恢复在 GitHub 的既有隔离部署场景执行。备份前创建明确标记的主机记录、登录取得真实会话；修改主机记录后执行恢复，独立 SQL 与生产主机 REST 均须读回原记录。归档保留恢复后的数据库探针值、文件内容及权限、CA／持久 JWT 摘要、原会话摘要和核心主机响应，不包含令牌、证书私钥或备份载荷。中断恢复、无效 CA 自动回滚和定时检查点恢复继续保留原断言。该证据证明维护恢复业务及身份材料，不将一次健康接口成功当作完整恢复。

REV-012 停止真实原生 Agent，等待未经缩短的生产离线阈值和扫描周期，通过实际告警 REST、数据库事件和本地测试 webhook 核对一次离线周期。再次扫描不增加事件／通知，原生 Agent 重连关闭旧事件；设置实际维护窗口并再次停止 Agent，跨多个扫描周期不增加离线事件或通知。首次尚未上线、禁用及删除夹具也必须没有离线事件。双副本场景在已有集群 CI 中执行，两个生产调度器始终运行，以共享数据库条件认领及通知去重证明并发边界；该场景 Agent 的测试心跳为 1s，单实例场景使用默认 10s，均不改变服务端 60s 阈值与 30s 扫描。当前实际契约见 [01 号 §5.2](01-总体架构与技术选型.md#52-心跳与在线判定)。本地 webhook 仅为隔离测试接收器。

REV-014 的近 30 日指标按明确毫秒起止范围聚合已确认自动响应事实，排除未来记录；七日趋势也改用同一事实来源，不再统计非空 `action_taken`。64 个明确标记的报告夹具各经生产分发路径发送两次，覆盖成功、仅告警、失败、排队、已发送及执行中；自动隔离分别经过 applying、未确认 active、确认 active 和重复确认，只有确认终态计一次。另有 31 日前、未来及平台午夜前后一毫秒边界，与独立 SQL 及逐日分组核对。报告夹具不描述为原生 Agent 实际执行了杀进程或隔离。

引擎接口分别读取文件事件监控、Windows 登录采集、ClamAV、YARA、SCAP 的自身能力契约、启用状态、接收时间及运行探测，覆盖全部适用主机，不受界面分页影响。混合就绪显示部分就绪，121 台中的最后一台缺报告仍须反映在覆盖率中；Linux 主机不计入 Windows 登录采集分母。缺失、失败、停用、不支持、过期、未来观测和主机离线分别核对原始状态表。原有进程／文件防篡改／登录策略／诱饵四项缺少自身独立就绪证据，继续明确显示未确认；主机总开关开启不构成就绪证明。这不关闭 BKL-010 所要求的完整期望／应用版本覆盖能力。

## 执行约束和失败记录

本机串行构建和验证。Java 容器上限 640 MiB、堆 256 MiB、一个 CPU；PostgreSQL 256 MiB；需要真实心跳时另用一个 192 MiB 原生 Agent。启动前检查内存与 swap，运行时保持可用内存至少 384 MiB、full PSI 不超过 10%。不启动本机完整 Compose；双副本和完整维护恢复使用独立 GitHub runner。验证结束删除自有容器及私有数据，保留原有用户服务和卷。

本机原生 Agent 编译因 `/tmp/go` 标准库不完整而未执行成功，不能记为构建通过；本地改用已验主线 CI 的 Linux amd64 Agent，核对完整 ZIP 摘要、二进制摘要及未修改的 Agent／协议源码树。本批 CI 仍从自身源码重建原生 Agent。

首轮测试入口在启动时失败。诊断日志最终定位到测试脚本的 Hikari 环境变量名：把连接超时的复合属性误写为嵌套属性，导致连接池提前启动后再次绑定失败；修正变量名后才完成应用启动和故障场景。首次完整场景的收尾断言又将 JVM 收到 SIGTERM 后的 143 退出误判为异常；保留原日志和失败，后续按显式发送的终止信号核对退出码、非 OOM 及零残留，不把异常应用退出一概接受为正常。最终接受结果须另绑定完整重跑与精确 CI。

独立复核另发现 121 台场景切换后，SCAP 夹具状态表保留上一场景的行；接口连接当前主机的结果正确，但原始夹具证据未隔离。夹具改为显式清理五张自身状态表后重新采集，原失败记录保留。浏览器首轮在页面定时器创建后才安装模拟时钟，无法推进原轮询；改为首次导航前安装后，网络失败、超时和恢复检查均通过。
