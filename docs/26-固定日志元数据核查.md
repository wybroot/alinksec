# Ubuntu24.04 固定日志路径元数据核查

独立候选 [log-metadata/linux-baseline.json](../deploy/baseline/packages/log-metadata/linux-baseline.json) 版本1覆盖旧0023、0027、0028的限定路径观察。适用于 Ubuntu24.04 Linux、POSIX元数据与procfs，并要求管理员确认传统 auditd/utmp 日志路径和本地utmp组。系统版本匹配只是选模条件；该包不解释实际auditd日志目标、有效logrotate配置或其他日志产品。两端需升级，旧Agent不支持新类型时返回执行异常。按[模板流程](18-基线模板审核与系统适配.md)审核、选主机测试后再发布，没有自动导入或自动修复。

| 固定目标 | 类型 | 允许的模式位上限 | 数值属主/属组 |
|---|---|---|---|
| /var/log/audit | 目录 | 0700 | UID 0 / GID 0 |
| /var/log/btmp | 普通文件 | 0660 | UID 0 / 本地group中utmp的GID |
| /var/log/wtmp | 普通文件 | 0664 | UID 0 / 本地group中utmp的GID |

`linux_log_metadata` 固定使用 `operator=subset`，定义不能改变路径、上限或属主/属组，也不能传命令、连接或其他产品字段。特殊模式位均不允许；0600、0400、0000等更严格模式可以满足位上限，但不表示日志可读、可写或服务可用。阈值是本项目的参考策略，不是完整上游认证要求。

Agent从根目录逐段使用O_PATH/O_NOFOLLOW打开固定目标，拒绝最终或父路径链接；不会打开设备、阻塞FIFO或读取日志内容。日志大小不影响仅元数据的检查，不使用身份文件的8MiB内容限制。普通文件需单硬链接。使用持有的描述符经procfs确认访问ACL，目录还需确认默认ACL；扩展ACL存在、ACL读取失败或文件系统不支持确认时保持error，不把模式位当成完整授权。utmp GID只从有界且稳定的本地group文件取得，没有NSS或数字回退。

检查结束重新从根打开路径，核对父目录身份、目标inode、模式、UID/GID、链接数和ctime；轮转、路径替换、权限变化或并发写入导致无法确认稳定快照时保持error并提示重试。超时同样是error。目标缺失、类型不符、链接、ACL或本地组缺失都表示无法完成此参考的取证；只有成功取得限定元数据后的明确模式或数值属主/属组偏差才是fail。证据只保留路径、类型、模式、数值ID、ACL状态及参考上限。

这是固定路径的当前元数据观察。父目录的授权、挂载授权、SELinux/AppArmor、日志内容/记录完整性、实际auditd `log_file`、日志写入/投递、轮转后的权限和服务运行状态仍需分别核查；不把传统路径存在当成产品实际使用该路径。审计目录策略要求root独占，在采用其他日志组的环境应制定另一个经过实现和验证的产品候选，而不是更改本类型的允许字段。

观察含义依据 [Ubuntu24 auditd.conf](https://manpages.ubuntu.com/manpages/noble/man5/auditd.conf.5.html)和 [utmp/wtmp手册](https://manpages.ubuntu.com/manpages/noble/man5/utmp.5.html)；auditd日志文件由配置决定，utmp机制并不覆盖所有程序。btmp/wtmp模式与组的参考出处是logrotate 3.21.0的 [btmp示例](https://github.com/logrotate/logrotate/blob/3.21.0/examples/btmp)和 [wtmp示例](https://github.com/logrotate/logrotate/blob/3.21.0/examples/wtmp)，示例不能证明某台Ubuntu主机的有效轮转策略。

```bash
python3 -B deploy/baseline/build-package.py \
  --definitions deploy/baseline/log-metadata-definitions.json --platform linux \
  --output-dir .tmp/log-metadata-candidate
```

验证覆盖缺失、最终/父目录链接、FIFO、类型错误、硬链接和定义越界。两架构原生Linux CI用私有临时目录验证更严格模式、超过上限、错误数值ID、缺少utmp组、访问/默认ACL及超过8MiB的日志文件，不修改真实日志。真实三个路径另作只读观测，不要求runner满足参考。SQLite/PostgreSQL REST及生产网页采用明确协议夹具验证定义快照、error阻止发布、完整pass/fail证据与桌面/手机展示，不能冒充实际日志写入验证。最终验收必须使用本批源码提交的CI。
