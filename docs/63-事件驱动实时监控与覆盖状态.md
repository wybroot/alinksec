# 事件驱动实时监控与覆盖状态

第9项分支 `event-driven-realtime-monitoring` 从已合并并验收的 `main` 提交 `1e4e1b2e3d210029a2499d35b8fac2e329832497` 创建。当前为实现及模块验证阶段；发布和实际部署另行安排。

## 行为与适用范围

Linux amd64/arm64 使用 inotify，Windows amd64 使用 ReadDirectoryChangesW，通过固定依赖 [fsnotify v1.10.1](https://github.com/fsnotify/fsnotify/releases/tag/v1.10.1) 接收创建、写入、权限变化、删除和重命名通知。递归注册由 Agent 管理，监听父目录以覆盖原子替换、根目录删除和重建。网络文件系统、虚拟文件系统及挂载视图不保证提供内核事件；周期补查保留，但不能恢复已经消失的内容。

文件事件分别触发现有病毒检查、关键文件完整性核验和已登记诱饵核验。病毒保护仍独立于勒索诱饵开关，继续使用本期哈希和内部规则检测、放行清单、摘要绑定隔离及离线事件队列。新引擎和特征库增量更新属于后续模块。默认病毒实时目录在启动时不存在也保留父目录锚点，后续创建时接入监听；主动快扫仍选择已有目录。启动、新增监听、策略启用、监听失效和事件溢出会请求补查；正常运行每60秒请求补查一次。

勒索速率判定保留完整策略窗口的快照比较，避免连续小批事件缩短窗口而稀释阈值。关键文件仍保留5秒安全复核，诱饵保留60秒健康复核。进程规则和登录采集沿用各自机制。文件通知没有可信进程身份，不作为杀进程证据；Windows ETW 写入者归因及无法核实时的安全响应边界继续适用。

## 资源与失败边界

| 项目 | 边界及处理 |
|---|---|
| 监听配置 | 最多128个去重后的根配置；最多1024个目录监听，包含父目录锚点 |
| 递归范围 | 最多5层子目录；隐藏子目录、符号链接、Windows目录联接不跟随；显式配置根可含隐藏名称 |
| 监听注册 | 每次至多20000个元数据条目、1秒；达到上限报告降级，30秒重试，目录拓扑变化最多每2秒触发复核 |
| 事件队列 | 按规范化路径合并，最多2048条；独立读事件协程不调用内容扫描。另有最多32条在执行批次，未处理路径保留到下一批 |
| 超限与失效 | 内核错误、队列溢出、监听注册失败、目录不可用及身份变化记录问题和累计中断；请求补查，不冒充完整覆盖 |
| 路径 | 事件路径最多4096字节；策略范围变化清空原生待处理队列、关闭旧范围补查句柄；重新启用病毒策略时即使监听目录未变也补查停用期间的文件；执行前重新检查当前病毒根及路径组件；最终读取、恢复和隔离继续使用原有身份复核 |
| 补查 | 深度优先，保留最多6个目录句柄和遍历位置；每次元数据步进最多512项，内容检查每批最多8文件、启动预算250毫秒；大目录按批推进，不在每批预算耗尽后从头开始 |
| 内容检查 | 实时单文件源读取最多2秒/20 MiB，沿用文件大小、规则范围和处置限制；实时读取接入共享资源治理的IO通道。单次检查可延长批次软预算 |
| 停止 | 取消时关闭原生监听、等待读线程退出并关闭补查目录句柄 |

原生通知可能在文件写入完成前到达。写入期间的身份或内容变化、读取失败、超限、白名单和检测库不可用继续按既有检测边界处理。单文件未覆盖原因写 Agent 日志；本模块未将“未检出”转换为“已确认干净”，也不提供所有文件的覆盖证明。

## 主机状态

心跳新增 `file_watch_contract=1` 和有界 `file_watch_status`，按认证通道绑定的主机保存；未知能力按不支持处理。SQLite/PostgreSQL 的 V022 保存最近覆盖状态，主机删除时级联清理。状态接口 `/api/protect/file-watch-status` 要求登录，各读取角色可查询，拒绝异常枚举、超长JSON、负数计数和超出队列/监听上限的声明。

实时防护页区分启动中、未启用、正在监听、补查中、覆盖降级、不支持、离线、过期和监听未推进。心跳或监听复核超过90秒、以及异常未来时间均不能显示正在监听；问题、累计丢弃、中断、当前队列及最近补查结束时间保留。API失败隐藏旧列表并允许重试。最近补查结束只表示遍历结束，不证明每个文件读取和检测成功。

## 验证

模块要求 Linux amd64/arm64 和原生 Windows 的真实文件事件到防护链路验证，包括创建、写入、原子替换、改名、新子树、根目录重建、缺失根后续创建、真实哈希检出后的隔离与回报、策略关闭和范围替换以及句柄清理。受控队列/内核错误和注册失败场景验证恢复请求；竞争检查覆盖采集、消费和策略更新。

SQLite/PostgreSQL 验证能力、降级、恢复、离线、时效、坏报文及删除级联；生产构建页面使用数据库响应验证桌面、390像素手机视口、失败重试和旧Agent状态。原始证据随CI保存，最终验收链接在检查通过后补齐。本机内存压力超过本地验证约束，重编译和浏览器检查使用独立CI runner。
