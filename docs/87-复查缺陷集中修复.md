## 传输与资产契约

新 Agent 心跳声明 `report_receipt_contract=1`。服务端以不带指令 ID 的 `CmdReportReceipt` 应答能力，并在同步事务或集群 SQL 收件箱持久接收后回执对应报告 ID。集群回执表示平台已持久接收，业务执行仍由可观察的收件箱状态跟踪。新 Agent 不在未协商的连接上排空业务队列；旧服务端未声明支持时保留积压并报明确兼容错误，须先升级服务端。旧 Agent 不具备通用持久回执或采集序号，不能外推新 Agent 的可靠性结论。

JSONL 队列保留既有 500 MiB／24 小时预算，单记录 4 MiB；回执重试间隔至少 5 秒，心跳及中间 ACK 不等待业务队列，终态任务 ACK 先落盘并按 FIFO 跟随此前业务结果发送。容量或磁盘失败明确记录错误，不能据本次修复承诺无限离线保留。服务端普通报告去重保留 7 天，长于该队列保留范围；具体任务的终态与已存在的专项结果／取证回执边界保持原有约束，迟到结果不重新开启已结束任务。

采集序号和初始化标记保存在 Agent 工作目录 `asset-sequence.json`、`asset-sequence.initialized.json`，必须随身份材料保留；初始化后计数文件丢失／损坏时拒绝采集，不能静默从零开始。每个资产类别独立推进序号，时间只用于展示。旧的零序号快照明确标为覆盖未知，一旦某类别收到正序号，旧式快照不能覆盖该类别。

本批增加 V037（SQLite 和 PostgreSQL），共 37 个迁移、106 张业务及辅助表。新增会话、逐类采集状态、磁盘资产和成功动作事实表；迁移脚本、SQLite 运行时资源和两库检查保持一致。

## 账号操作与恢复

自助改密要求原密码，新密码至少 12 字符且不超过 72 个 UTF-8 字节；成功后该用户所有旧会话失效。管理员创建账号时建议先选 viewer，再按职责授予 operator 或 admin。用户编辑时密码留空表示保留原密码，明确填写才是重置；版本冲突应刷新后重新核对，不能盲目重试覆盖。账号相关审计记录操作元数据，不保存密码请求正文。

管理员全部失联时需由持有数据库维护权限的负责人执行离线恢复，不提供免鉴权网页后门。以下流程仅适用于已应用 V037 的当前源码数据库：

1. 停止应用写入，按维护手册备份并保留原会话／审计事实。确认具体部署、数据库和待恢复账号，避免在其他数据库操作。
2. 在受控终端使用 `htpasswd -nBC 12 recovery` 交互生成临时密码的 BCrypt 哈希；工具来自系统的 Apache 工具包。不要将明文密码写到命令参数、脚本或会话记录；输出中只取冒号后的 BCrypt 哈希。
3. 使用数据库维护账号在一个事务中，将指定用户名的 `password_hash` 更新为该哈希、`status` 设为 1、`role_id` 设为现有 admin 角色并令 `auth_version=auth_version+1`；删除该用户的 `t_user_session`。必须核对只更新预定的一行，否则回滚。
4. 启动应用并检查 `/api/ready`，用临时密码登录后自助再次改密，核对审计和旧会话失效。记录恢复负责人、时间和范围，不记录明文密码。

已有管理员可直接通过用户管理重置其他账号，仍须遵循职责和审计要求。恢复操作没有在本次开发机上的用户业务数据库执行。

## 继续复核：中断写入后的队列尾部

## 继续复核：账号操作中的审计失败隔离
