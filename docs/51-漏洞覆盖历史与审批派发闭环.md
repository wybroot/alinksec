# 漏洞覆盖、历史与审批派发闭环

本批在 `vulnerability-applicability` 同一模块内成组完成：覆盖与缺失信息、原始历史与重新发现、实际账号审批、维护窗口、持久排队、离线重放和取消/失败处理。相关功能统一验收；不拆分到其他模块。

## 覆盖与历史

“比对覆盖”按主机展示采集失败、历史完整性未知、未比对、资产变化、规则变化、完整空清单、覆盖缺失和已按现有声明比对。包级记录保留完整版本、来源、包架构、受影响/不受影响/未知 CVE 数和至多 20 条来源摘要示例。“没有告警”“无适用规则”“空清单”均不证明安全。当前整条 CVE 的选择规则仍为人工来源优先、其他按来源标识排序，不合并其他来源的发行版范围；来源治理保持后续模块。

原生身份、完整版本、二进制范围或原始入库来源不足时保持未知。相同包/CVE 的受影响与明确排除声明、修复目标冲突或不可评估证据会阻断自动修复。覆盖数据绑定软件清单与规则修订号；库或资产变化后，旧计数明确不代表当前覆盖。详情展示记录时的原始系统身份，避免使用当前身份解释旧记录。

`V013` 增加覆盖、包级评估和规则修订状态；不补写 V010 之前的来源、用户或声明。旧 findings、任务和修复引用均保留。最近不命中的未处置记录进入状态 4，在“处置历史”查询；已忽略、已修复的历史证据不会删除。修复结果仅证明该次安装复核成功：未重新采集时，原清单不会反复新增；后续完整采集仍出现受影响版本时，新增 finding，原 finding 和修复记录保持可追溯。更换版本、架构、系统身份或规则摘要会重新判断。

## 实际账号与窗口

创建人来自已验证登录身份。审批人从已启用的 admin/operator 账号中选择并绑定用户 ID；只有指定账号可以批准。请求体中的 `operator`、显示姓名或伪造 UID 不决定实际审批身份。账号禁用或失去角色时不能继续派发/重放。当前允许创建人明确指定自己审批，不要求双人审批。

填写维护窗口时必须同时提供起止时间，结束晚于开始且尚未过期；不填写时审批后立即排队。API 接受带偏移 ISO 时间；无偏移本地时间按 Asia/Shanghai 解析。页面采用浏览器本地时间并发送带时区的 ISO 时间。

审批、窗口领取、固定对象复核、任务状态与指令入库位于同一事务。并发批准或调度最多产生一条对应主机的持久指令；事务提交前不向 Agent 暴露指令，回滚时不留下批准或队列。一次最多 500 个 finding；同一主机同一软件包已有活动任务时禁止重复排队，同一批次也只选择一个当前包目标，安装后重新比对其他 CVE。多个安装版本或架构仍需人工处理。

## 发送、重放与安装截止

每次发送和重推都重新核对：任务仍处于执行中、指定审批与实际账号一致、当前账号有效、维护窗口和 30 分钟任务期限、当前软件身份、原 finding 与规则摘要、具体不可替换补丁、未撤销的复核和实际字节 SHA-256。终态修复项不再次安装。保存的指令不含下载凭证；实际发送时签发绑定任务、主机、finding、具体复核和文件的短期凭证。取消、复核撤销、任务终结或规则变化后，原凭证不能继续下载。

Agent 执行契约升级为 **2**：包含身份、实际包头、完整版本复核和安装开始截止时间。契约 1、未知能力和 Windows 注册表清单仍可展示，但不允许自动包安装。新版 Agent 需重新采集后才取得契约 2。下载也受截止时间限制，安装开始前再次检查；截止后不开始安装。已经开始的安装沿用既有有界执行和结果上报，不强制中断包管理器、不承诺自动回滚，也不自动重启。

指令从真实发送时间计 ACK 超时，按已有重试次数限制处理。ACK 只能推进已经发送的命令，不能由 PENDING 变成已执行，也不能倒退状态；DONE ACK 不替代逐项 verified 结果。包修复结果必须属于发送过的绑定指令，未发送、外部主机、重复或终态结果均不回写成功。FAILED ACK、重试耗尽、窗口到期、超过派发后 30 分钟或重放校验失败会留下明确失败原因并结束待处理记录。

只有创建人或指定审批人可取消尚未送出的任务，取消原因留审计，队列和凭证同时失效。发送与取消通过任务行锁排序；任一指令已经送出时拒绝取消，提示查看实际结果并人工处理。

## 验证入口

- `VulnerabilityWorkflowIntegrationTest`：真实 SQLite/PostgreSQL、真实 DEB 包、事务回滚、并发审批/调度/重放、覆盖与历史、账号/窗口/取消、复核与字节变化、ACK/结果/超时边界。
- `AgentChannelSecurityIntegrationTest`：真实 mTLS/gRPC、所有权、重复与未复核结果、持久任务与契约 2。
- Agent fixer/collector：截止时间缺失/过期/下载后到期、原生身份、包头与安装后完整版本复核。
- 实际 Agent 工作流：两台 Agent 串行安装；实际降级后重新采集产生新发现，原修复引用保留。
- 生产页面浏览器：账号选择、实际审批与离线取消、覆盖缺失/过期/历史依据、处置历史及桌面/手机显示。
- V013 与全量迁移、备份恢复、应用角色权限；Linux amd64/arm64 和原生 Windows CI。独立 runner 并行，本机及单 runner 内共享状态检查串行。

当前验收结果以对应提交的 CI 与产物记录为准，运行中不标记模块完成。此前执行契约 1 的批次记录保留其当时边界，当前能力要求以本文契约 2 为准。

当前来源撤销与退役边界见[来源治理](52-安全来源治理与有界NVD同步.md)：已退役来源退出选择，优先公告撤销保留优先位置但不参与比对，原始声明与历史证据保留。
