# 扫描任务管理、失败复扫与检出处置

2026-10-27，未发布 develop 的管理入口补强。版本基线仍为 v0.0.4，历史发布与验收
记录保持原范围。当前本机预览沿用已配置的公开库和原生 Linux YARA Agent。

## 操作流程

病毒查杀页的 YARA 主机卡片提供“扫描此主机”和“查看主机任务”。扫描入口预选当前
主机和 YARA，引擎状态重新读取，只有就绪主机可选；提交和实际派发时服务端再次检查
执行契约、操作者权限及引擎版本。状态变化会拒绝任务，填写内容保留供修正后重试。

扫描对话框可填写任务名、主机、模式、绝对路径及每台主机预算。页面初始使用
300 秒／1,000 文件／256 MiB 的小范围排查预算，可切换标准上限或自行调整。
API 未传预算时仍沿用 7,200 秒／100,000 文件／20 GiB；每项必须为正整数且不超过
上述硬上限。读取预算按源字节累计，不能当作磁盘总量或全部文件检查保证。

主动扫描检出后会自动隔离；提交前必须明确确认该行为。周期检测的仅告警策略独立
设置，不改变主动扫描动作。任务提交后按预算执行，界面的“取消”只关闭尚未提交的
表单。排队时间计入执行期限，派发时扣除已等待时间；超时清理另留五分钟回报宽限。

创建成功后立即打开返回任务编号的逐主机回执，待回报期间每五秒刷新。回执包含主机、
状态、固定版本、扫描／跳过／失败计数、读取字节、预算耗尽、覆盖声明和问题路径。
请求失败明确提示，可手动刷新；原任务没有回报时不会把提交成功显示成扫描完成。

## 失败复扫与追踪

部分覆盖、失败、超时主机可选择“复核范围并复扫”。页面优先填入证据中的有效绝对
路径；没有可用问题路径时使用原范围，旧任务缺范围时需操作者补填。目录不可用时先
核对路径和挂载；读取失败时核对权限及文件变更；预算不足时缩小范围或调整预算。
超大文件和路径排除规则不因复扫而放宽。

复扫创建新任务，使用当前就绪引擎的版本，保存 `scope.retry_of` 和当前操作者。
原回执、摘要和完成状态保留。服务端验证原任务存在、引擎一致、主机属于原任务且
未完整完成；同一原任务、同一主机存在待回报复扫时拒绝重复创建。提交前仍需重新
确认范围、预算和自动隔离行为，不能把旧失败证据直接当作新的处置授权。

任务表显示任务编号、操作者和复扫来源，支持主机编号／引擎／状态筛选及每页 20 条
分页；检出表支持主机编号／处置状态筛选和分页。admin／operator 可创建和复扫，
viewer 只读。现有检出处置继续以逐文件回执为准，隔离、删除、恢复及加白保留历史。

## 从检出进入处置（2026-10-27 后续改进）

任务列表的“查看本次检出”只显示该任务的记录；逐主机证据里的入口同时按任务和主机
筛选。任务筛选可清除，并可继续按处置状态筛选和翻页。总数与列表使用相同查询条件，
相同发现时间按编号稳定排序。任务关联不把周期检测或其他任务的检出算入本次结果。

单条或批量隔离、删除、恢复和加白均先显示主机、路径、SHA256 及已有隔离编号。
操作者核对并勾选确认后才能提交，每批最多 32 项。提交期间禁止重复点击和关闭表单。
提交错误会保留对象与错误提示，并锁定本次表单的再次提交；关闭、刷新检出并查看历史，
确认当前状态后才能重新操作。服务端仍在事务内验证当前权限、记录、执行契约和状态，
Agent 仍核对文件身份；浏览器核对不代替执行边界。

每次成功提交返回逐文件 `actionIds`，立即打开“本次处置回执”。汇总分别显示已确认
成功、待确认、失败、超时、策略已保存和未取得回执，待确认时每五秒刷新。读取失败
保留已取得的结果并允许刷新；缺失或未知状态不会算成功。只查询原提交的编号，后续
恢复、隔离或加白不会替换这批回执，可从结果打开该文件的完整历史。

隔离会移走原文件；删除不可通过平台恢复；恢复须核对误报和风险，原路径占用仍会
失败。恢复后的记录可重新隔离或删除。超时可能已有本机操作，平台不会自动重试。
加白跨主机、跨路径按 SHA256 放行，保存策略不代表 Agent 已收到，也不自动恢复文件，
已有检出、原状态和回执保留。admin／operator 可操作，viewer 保留查询和历史入口。

新增读取接口 `GET /api/virus/findings/actions/receipts?ids=<UUID,...>` 限制 1 至 32 个
唯一合法编号；`GET /api/virus/findings` 增加可选 `taskId`，原查询参数保持兼容。
没有数据库迁移、Agent 协议或运行配置变更。

本轮证据独立保存在 `.tmp/virus-disposition/`：38 项 Java 检查、27 项前端单测、完整
前端构建及 11 组页面浏览器检查通过。浏览器使用真实 SQLite 事务生成的处置回执与
已捕获引擎状态，拦截全部接口并模拟网络错误和提交，不写真实主机。本轮先停止后端，
按原保护线完成手机确认换行、只读角色、扫描创建、关联复扫、分页、部分成功、恢复、
加白及错误恢复检查；首轮手机／viewer 的待验项现已补齐，原失败记录保留。
浏览器针对当前页面预览，完整前端成品另行构建，不混称为完整成品浏览器验收。

本机预览现为 `alinksec-web-develop:virus-disposition-20261027`，实际 HTTPS 返回的
50 个成品文件与完整构建摘要一致。后端只替换已验证的查询、处置及 REST 覆盖类，
保留其他覆盖类原字节；Agent、来源配置、原容器资源限额及其他服务保留。
