# 原始日志集中检索

第 24 项在已合并的第 22／23 项之上完成采集、存储、检索、详情与导出。控制台入口为“原始日志”。原始日志可能包含账号、地址和其他敏感信息，全部接口检查登录声明和数据库中当前有效的管理员身份；查询及下载禁止缓存。

## 采集适用范围

| 系统 | 实际来源 | 时间含义与范围 |
|---|---|---|
| Linux amd64／arm64 | 固定普通文件 `/var/log/secure`、`/var/log/auth.log`，分别标记为 `secure`、`auth.log` | Agent 首次观察该行的时间；原文中的时间字符串不推断为标准事件时间 |
| Windows amd64 | 原生 `EvtQuery`／`EvtRender` 读取 Security 的 Microsoft-Windows-Security-Auditing 4624／4625 XML | 原生 `TimeCreated`；与登录防护共享读取器和游标，防护规则关闭时仍可采集 |

Windows 不主动开启系统审计，首次启动从当前尾部建立游标，不导入安装前历史；未启用审计、权限不足、原生日志缺口或解析失败可从现有 Windows 登录覆盖状态查看。此功能不覆盖全部 Security 事件、System／Application 通道、journald 或任意应用文件。需要额外来源时应扩展采集契约和验收。

Linux 每轮每文件最多读取约 256 KiB、100 行，完整行之外的片段有界持久化，重启后继续组装。dev／inode 与独立代次识别文件替换和已观察到的缩短；替换、轮转可能丢失尚未读取的旧文件尾部，复制截断在两次轮询之间完成时也可能无法观测，均不承诺完整无缺。

原文不删除空格、制表符或空行；行结束符作为字段记录。Linux 每行保留最多 16 KiB 原始字节前缀，超长、无效 UTF-8 替换及 NUL 转义均明确标记，转换后内容另有 64 KiB 上限。Windows 单条 XML 上限 64 KiB，不截取不完整 XML；超限会使读取状态失败，等待源记录处理或人工干预。`record_kind=collection_status` 是采集状态说明，页面单独标记，不能作为原始日志引用。无效或超限 Linux 游标文件会停止原文重采并报告 `cursor_invalid`，须修复状态后重启 Agent。

## 持久化和容量

日志在推进采集游标之前写入现有本地补传队列；写入失败时保留游标重试。传输被阻塞而队列无法整理时，原始日志达到容量会拒绝接纳，避免继续增长。队列通常按 24 小时／500 MiB 环形保留，不能提供断电或无限期离线保证。

现有协议在流 `Send` 成功后移除补传项，没有普通日志的服务端持久接收 ACK。因此流发送成功后服务端中断、拒绝批次或达到容量，仍可能出现日志缺口。集群模式的持久恢复从 SQL 收件箱接纳开始，队列失败可从集群管理面板查看与处理。不能将这些边界解释为零丢失采集。

服务端整批校验，单批最多 100 行／1 MiB protobuf、单条原文最多 64 KiB、字段最多 32 项／8 KiB且单值最多 4 KiB。超量、身份冲突或容量失败会回滚整批，保留已接纳的原文，不静默截断。新 Agent 的源事件键和旧 Agent 的报告编号／行号用于重放去重；同一事件的不同原文会被拒绝。去重身份随原文保留，过期清理后不承诺永久去重。

统一 SQL 容量锁和事务计数限制 20 万行／1 GiB 计费内容量。计费量包含原文、字段和固定行开销；旧记录按保守字符估算，不等于数据库文件或索引的物理大小。到达容量时拒绝新批次；应监控容量、采集覆盖及集群失败队列并及时处理。目标保留 30 天，清理每分钟每副本最多 500 条、每次独立事务，积压时物理清理会延后。备份与恢复仍覆盖所在数据库。

V035 保留已有内容与结构化字段，并新增原文、事件键、SHA256、时间语义、计费字节和容量状态。旧记录缺少原文摘要且可能已经截断，页面明确显示“旧记录 · 完整性未知”，不会补造完整性证明。

## 检索与导出

按浏览器本地时间填写与展示入库时间范围，开始包含、结束不包含，单次最多 31 天；Agent 时间另列，不能替代入库顺序。可按完整主机编号和来源筛选，原文关键词为区分大小写的字面子串，`%`、`_`、引号不作为通配符或 SQL。

检索固定首次请求的最大入库编号，每次最多扫描 5000 个编号、返回 50 条。没有匹配也可能仍有较早记录待扫描，页面显示“继续扫描”；仅扫描完成才显示范围内没有匹配，不虚构全局总数。筛选改变或请求失败后，旧结果标记过期并禁用翻页／导出，须重新检索。编号排序来自平台接纳顺序，不将相同时间、Agent 上报时间或外部直接写库等同于该顺序。

详情安全显示原文、结构化字段、时间语义与摘要（对实际保留内容计算），摘要不匹配时拒绝读取和导出。导出本页最多 50 条选定日志为 NDJSON 或 CSV，最大 8 MiB；CSV 转义引号、换行和公式前缀，下载带附件、禁止缓存、沙箱和 SHA256 头，浏览器在保存前核对摘要。成功导出必须在同一事务留下操作审计，审计不保存检索关键词或原文。日志被清理或读取失败时，不继续展示此前的详情。

- `agent/internal/windowslogin/raw*_test.go`：同一游标的原文接纳与失败重试；Windows 隔离 runner 实际失败 `LogonUserW` 产生 4625，由同一 Engine 读取原生 XML并核对重启游标。
- `agent/internal/comm/raw_log_test.go`：在线状态仍先落实际补传文件，重新打开保持原文；不可用或满且被领取的队列拒绝日志。
- `LogSearchIntegrationTest`：SQLite 与受限 PostgreSQL 的真实事务、原文／去重／容量／时间边界／字面检索／快照游标／清理／角色／安全导出，并捕获实际 REST、详情及下载文档。
- `web/test/log-search-browser.mjs`：生产页面使用真实数据库响应，检查桌面与移动布局、原文文本安全、下载摘要、过期详情、筛选过期、真实翻页、空结果、失败重试和只读角色隔离。
