# 基线模板上游自动更新

第 15 项在现有 Linux／Windows 基线 JSON 和离线 SCAP ZIP 之上增加受信发布源。服务器定时验证签名索引，发现并保存候选版本。候选仍须经管理员审核、适用主机测试和发布；更新源不会自动替换已发布模板、执行修复或改变历史任务。等保 2.0 的规则范围沿用[第 13 项](67-等保2.0主机合规规则包.md)，SCAP 原生解析和执行范围沿用[第 14 项](68-XCCDF与OVAL原生解释.md)。

## 配置来源

复制 [配置示例](../deploy/baseline-upstreams.example.yml)，设置来源编号、名称、HTTPS 索引地址、Ed25519 公钥及允许的包类型／编号。通过 `ALINKSEC_BASELINE_UPSTREAM_CONFIG` 指定配置文件，默认读取数据卷中的 `baseline-upstreams.yml`。示例公钥是占位符，必须先替换；无效配置会阻止启动。签名私钥保留在发布端。

默认不配置任何远端源。每个来源最多允许 64 个精确范围，例如 `baseline:ALINKSEC-MLPS2-L2-LINUX` 或 `scap:ORG-BENCHMARK`；不同来源不能声明相同范围。最多 16 个来源。地址和公钥只能在服务器配置中修改，网页管理员可调整启停和 1 小时至 7 天的轮询间隔，并手动同步、重试失败版本。operator、viewer 只读。计划使用修订号防止覆盖其他管理员的变更，记录操作人和说明。

HTTPS 地址不得含凭据、查询参数或片段，原件必须与索引同源。不会跟随重定向。明文 HTTP 仅接受字面回环地址，供受控测试使用。配置的源属于部署管理员的网络访问允许列表；系统不提供任意网址抓取接口。改变地址、公钥或包范围后，自动更新暂停，管理员须检查新配置并显式启用；接受过的最高序号仍保留。

## 构建静态发布目录

发布端需要 Python 3 和支持 Ed25519 的 OpenSSL 3。以下命令只生成本地文件：

```sh
openssl genpkey -algorithm Ed25519 -out /secure/baseline-signing.pem
python3 deploy/baseline/publish-upstream.py \
  --source-id internal-compliance --sequence 1 \
  --base-url https://baseline.example.invalid/ \
  --private-key /secure/baseline-signing.pem --output ./baseline-site \
  --release deploy/baseline/packages/compliance/level2/linux-baseline.json \
  --release deploy/baseline/packages/compliance/level2/windows-baseline.json
```

工具输出 `index.json` 和按原始 SHA256 命名的 `artifacts/`，并打印供服务器配置的 DER 公钥 Base64 和公钥指纹。私钥必须位于输出目录之外。发布新索引时递增 `--sequence`；输出目录已有索引时默认验证并沿用它，也可用 `--previous` 指定已发布索引。未再次列出的历史条目保留。用 `--withdraw baseline/CODE/VERSION` 或 `--withdraw scap/CODE/VERSION` 撤回现有条目；撤回终止该版本，后续更正需新版本。重新签名续期同样需要新序号。默认有效期 7 天，可设 1 至 30 天。

由运维将整个目录部署到配置的 HTTPS 地址，先上传原件再原子替换索引。此模块不替用户部署发布站点，不内置厂商账户、官方签名或公共规则下载地址。发布工具检查包身份、大小和签名；服务端仍完整验证原有格式、编译的检查白名单及 SCAP 原生解析边界。

## 签名格式与版本约束

外层 JSON 仅允许 `formatVersion: 1`、`payload` 和 `signature`。后两项是标准 Base64；签名是对解码后 UTF-8 载荷**原始字节**进行的 Ed25519 签名，不对重新序列化的 JSON 验签。公钥为 X.509 SubjectPublicKeyInfo DER。载荷例：

```json
{
  "sourceId": "internal-compliance",
  "sequence": 1,
  "generatedAt": "2026-10-23T00:00:00Z",
  "expiresAt": "2026-10-30T00:00:00Z",
  "releases": [{
    "kind": "baseline",
    "code": "ALINKSEC-MLPS2-L2-LINUX",
    "version": "1.0",
    "osType": 1,
    "url": "https://baseline.example.invalid/artifacts/ORIGINAL_SHA256.json",
    "sha256": "64位小写十六进制原件摘要",
    "size": 12345,
    "status": "active"
  }]
}
```

实际摘要、大小、版本和地址由工具计算。`kind` 为 `baseline` 或 `scap`，`osType` 为 Linux `1` 或 Windows `2`，状态为 `active` 或 `withdrawn`。身份字段使用 ASCII 字母、数字、点、下划线、冒号和横线，首字符为字母或数字；原有包格式可能施加更严格的长度限制。接收端拒绝重复 JSON 字段、未知字段、无效 UTF-8、超深结构、重复版本和超界数值。

索引最多 64 个条目，载荷最多 256 KiB，外层最多 384 KiB；每个原件最多 2 MiB。发布时间最多超前 5 分钟，有效期不超过 30 天。下载后核对**原始字节**的大小、SHA256 和包内类型／编号／版本／系统，再进入原有格式校验；标准 SCAP 包还须经过有资源和时间限制的 OpenSCAP 解析。

序号必须为正 64 位整数。低于已接受序号的索引被拒绝；同序号不同载荷被拒绝，同序号同载荷幂等。配置变更后需要新序号。同一来源、类型、编号和版本的原件摘要、大小、系统及地址不可变；已撤回版本不能恢复。版本名称不做语义排序：更高索引序号可以介绍历史版本，但它只产生候选，发布仍由已有审核与测试门槛控制。

ETag／Last-Modified 仅在成功验签并接受索引后保存。仅对尚未过期且配置一致的索引发送条件请求，`304` 不延长签名有效期。失败原件可在有效的 `304` 响应之后继续尝试；过期、未请求的 `304` 和无效新索引都不能绕过验证。

## 导入、撤回和故障处理

调度器每分钟检查到期来源；每个进程只有一个工作线程，数据库全局租约阻止多个进程同时拉取。一次最多处理两个原件，余下待导入项下一分钟继续。每次 HTTP 请求在 30 秒内结束，限量订阅器在超过上限前取消响应；整个工作轮次 180 秒，租约 240 秒。下载和原生解析在数据库写事务之外，保存前复核租约、来源修订号、启用状态、签名有效期及版本状态。停用或修改计划期间下载完成的旧轮次不能提交候选。

失败只保留固定错误码，不把远端响应正文、URL 凭据或原始主机值写入错误信息。每个原件最多自动尝试 3 次；管理员可显式重试。重启后的过期租约可被接管，遗留记录标为中断。来源网络错误按配置的轮询间隔继续，手动同步可提前重试。原件失败不推进候选状态、不创建半份模板，也不影响当前发布规则。

上游撤回、签名索引过期、配置移除或信任配置变化会阻止已关联候选继续批准、测试或发布。暂停轮询本身不撤销仍有效的签名。上游状态在审核页和来源页可见；已发布版本由管理员按现有流程撤回，已有任务的内容、摘要和执行证据保持原样，不依赖更新站点实时在线。

下载原件摘要与基线规范化内容摘要、SCAP 标准解析后下发摘要分别保存。来源记录关联首次发现、实际导入和当前状态的签名凭据；密钥轮换不改写首次发现或导入时的凭据。已在审核／发布流程中的手工版本不能被后台重新绑定来源，同一候选也不能绑定到两个来源条目。SCAP 和基线导入中的操作人 `0` 表示系统导入，审核操作仍须真实管理员身份。

全局原件容量默认 64 MiB，可配置 2 至 256 MiB；这里计原始文件字节，数据库 Base64、现有包和派生内容会额外占空间。最多保存 256 个版本记录，达到边界时明确失败，保留已有证据。所有版本引用的签名索引保留，另保留每源最近 20 份未引用索引；来源页展示最近 100 次同步和计划操作。扩容或归档须先导出原件及签名凭据，并按运维流程处理；系统不自动删除已采用版本或历史任务。

## 接口与验证

`/api/baseline/upstreams` 提供来源列表；`/{id}` 提供版本、签名元数据与更新记录；`PUT /{id}/schedule`、`POST /{id}/sync`、`POST /{id}/releases/{release}/retry` 为管理员操作。`GET /{id}/receipts/{receipt}` 和 `GET /{id}/releases/{release}/artifact` 下载原始凭据／原件，返回 `no-store`、`nosniff` 和下载 SHA256；浏览器验证下载摘要。

V028 在 SQLite／PostgreSQL 增加 5 张独立来源表。专用 CI 运行真实 Ed25519／OpenSSL、HTTP 发布源、原生 OpenSCAP 导入，以及使用生产前端构建的浏览器检查；全量 CI 另运行 PostgreSQL 应用角色、迁移和旧模块回归。测试覆盖幂等、回放、同版本篡改、撤回、过期、`304`、下载损坏／重定向／超时、停用竞态、跨进程租约、密钥轮换、配额、JWT 权限、修订冲突和原件导出。页面验证使用集成测试捕获的实际数据库／REST 生命周期响应。公共厂商来源、生产发布站点及全系统现场组合的实测属于后续外部联调和系统验收范围。
