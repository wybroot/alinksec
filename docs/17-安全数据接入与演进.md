# 安全数据接入与演进

> 版本基线：v0.0.4。已按本版核对「安全数据接入与演进」的操作、实现引用与适用边界；历史日期及验证结果仍只对应其原始提交。版本差异见[发布说明](releases/v0.0.4.md)，全部资料见[文档索引](README.md)。

目标是让外部数据经过来源管理、格式转换和适用性判断，进入平台已有的病毒扫描、漏洞比对、基线核查与修复流程。优先使用正式 API 和可校验的数据文件，按照来源分别维护版本和更新状态。人工导入继续承担初始库、离线更新和本地修订。

## 1. 已实现：同步计划与原生来源

在“安全库管理”里，管理员可以为已配置的来源启用/暂停同步、修改间隔、立即执行或恢复部署默认值。启停和间隔保存在数据库，重启后保留；配置文件仍负责来源类型、地址、凭据、MISP 审核标签、NVD 产品映射和存储设置。新增来源或修改这些连接设置需要重启服务。

界面显示当前来源条目数、最近成功检查、下一次检查和连续失败情况，支持查看每个来源最近 50 次执行记录。手动同步和定时任务分别记录开始/结束时间、结果及保留的有效条目数。计划修改和手动操作沿用平台操作审计；只读角色可以查看状态和执行记录。

MISP 增加原生 `misp` 类型，服务端使用只读 Auth Key 请求完整的 SHA256 文本导出。请求范围固定为已发布、可用于检测、未删除、通过 warninglist 筛选且具有指定审核标签的情报；校验和合并发布完成后沿用现有 Agent 特征更新通道。认证与配置见 [对接指南](16-开源安全平台对接指南.md#30-原生同步推荐)。MISP 的接口依据 [官方 restSearch 规范](https://www.misp-project.org/openapi/#tag/Attributes/operation/restSearchAttributes)。

现有 NVD、MalwareBazaar 和规范文件源使用同一套调度、失败保留与执行记录机制。MISP 原生来源和桥接来源使用不同 ID；同一数据集合只选一种接入方式，避免撤销时被重复来源继续保留。

## 2. 调度与恢复规则

| 项目 | 当前行为 |
|---|---|
| 调度频率 | 每分钟检查一次，优先执行最早到期的来源 |
| 并发 | 单个服务实例串行处理远端同步，避免多源同时下载和发布 |
| 可配置间隔 | NVD 两小时至七天；其他来源五分钟至七天 |
| 推荐初始值 | MISP、MalwareBazaar 三十分钟；NVD 两小时；规范文件按上游实际发布频率 |
| 连续失败 | 在正常间隔基础上指数延后；上限不超过一天或原始间隔中的较大值 |
| 手动同步 | 已启用来源可提前重试；有任务执行时返回未接受 |
| 暂停 | 停止新任务，已开始任务继续；已入库内容保留 |
| 重启 | 恢复已保存计划，把未结束的执行记录标为中断，按计划重试 |
| 恢复部署配置 | 删除该来源的控制台计划覆盖值，重新采用 YAML 中的启停与间隔 |
| 执行记录 | 每源保留最近 50 条，不保存 URL、密钥、响应正文 |

“最近成功检查”表示平台成功读取了该来源，不代表上游一定新增了情报。桥接来源还需监控桥接任务的最后成功导出时间。MalwareBazaar 的 60 分钟覆盖窗口可能因停机或失败后延迟而出现断档，需用基础库或全量来源补齐。

单实例串行调度；PostgreSQL 集群通过可续期 SQL 工作租约、发布时所有权核对及自然时间槽避免多副本重复执行，见[集群指南](../deploy/cluster/README.md)。基线模板、补丁文件、远端来源的清空操作不由启停计划代替。

新增表通过 `V003__library_schedules.sql` 迁移：SQLite 自动应用，PostgreSQL 沿用已有迁移脚本；应用角色仅需 DML 权限。平台备份需要包含计划、来源状态和执行记录表。

## 3. 与现有业务的对应关系

| 数据类别 | 接入与存储 | 平台使用方式 | 当前边界 |
|---|---|---|---|
| 病毒文件特征 | MISP、MalwareBazaar、SHA256/ZIP 来源与人工包 | 合并发布 → 特征更新指令 → Agent 本地哈希/内部规则扫描 | SHA256 识别完全相同的文件；可选 ClamAV 与原生 YARA 接入分别见文档 64、65 |
| 漏洞信息 | NVD 原生、规范 CVE JSON 与人工导入 | 信息入库；具备明确 `affected` 条件时重新比对资产 | NVD 默认只同步描述，不推测发行版包适用性或修复版本 |
| 基线内容 | 内置模板及经审核、测试、发布的候选包 | 按 Agent 系统与版本自动选模 → 核查 → 版本快照与结果 | 支持 Linux/Windows 包流程；初始基础包并非完整合规基线，独立离线 XCCDF／OVAL 流程和完整主机条款目录分别见文档 68、67，保留其明确范围 |
| 补丁二进制 | 当前人工上传，持久化磁盘或已有 S3 兼容存储 | 现有补丁清单、下载令牌和修复任务 | 漏洞公告同步不会自动取得可安装补丁 |

## 4. 当前已完成的能力与边界

- [候选模板审核](18-基线模板审核与系统适配.md)支持来源差异、人工审核、指定主机测试、发布撤回、逐主机系统选模和不可变任务快照；[等保主机包](67-等保2.0主机合规规则包.md)提供二／三级 Linux／Windows 条款证据目录，人工材料仍须复核。
- [离线 XCCDF／OVAL](68-XCCDF与OVAL原生解释.md)使用固定摘要运行时和审核内容；[上游候选更新](69-基线模板上游自动更新.md)验证签名、发现版本和来源撤回，不自动发布未审核规则，不执行任意 Shell。
- [RPM／DPKG 版本](45-RPM-DPKG完整版本比较与epoch保留.md)、[软件身份](46-软件包身份与采集完整性.md)、[修复审批](51-漏洞覆盖历史与审批派发闭环.md)及[厂商公告](70-厂商漏洞公告原生接入.md)已经实现；NVD 修改窗口、来源退役和失败保留以[来源治理](52-安全来源治理与有界NVD同步.md)为准。
- [OpenCTI](71-OpenCTI原生指标接入.md)支持完整可见集合、审核标签、置信度、撤销与到期；[多来源治理](72-多来源可信度与冲突处理.md)明确来源权重、整条规则选择、冲突与历史，不把公告数量当成可安装补丁覆盖。
- [ClamAV](64-ClamAV引擎与扫描证据.md)、[原生 YARA](65-原生YARA引擎与规则证据.md)及[增量更新](66-病毒特征库增量更新.md)已分别实现，默认 Agent 不携带原生 YARA 运行库；引擎就绪、规则来源和更新失败均保留证据。

数据源仍由部署配置固定地址和密钥。数据库保存索引、计划、来源与游标，较大文件使用持久化目录或已有 S3；对象存储不解除 Agent 内存和下载上限。真实私有来源、指定 Windows 补丁和长期负载仍按[现场清单](80-发版准备与现场交付.md)后续验证。

## 5. 接口与开发验证

| 接口 | 权限/用途 |
|---|---|
| `GET /api/libraries` | 已登录用户查看库和来源状态；含 `nextCheckAt`、`failure_count`、`configurationIssue` |
| `PUT /api/libraries/sources/{id}/schedule` | 管理员；JSON 为 `{"enabled":true,"intervalMs":1800000}` |
| `DELETE /api/libraries/sources/{id}/schedule` | 管理员；恢复部署配置 |
| `POST /api/libraries/sources/{id}/sync` | 管理员；提交立即同步，检查返回的 `accepted` |
| `GET /api/libraries/sources/{id}/runs` | 已登录用户；最近 50 次执行 |

控制台只管理部署中已经列出的来源，不允许通过这些接口提交任意地址或密钥。可恢复配置、同步间隔校验、角色权限、失败后保留、重启恢复和记录容量都有对应后端测试；PostgreSQL 迁移检查覆盖新增表的应用角色权限。
