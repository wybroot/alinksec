# 真实外部服务联调

第 27 项以实际连接到服务、生产适配器提交结果及独立证据核对为验收依据。当前没有部署方提供的私有隔离环境配置，因此先覆盖无需密钥的四家官方公告源，以及每次新建的真实 VictoriaMetrics 实例。真实私有情报、补丁安装和长期负载仍保留现场待验收状态。

## 可重复的公开源与指标联调

完整 CI 的 `vendor-advisories` 作业保留原有原件抓取、格式／索引、双数据库相关回归及浏览器检查，并增加：

1. 使用生产 `FeedDownload` 和 `LibrarySyncService` 直接请求 Canonical USN、Debian Tracker、Red Hat CSAF 和 Microsoft CVRF 的官方 HTTPS 地址。固定样例沿用已有格式验证地址；Debian 请求当前完整压缩快照，显式选择 `openssl`、`curl`、`expat` 源码包。测试不提供镜像或本机 HTTP 替身，不修改 TLS 校验和重定向限制。
2. 每个来源使用单独临时 SQLite，执行全部真实迁移，核对已提交的 CVE 集合与原件解析集合、原件字节／SHA-256、贡献记录和 `official_https` 来源。通过生产 REST 控制器、JWT 拦截器验证未登录拒绝、登录后的原件字节及声明查询。这里的 REST 调用使用 MockMvc，不宣称已覆盖现场反向代理或实际浏览器到服务器的网络。
3. 启动与标准部署相同版本的官方 `quay.io/victoriametrics/victoria-metrics:v1.102.0` 镜像。使用随机名称及回环端口、普通 UID、只读根目录、有限 tmpfs、192 MiB 内存、1 CPU 和 64 PID 上限；不使用既有数据卷。记录镜像 ID／digest，结束时删除本次实例并确认没有残留。
4. 生产 `MetricsForwarder` 写入两条含毫秒尾数及中文、反斜线、引号、换行标签的样本。独立原始导出核对时间和值，生产 `VmQueryClient`／REST 控制器核对即时及区间查询。测试使用德语 JVM 默认区域设置，确保数字格式不依赖本机语言。
5. 独立验收脚本要求四个公开源用例、一个真实指标用例全部执行且无跳过，重算原件摘要及原始指标样本。失败、缺文件、旧提交、残留容器或任何跳过均不接受；不使用重试断言或受控响应替代成功。

VictoriaMetrics 默认 `-search.latencyOffset=30s`，最新样本虽已写入，查询仍可能暂时为空。联调使用带毫秒尾数、时间为一分钟前的两条样本，验证默认设置下的存储及查询精度；不改动正式查询参数或降低该服务的默认延迟，也不据此宣称大盘满足一秒延迟。首次 CI 已保留“原始导出存在而即时查询为空”的失败记录；同版本真实实例另行验证了默认偏移与 `latency_offset=1ms` 查询的差异。[官方查询延迟说明](https://docs.victoriametrics.com/victoriametrics/keyconcepts/#query-latency)

原指标出口使用带小数的秒并依赖 JVM 默认区域设置，德语环境会生成 `1790000000,123`。现在直接保留 Agent 的整数 Unix 毫秒 `1790000000123`，避免这一格式错误。回归测试在旧代码上复现失败，真实指标测试再验证入库后的毫秒精度。[Prometheus 文本格式](https://prometheus.io/docs/instrumenting/exposition_formats/#text-format-details)与 [VictoriaMetrics 导入／导出接口](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/#how-to-import-data-in-prometheus-exposition-format)为协议依据。

该指标测试从生产服务接收 `RptMetricsBatch` 这一边界开始，**不包含原生 Agent 的网络传输、200 台主机或 72 小时持续负载**。官方 HTTPS 和摘要也不证明厂商签名、全量历史公告、已安装补丁或主机适用性。未映射的 Red Hat／Microsoft 产品与 Debian 源码包不会被擅自转换为二进制匹配或修复目标。

在有足够资源的隔离开发机上，可按 CI 相同入口运行（输出目录必须尚不存在）：

```bash
docker pull quay.io/victoriametrics/victoria-metrics:v1.102.0
cd server
MAVEN_OPTS=-Xmx256m python3 ../deploy/tests/external-services.py \
  --output ../.tmp/external-services -- \
  mvn -B -T1 -pl alinksec-bootstrap -am \
  -Dtest=MetricsForwarderTest,VendorAdvisoryAdapterTest,VendorAdvisoryIndexTest,VendorAdvisoryIntegrationTest,VendorAdvisoryLiveIntegrationTest,ExternalMetricsIntegrationTest \
  -Dsurefire.failIfNoSpecifiedTests=false -DargLine=-Xmx256m test
cd ..
python3 deploy/tests/external-services-verdict.py .tmp/external-services \
  server/alinksec-bootstrap/target/surefire-reports "$(git rev-parse HEAD)"
```

实际证据位于 `vendor-advisory-evidence` 产物中的 `external-services` 目录和对应 JUnit 报告，包含接受时的公开原件、摘要、入库数量、查询结果及受限服务日志。失败轮次保留，不能混用旧目录补齐。约 2 GiB 的本机继续遵守 `AGENTS.md` 的串行构建和内存／PSI 看护；触发停止的命令不计通过，不以增加本机并发或堆上限完成验收。

## 仍需真实环境的项目

| 服务 | 当前可验证范围 | 现场验收所需证据 |
| --- | --- | --- |
| OpenCTI | 已有原生 GraphQL 适配、版本固定的协议与数据库回归 | 实际实例版本、受限账号和审核标签；真实分页集合核对、撤销／过期、发布及 Agent 接收 |
| MISP／MalwareBazaar／需要密钥的 NVD 配置 | 已有原生适配与失败保留回归 | 真实受限账号、审核范围、截断检查、发布前后集合与实际回执 |
| 签名基线源 | 已有签名／来源生命周期及原生应用回归 | 部署方 HTTPS 源、公钥、作用域和 Linux／Windows 实际接受结果 |
| S3 兼容存储 | 已有 SDK 传输边界及发布事务回归 | 真实隔离 bucket 和受限凭据；上传／下载摘要、失败保留旧发布、临时对象清理 |
| 通知机器人 | 已有受控发送、重试和审计回归 | 明确测试接收方、实际提供方业务成功响应及接收回执；HTTP 2xx 本身不证明业务成功 |
| WSUS／Windows Update | 已有实际 WUA 接口和受控安装提供程序回归 | 专用主机、既定源及明确 UpdateID／RevisionNumber；实际安装、重启、安装后复核 |
| VictoriaMetrics 现场规模 | 本文的真实临时实例写入／查询闭环 | 原生 Agent、真实主机身份、完整持续时间、指标延迟与所有失败／重连／资源原始样本 |
| ClamAV 官方完整库 | 已有三平台真实引擎与无害小库验收 | 受维护的实际引擎、FreshClam 更新、完整官方库及容量／长期性能，见[引擎边界](64-ClamAV引擎与扫描证据.md) |

这些项目没有因缺配置自动判定通过或不适用。配置应保存在已有权限控制的部署文件中；回执只记录必要身份、数量、时间和摘要，不上传凭据、私有配置或原始私有情报。实际通知发送需先明确测试接收方。

第 28 项真实旧生产库升级依据用户确认，在当前全新部署范围不适用，既有迁移和恢复回归继续保留。第 29 项版本发布及生产部署仍需单独指令。现场系统范围及长期性能的其余限制见[第 25／26 项](76-系统适配与规模验收.md)。
