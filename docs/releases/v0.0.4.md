# ALinkSec v0.0.4

v0.0.4 将 v0.0.3 之后的四项启动凭据修正和全部文档更新纳入新成品。此前已经完成的功能继续包含在本版中；既有 v0.0.3 标签、附件和镜像保持不变。具体发布成功时间、最终源码提交和完整 CI 以本版 GitHub Release 与 `release-manifest.json` 为准。

## 修正与文档

- 修复证书目录为单段相对路径时 JWT 初始化空指针，保留正常生成、重启复用与环境变量优先级。
- 拒绝空或空白的持久 JWT 密钥；拒绝 CA 私钥与证书不匹配，以及服务端证书非当前 CA 签发。错误材料保持原字节，不自动轮换；应恢复同一部署的成套备份。
- 完整核对架构、协议、数据库、Agent、部署、验证、模块说明和历史记录。修正过时的规划描述、14 种任务指令／4 种回执消息、集群协调与当前数据库来源，增加[文档索引](../README.md)和[逐文档核对记录](../82-v0.0.4文档核对与封版范围.md)。
- 产品、Maven、Agent、前端和默认组件镜像统一为 `0.0.4`；不新增数据库迁移，仍截至 V036。

## 包含的功能

Agent 升级失败回退、隔离租约与失联撤销、配置可信恢复、资源适配和有界补传；Linux 弱口令与 Windows 登录防护、原生 ETW 归因、WUA 更新及事件驱动监控；ClamAV、可选原生 YARA、增量特征更新；等保 2.0 主机条款包、离线 XCCDF／OVAL、签名上游候选；厂商公告、OpenCTI 与多来源信任／冲突治理；报表快照、集中取证、检查点备份、PostgreSQL 应用集群和原始日志集中检索。范围和操作见[模块清单](../19-模块完善计划.md)。

默认发布 Agent 使用 `CGO_ENABLED=0`，不含原生 YARA 运行时；原生 YARA 需单独审核构建及运行库，ClamAV 需配置本机服务。SCAP 同样受批准的内容与运行时摘要约束。平台不会因配置中启用某引擎就将缺少运行依赖记为已就绪。

## 部署与更新

下载六个附件并校验 `SHA256SUMS`，核对清单提交及镜像摘要，使用本版[部署文档](../06-部署文档.md)和[检查清单](../../deploy/部署检查清单.md)。v0.0.3 更新保留原数据卷、CA、JWT 和 Web TLS，更新前成套备份，在维护窗口使用同版源码／Compose／镜像并分批更新 Agent；启动拒绝不一致材料时恢复匹配备份，不删除密钥绕过验证。集群全部副本同版维护，不承诺混合版本滚动更新。

SQLite 保持单实例、本地 WAL 文件，默认关闭指标。标准部署使用 PostgreSQL 17／VictoriaMetrics；可选集群需要部署方准备外部 HA、共享 POSIX 存储和固定配置。真实旧生产数据库升级演练因当前全新部署范围不适用，既有迁移与恢复回归继续保留。

## 验证与现场边界

四项凭据问题在原 main 使用同一组测试实际复现，修正后 9/9 通过；修正 main 的[CI40192844535](https://github.com/wybroot/alinksec/actions/runs/40192844535)首次 27/27 成功。本版版本和文档提交仍须通过自己的完整 CI，最终 run ID 记录在发布清单，不能把上述历史 CI 当成本版精确提交的结果。

用户已将目标系统真机、Windows 持续稳定性、200 台真实主机／72 小时、一秒指标目标、真实私有情报源和指定 Windows 补丁安装／重启留待后续；这些仍未记为通过，见[交付清单](../80-发版准备与现场交付.md)。本次发布不执行生产部署，也不宣称全部系统适配或整套等保测评完成。
