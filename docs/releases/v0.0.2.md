# ALinkSec v0.0.2

Linux ARM64 与多架构交付版本，统一服务端、Web 和 Agent 产品版本为 `0.0.2`。

下列附件和镜像由同一版本提交生成，发布状态以 [v0.0.2 Release](https://github.com/wybroot/alinksec/releases/tag/v0.0.2) 为准。v0.0.1 历史成品仍为 amd64；ARM64 安装和源码构建见 [ARM64 支持](https://github.com/wybroot/alinksec/blob/v0.0.2/docs/14-ARM64支持.md)。

## 变更

- 新增 Linux ARM64（aarch64）原生 Agent，以及 Server、Web、SQLite 维护工具的 Linux amd64 + arm64 镜像。
- Linux 两种架构分别在原生 runner 上执行测试、Agent 联动、镜像构建和冒烟；发布时按已验证的不可变 digest 合并双架构镜像索引。
- 主机详情显示实际 CPU 架构，兼容旧 Agent 上报的 `x86_64` / `aarch64`。升级下发前检查全部目标的平台，混合架构批次只要有一个目标不匹配，就拒绝整个批次；Agent 替换文件前再次核对升级包内的 Go 构建平台。
- 发布门禁要求同一 main 提交的 Linux amd64、Linux arm64、Windows 和数据库四个作业全部成功，复用同一次 CI 的三个原生 Agent，并校验 ELF/PE 实际架构。

## 部署与下载

| 组件 | 平台 |
| --- | --- |
| Server、Web、SQLite 维护镜像 | Linux amd64、Linux arm64 |
| 原生 Agent | Linux amd64、Linux arm64、Windows amd64 |

```text
wangyanbiao/alinksec:server-v0.0.2
wangyanbiao/alinksec:web-v0.0.2
wangyanbiao/alinksec:sqlite-maintenance-v0.0.2
```

同一组件标签包含两种 Linux 架构，Docker 自动选择本机平台。发布提供六个附件：

| 附件 | 用途 |
| --- | --- |
| `alinksec-v0.0.2.tar.gz` | 完整源码、部署配置及中英文文档 |
| `alinksec-agent-linux-amd64` | Linux x86_64 原生 Agent |
| `alinksec-agent-linux-arm64` | Linux aarch64 原生 Agent |
| `alinksec-agent-windows-amd64.exe` | Windows x64 原生 Agent |
| `release-manifest.json` | 发布提交、完整 CI run ID、附件 SHA256、镜像索引及各平台 digest |
| `SHA256SUMS` | 其他五个附件的 SHA256 |

下载全部附件后执行 `sha256sum --check SHA256SUMS`，再按 [部署文档](https://github.com/wybroot/alinksec/blob/v0.0.2/docs/06-部署文档.md)安装。Linux 以目标主机的 `uname -m` 为准选择 Agent：`x86_64` 对应 `linux-amd64`，`aarch64` 对应 `linux-arm64`。控制台上传升级包时，平台分别选择 `linux-amd64`、`linux-arm64` 或 `windows-amd64`，每次下发使用同一平台的主机批次。

## 验证状态与边界

发布要求 v0.0.2 对应的同一 main 提交通过 Linux amd64、Linux arm64、Windows 和数据库完整 CI，再完成两种原生架构上的镜像冒烟、双架构索引和六个附件校验。`release-manifest.json` 记录实际发布提交、完整 CI run ID、镜像 digest 与附件 SHA256；CI 地址为 `https://github.com/wybroot/alinksec/actions/runs/<ciRun>`。门禁与顺序见 [发布流程](https://github.com/wybroot/alinksec/blob/v0.0.2/docs/13-版本发布流程.md)。

本次没有新增数据库迁移。验收以全新部署为范围，尚无 v0.0.1 到 v0.0.2 的完整存量升级验收结论；已有部署变更前应保留数据库、证书、JWT 密钥和上传物料的备份。源码、Compose、镜像和 Agent 应使用同一版本。

ARM64 原生 CI 在 Ubuntu ARM64 runner 上执行，不代表所有 ARM Linux 发行版或硬件均已验收，也不包含 ARMv7、Windows ARM64 或 macOS。v0.0.1 的 amd64 短时性能采样不能作为 ARM64 性能结论。Windows SCM 验证不等于 Windows 全量安全引擎与 Java 平台完整联动；SQLite 仍限单 server、本机持久化卷和初始 1～10 台主机。详细证据见 [ARM64 验收记录](https://github.com/wybroot/alinksec/blob/v0.0.2/docs/14-ARM64支持.md)及 [原生 Agent 验收](https://github.com/wybroot/alinksec/blob/v0.0.2/docs/12-原生Agent本机验收记录.md)。
