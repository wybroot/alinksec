# 告警等级与采集查询修正

本组同时修正告警等级来源、Windows ETW 启动状态及近期指标可见性。原有系统、规则、失败边界和完整 CI 场景继续保留。

## 告警等级

`t_alert.severity` 保留原始数值。V036 增加独立的 `severity_source`，由服务端入库路径写入，不采用事件 detail 中的同名字段。`v_alert_severity` 提供展示和阈值用的 `severity_level`：

| 来源 | 原值 | 展示等级 |
| --- | --- | --- |
| `agent_proto_v1` | 1 / 2 / 3 / 4 / 5 | 信息 / 低危 / 中危 / 高危 / 严重 |
| `agent_proto_v1` | 0 或无法识别的值 | 未知 |
| `legacy_unclassified` | 1 / 2 / 3 / 4 / 5 | 低危 / 中危 / 高危 / 严重 / 严重，标注历史含义 |
| `legacy_unclassified` | 其他值 | 未知，标注历史含义 |

展示等级数值为信息 0、低危 1、中危 2、高危 3、严重 4、未知 -1。迁移前的来源无法可靠恢复，因此不将历史行追认为 protobuf，也不改写原值。聚合要求来源与原值相同，避免历史与新事件、或升级后的不同等级合并到同一行。既有报表快照字节和摘要保持原样；新报表保存来源、原值、展示等级及当次文字解释。

列表、筛选、保护阻断记录、大盘、通知首次发送及补发均使用同一数据库视图。通知负载同时带原值、来源、展示等级和说明；通知渠道的既有阈值仍为 1低、2中、3高、4严重。来源未知的历史记录继续按旧含义匹配阈值。既有通知投递记录不重写或重复投递。

SQLite 与受限 PostgreSQL 应用账号执行相同回归，检查真实事件入库、混合聚合、未知值、筛选、统计、快照不可变和回环 HTTP 通知首次失败后的补发。浏览器读取这两个数据库实际生成的响应，检查高危／严重筛选和历史标记。基线与 CVE 的独立等级契约不按事件 protobuf 改写。

## Windows ETW

原启动流程在消费者准备前启用文件事件提供程序，初始化期间缺少消费者排空。现在先准备路径映射与事件消费，再启用提供程序；发布 ready 前查询实际会话健康。请求的 64 KiB 缓冲区和最多 16 个缓冲区上限保持原值。

启动期间回调报告丢失时，Monitor 不再用随后返回的启动成功覆盖 unavailable。确定性回归模拟此顺序，要求没有可归因的 ready 窗口。原生 Windows Server 2022／2025 的三次独立进程测试保留全部原断言，并记录会话实际缓冲区、EventsLost、RealTimeBuffersLost、LogBuffersLost 及回调丢失计数。任何丢失仍使当前证据失效，不隐去错误或接受带缺口的归因。

这修复了启动顺序中的风险和状态覆盖问题；不据此认定此前 Windows 2025 一次 `etw_events_lost` 的根因已经证明。原始失败与原样重跑记录继续保留。缓冲区积压和实际查询计数的依据见 [Microsoft EVENT_TRACE_PROPERTIES](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_properties)。

## 近期指标

生产即时与区间查询均传递 `latency_offset=1ms`，避免 VictoriaMetrics 默认三十秒偏移使近期样本暂不可见。真实隔离实例同时验证历史毫秒精度和当前样本，保留查询逐次响应、可见耗时与原始导出。十秒以内的测试上限是回归边界；一秒显示延迟、原生 Agent 网络及 200 台真实主机连续 72 小时仍需现场验收，见[外部服务联调](77-真实外部服务联调.md)。

私有外部服务、未覆盖的原生操作系统、实际补丁安装／重启和长期负载继续列为待验收。版本发布及生产部署等待单独指令。
