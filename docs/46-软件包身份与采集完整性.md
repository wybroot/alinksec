# 软件包身份与采集完整性

本阶段在 `vulnerability-applicability` 分支完善软件资产证据。包架构、发行版和采集状态用于资产展示及修复前检查；整个漏洞判断与修复适用性模块仍在开发中。

## 身份来源与边界

| 信息 | 取值依据 | 缺失时的处理 |
|---|---|---|
| RPM 完整版本、架构 | 包数据库 `EPOCHNUM/VERSION/RELEASE/ARCH` | 不合格记录使整次软件采集失败；旧 RPM 公钥伪包不属于软件资产 |
| DPKG 完整版本、架构 | `Version/Architecture`，包名用 `Package` 保持同名多架构记录 | hold 且正常安装的包保留；半安装、重新安装必需等异常状态使采集失败 |
| Linux 发行版 | `/etc/os-release` 的 `ID` 和 `VERSION_ID`；仅文件不存在时回退 `/usr/lib/os-release` | 保留未知或不完整身份；不从系统显示名、`ID_LIKE` 或代号推断版本 |
| 软件来源 | 实际读取的包数据库；两个数据库都可用时均查询，快照来源为 `mixed` | 一项查询失败则整体软件清单不完整；不以非空输出决定回退 |
| Windows 应用 | 两个 Uninstall 注册表路径 | 注册表读取失败使软件清单失败；注册表视图和 Agent 编译架构不作为软件包架构 |

版本比较沿用[完整软件包版本规则](45-RPM-DPKG完整版本比较与epoch保留.md)。Linux 查询每个数据库最多 20 秒、16 MiB 输出，总清单最多 100,000 项；超限、非零退出和解析错误不会伪装成空清单。命令超时终止本次进程组。`os-release` 读取最多 64 KiB，仅解析字面字段，不执行 shell 内容。

## 入库与展示

协议新增兼容字段 `SoftwareInfo.architecture` 和 `RptAssetSnapshot.software_inventory`。状态为 complete、failed、unsupported 或未知；旧 Agent 未携带元数据，标为 legacy，完整性未知。

V008 在 SQLite/PostgreSQL 增加包架构、发行版身份、软件清单来源、最近尝试状态和最近成功时间。历史资产不补造身份；已有迁移及其校验和保持原样。

成功清单才替换软件资产，成功空清单可以清空资产并清理未处置且没有待执行修复引用的漏洞记录。失败、不支持、未知状态、非法或重复的 complete 记录保留上次软件资产和身份，更新最近尝试状态。端口、进程等类别独立更新；针对这些类别的采集不覆盖软件证据。显式失败清单不触发新比对，手动重扫也跳过该主机。

主机详情显示发行版、来源、成功时间、包架构和采集状态。失败时注明当前为保留清单，完整性未知时提示重新采集；没有包架构的记录显示“未知”。抽屉最多展示前 500 条，资产查询接口仍可分页取得其余记录。

## 修复前检查

创建软件修复任务必须有最近一次完整采集，并存在唯一的同名安装记录，且已安装版本与选中漏洞记录相同。Linux 还必须有发行版 ID/版本、原生软件来源和包架构；多个架构或多个安装版本禁止通过包名自动修复。补丁类型必须与软件来源一致。

任务保存当时的软件来源、架构、发行版、系统和安装版本。审批立即派发以及维护窗口派发都会重新检查这些信息。清单失败或身份变化会阻断派发；缺少新身份快照的历史待审批任务需要重新创建。

这些检查证明资产证据足以定位单一安装记录。当前漏洞匹配规则、finding 和列表聚合仍未完成发行版/架构作用域改造，规则厂商来源、回移修复依据、真实补丁包内部元数据及修复版本确认也尚待实施。本阶段不能据此宣称某发行版或架构的 CVE 已确认，也不证明已导入补丁的真实架构和内容适用性。审批权限、并发派发和 Agent 安装前后的身份复核在同模块后续阶段继续完成。

## 验证入口

- Go collector 测试：多架构、完整 EVR、hold 包、双数据库、成功空清单、部分失败、非法身份、输出上限、超时及非零退出。
- `SoftwareInventoryIntegrationTest`：真实 SQLite 迁移、事务、失败保留、成功空清单、历史兼容、修复创建及审批派发检查。
- `AgentChannelSecurityIntegrationTest`：SQLite/PostgreSQL 上协议接收、持久化、审批派发与结果归属回归。
- CI 原生采集：Ubuntu DPKG 与隔离的 Rocky9 RPM，Linux amd64/arm64 分别执行；Windows collector 纳入原生 Windows 测试。
- 真实 Agent 工作流：夹具先安装 1.0 包，由 Agent 采集并经查询确认 `all` 架构，再审批安装 2.0。
- 生产前端浏览器检查：完整、失败、旧清单、不支持、身份不完整、成功空清单及手机抽屉宽度。使用合成 API 夹具，不将页面测试视为真实软件检测。

本机约 2 GiB，重验证串行执行并由内存看护限制。本地采集器单元测试已完成；本地原生采集尝试被内存压力看护中止，原服务已恢复。完整跨平台验收以本阶段提交的 CI 结果为准。
