# IPv4 主机角色与全部接口当前参考核查

独立 [ipv4-host/linux-baseline.json](../deploy/baseline/packages/ipv4-host/linux-baseline.json) 版本1成组提供旧0036/0038两项。限定Ubuntu24.04 amd64/arm64、Linux IPv4 procfs及当前Agent线程的网络命名空间，最多16现存接口。管理员须先确认该命名空间无需IPv4转发且采用对称路由；这不是所有Linux主机的通用安全要求。

| 原规则 | 完整参考 |
|---|---|
| 0036 | `role=non-router-symmetric,default_effective=1,interfaces_effective=1` |
| 0038 | `role=non-router-symmetric,ip_forward=0,all/default/interfaces_forwarding=0` |

管理员需评估路由器、容器宿主、VPN、多宿主、策略路由和非对称路径。在确认适用后，人工在`/etc/alinksec/ipv4-host-role`中声明`non-router-symmetric`及一个换行；生产Agent只读，不创建声明或修改网络。声明属于管理员输入，不能据此认证真实拓扑。角色文件缺失、内容不适用、其他角色、空值或格式未知均为error；不能根据`ip_forward=0`反推业务角色。文件及全部父目录需root:root、无组/其他写权限、无链接、无普通文件硬链接及访问/默认ACL，无法确认也保持error。

读取固定`/proc/sys/net/ipv4/ip_forward`及`conf/all`、`conf/default`与全部现存接口的`rp_filter`和`forwarding`。包括loopback、未启用接口及含点名称，名称限1至15个ASCII字符：字母数字下划线短横线开头，后续允许点号。未知名称、超过16接口、缺少all/default/现存接口参数或非规范单字节数值加换行均为error。不存在的IPv4接口树不会以空集合通过。

0036按照内核的`max(all,interface)`计算当前反向路径过滤模式，每个接口须严格模式1；`max(all,default)`也须1，仅作为当前新接口默认值参考。`all=1`而接口值为2仍是宽松模式，返回fail；`all=0`且全部接口/default为1可以满足参考。0038要求`ip_forward`、all、default及全部现存接口的forwarding均0；单独接口1也返回fail。`ip_forward`与all.forwarding是别名，读值不一致视为变化或未确认输入，返回error。

生产锁定调用线程，读取`/proc/thread-self/ns/net`身份；目录逐层以描述符相对打开，拒绝链接，核对procfs类型、root数值属主、文件/目录类型和写权限。每参数最多64字节，持有全部描述符至路径身份复核，接口枚举有固定上限。两次完整读取比较值、接口名称、inode及命名空间身份，最后复核角色输入；全部共享100至30000ms截止时间，默认5000ms。明确0或null超时、弱比较、接口筛选、角色路径、命令和其他扩展字段均被两端拒绝。观察仍非原子，短暂变化或ABA变化可能未被捕获。

证据明确标注`routing_state=unverified packet_enforcement_state=unverified persistence_state=unverified other_netns_state=unverified snapshot_state=non_atomic`。不解析路由/FIB/fwmark、不发送测试包，不证明真实数据包丢弃、完整防伪造、IPv6、其他命名空间、重启持久性或未来接口实际配置。Agent处于容器时仅观察该容器命名空间，不能扩大成宿主机结论。完整已知参数偏差为fail；角色/路径/读取/格式/超限/变化/超时为error。一项error阻止两项整批发布，任一新定义需整批新测试证据，旧任务快照保留。无自动修复，候选需依[审核流程](18-基线模板审核与系统适配.md)独立导入、确认适用性和测试。

CI的Ubuntu24 amd64/arm64独立runner依次创建九个无外网临时Docker网络命名空间。Docker先设置namespace-local全局值；runner子进程确认目标命名空间与宿主不同后，以nsenter只进入该容器的网络命名空间，顺序设置default及lo局部值，避免全局写入重置局部值和OCI映射无序。随后确认目标及宿主命名空间身份未变，再执行测试。容器的/proc/sys始终只读；每个容器128MiB/一个CPU、无SYS_ADMIN或privileged模式、无宿主/etc或数据卷、仓库只读。NET_ADMIN只用于创建两个未启用dummy接口，其中一个名称含点。root、双显式开关及镜像隔离标记缺一立即拒绝写入测试角色；成功或失败均清理本场景容器后才开始下一个。

九组场景覆盖all提供严格模式、各接口独立严格、all或接口宽松覆盖、关闭、未来默认宽松、单接口转发、默认转发及全局转发。每组真实固定生产选择器观察两项并保留item ID，与原生procps的含点路径查询对照。强制边界覆盖角色缺失/不适用/格式、UID/GID、访问/默认ACL、链接/硬链接/FIFO，普通磁盘冒充procfs、读取超限/缺失/未知、多接口上限、参数/接口/路径/命名空间变化和共同截止时间；夹具不允许跳过。REST及生产页面完整报告是协议夹具，与真实内核参数观察分开。每批验收绑定对应提交的CI。

语义依据[Linux内核IP sysctl文档](https://www.kernel.org/doc/html/latest/networking/ip-sysctl.html)的`ip_forward`、接口`forwarding`、`rp_filter`和`src_valid_mark`。严格模式阈值属于本项目的特定主机参考；内核明确建议非对称或复杂路由采用不同策略。变更ip_forward会影响其他内核参数，管理员应按业务评估，不据候选执行统一修复。
