# ALinkSec 部署文档（详细版）

> 适用版本：M1-M4 全量功能（含卸载口令防护 / 断网落盘队列 / RBAC 三角色）
> 部署形态：生产模式使用 PostgreSQL 17 + VictoriaMetrics + 服务端 + 前端 Nginx；轻量模式使用 SQLite WAL + 服务端 + 前端 Nginx。Agent 均裸装到目标主机。
> 每一步都附【做什么】【为什么】【怎么验证】，照抄命令即可完成部署与联调

---

## 0. 架构总览与端口清单

先建立全局认知，后面每一步都在往这张图里填东西：

```
                        ┌────────────────── 服务器（Docker Compose）──────────────────┐
                        │                                                             │
  浏览器 ──8443──►  nginx(web容器) ──/api/ 反代──► server:8080 (REST + JWT + RBAC)    │
                        │                              │            │                 │
                        │                    PostgreSQL:5432   VictoriaMetrics:8428   │
                        │                      (38张业务表)      (时序指标,90天)       │
                        └─────────────────────────────▲─────────────▲─────────────────┘
                                                      │ gRPC mTLS 双向证书
                                        9443 ──────────┘             │
                                              │                     │
                                    ┌─────────┴─────────┐   ┌───────┴────────┐
                                    │ 目标主机 A (Linux) │   │ 目标主机 B (Win)│
                                    │ alinksec-agent    │   │ alinksec-agent │
                                    └───────────────────┘   └────────────────┘
```

| 端口 | 协议 | 用途 | 谁访问 | 是否放行防火墙 |
|---|---|---|---|---|
| **9443** | gRPC mTLS | Agent 接入（注册/心跳/上报/指令） | 目标主机 | ✅ 必须 |
| **8443** | HTTPS | Web 控制台、API 与 Agent 包下载 | Agent、浏览器 | ✅ 必须 |
| 8081 | HTTP | 仅重定向至 HTTPS | 浏览器 | 可选 |
| 5432 | PostgreSQL | 仅 compose 内网 | server 容器 | ❌ 不暴露 |
| 8428 | VM | 仅 compose 内网 | server 容器 | ❌ 不暴露 |

**组件职责一句话**：
- `postgres`：业务库（主机、资产、基线、漏洞、病毒、告警、审计等，SQL 首启自动初始化）
- `victoriametrics`：Agent 心跳性能指标的时序存储（大屏图表数据源）
- `server`：Java 21 服务端（gRPC 9443 + REST 8080，首次启动自动生成 CA/服务端证书 + admin 账号 + 注册码）
- `web`：Vue3 前端静态资源 + nginx（8443 HTTPS 入口，`/api/` 反代 8080）

### 0.1 模式选择

| 模式 | 建议用途 | 支持边界 |
|---|---|---|
| `postgres` | 正式环境 | PostgreSQL 外部迁移、最小权限应用账号、VictoriaMetrics 90 天指标；本手册默认流程 |
| `sqlite` | 开发、演示、少量主机快速验证 | 初始承诺 1～10 台、单 server 实例、默认关闭指标、不支持高可用 |

SQLite 文件位于 `server-data` 卷中的 `/app/data/alinksec.db`，启用 WAL、外键和 5 秒锁等待。不得把数据库文件放在 NFS/SMB，也不能通过直接复制运行中的 `alinksec.db` 作为备份。两种模式不提供原地自动互转；切换到 PostgreSQL 需要停机、导出并按业务表校验迁移。

## 1. 前置条件

### 1.1 服务器（跑 Docker 的那台）

| 项 | 要求 | 检查命令 |
|---|---|---|
| 操作系统 | Linux x86_64（CentOS 7+/Ubuntu 20.04+ 均可） | `uname -m` → `x86_64` |
| Docker | ≥ 20.10 | `docker -v` |
| docker compose | v2（`docker compose` 子命令形式） | `docker compose version` |
| 内存 | ≥ 4GB（JVM 默认拿 75%） | `free -h` |
| 磁盘 | ≥ 20GB（PG 数据 + VM 90 天指标 + 特征库） | `df -h` |
| 端口 | 9443/8443/8081 未占用 | `ss -tlnp \| grep -E '9443\|8443\|8081'` 应无输出；8080 仅容器内使用，不映射宿主机 |

### 1.2 目标主机（装 Agent 的每台）

- Linux x86_64 或 Windows x64（Agent 两种都支持）
- 能访问服务器的 **9443**（gRPC）和 **8443**（HTTPS 下载与控制台）
- Linux 需 `systemd`；Windows 需管理员权限

### 1.3 构建机（你现在的 Windows 开发机）

- JDK 21 + Maven（构建服务端 jar）
- Node.js ≥ 20（仅本地调试用；前端在 Docker 里构建，本机可不装）
- Go ≥ 1.22（交叉编译 Agent）

## 2. 第一步：本机构建发布包

> 【做什么】在 Windows 开发机上产出 `alinksec-release.zip` + Agent 二进制
> 【为什么】服务器不需要装 JDK/Maven/Node/Go，镜像在服务器上由 Docker 构建

### 2.1 发布前校验

```powershell
# 在仓库根目录执行；记录本次部署提交，所有校验通过后再打包
git status --short
git rev-parse --short HEAD

Push-Location server; mvn -B test; Pop-Location
Push-Location agent; go test ./...; Pop-Location
Push-Location web; npm ci; npm run build; Pop-Location
```

> 发布包不包含本地的 `target/`、`node_modules/` 或 `dist/`。镜像会在 Docker 构建阶段根据完整的 `server/`、`proto/`、`web/` 源码重新构建，因此服务器只需 Docker，不需要单独安装 Maven 或 Node。

### 2.2 交叉编译 Agent（Linux 版 + Windows 版各一份）

```powershell
cd agent

# ---- Linux amd64 版 ----
$env:GOOS="linux";   $env:GOARCH="amd64"
go build -trimpath -ldflags "-s -w" -o ..\release-bin\alinksec-agent-linux-amd64 ./cmd/agent
# -trimpath/-s -w：去掉调试信息减小体积（约 10MB）

# ---- Windows amd64 版（如有 Windows 目标主机）----
$env:GOOS="windows"; $env:GOARCH="amd64"
go build -trimpath -ldflags "-s -w" -o ..\release-bin\alinksec-agent-windows-amd64.exe ./cmd/agent

# 还原环境变量（重要！否则后续本机 go 命令会编译出错误平台的包）
$env:GOOS=""; $env:GOARCH=""
cd ..
```

### 2.3 打真机发布包（完整服务端源码 + 前端源码 + 部署物）

```powershell
$releaseDir = Join-Path $PWD 'release'
$archive = Join-Path $PWD 'alinksec-release.zip'
if (Test-Path $releaseDir) { Remove-Item -Recurse -Force $releaseDir }
if (Test-Path $archive) { Remove-Item -Force $archive }
New-Item -ItemType Directory -Path $releaseDir | Out-Null

# Dockerfile.server 会 COPY server/ 和 proto/ 后在容器内 Maven 构建；不能只打一个 JAR。
foreach ($name in 'server', 'proto', 'web', 'deploy') {
  robocopy $name (Join-Path $releaseDir $name) /E /XD target node_modules dist .idea | Out-Null
  if ($LASTEXITCODE -ge 8) { throw "复制 $name 失败，robocopy 返回 $LASTEXITCODE" }
}
Copy-Item .dockerignore $releaseDir
Compress-Archive -Path "$releaseDir\*" -DestinationPath $archive -Force
```

**发布清单自查**：

```
alinksec-release.zip
├── server/         （完整 Maven 源码；Dockerfile.server 在镜像内构建）
├── proto/          （Agent 通信协议；服务端构建时生成 Java/gRPC 代码）
├── web/            （package.json + src/ + public/，无 node_modules）
├── deploy/sql/     （PostgreSQL DDL + SQLite schema 生成脚本）
├── deploy/sqlite-maintenance.sh （SQLite 在线备份、校验与恢复）
└── deploy/docker/  （生产/轻量 Compose + Dockerfile×2 + nginx.conf + env 示例）

release-bin/
├── alinksec-agent-linux-amd64        ← 传到每台 Linux 目标主机
└── alinksec-agent-windows-amd64.exe  ← 传到每台 Windows 目标主机
```

> 如果你打算把整个代码仓库直接传到服务器也可以，但必须保留 `server/`、`proto/`、`web/` 和 `deploy/` 四个目录的相对层级。不要将 `.env`、数据库备份或已导出的 CA 一并提交进代码仓库。

## 4. 第三步：配置 .env（⚠️ 首次启动前必做，改晚要重建）

> 【做什么】把服务器真实 IP 写进 .env
> 【为什么】服务端 **gRPC 证书只在首次启动生成一次**，证书 SAN（可访问主体名单）里必须包含
> 服务器 IP，否则目标主机的 Agent 连 `IP:9443` 时 TLS 校验必失败。
> 证书一旦生成不会自动更新——忘配的后果是删 volume 重来（见 §12 排障表第 1 条）。
> 同时该 IP 也被用作特征库/补丁包下载地址（Agent 走 `https://<HOST_IP>:8443/...` 并校验平台注册 CA）。

```bash
cd ~/alinksec/deploy/docker
cp .env.example .env

# 把 HOST_IP 改成服务器真实 IP（必须是目标主机 ping 得通的那个 IP，不能写 127.0.0.1）
# 查本机 IP：ip addr 或 hostname -I
vim .env
```

`.env` 至少需要以下各项：

```ini
HOST_IP=192.168.1.100    # ← 示例占位值，启动时会被拒绝；改成真实接入地址
ALINKSEC_BIND_ADDRESS=192.168.1.100  # Docker 仅在该本机 IPv4 上发布端口，禁止 0.0.0.0
ALINKSEC_BOOTSTRAP_ADMIN_PASSWORD=<至少12位的高强度密码>
ALINKSEC_BOOTSTRAP_ENROLL_TOKEN=ENROLL-<随机字符串>
ALINKSEC_POSTGRES_PASSWORD=<初始化/迁移账号随机密码>
ALINKSEC_POSTGRES_APP_PASSWORD=<不同的应用账号随机密码>
ALINKSEC_JWT_SECRET=<openssl rand -base64 48 的输出>
```

生成随机值时可使用：

```bash
openssl rand -base64 48        # JWT 密钥或数据库密码
openssl rand -hex 24           # 可拼接为 ENROLL-<输出>
```

> `.env` 是生产密钥文件，应设为仅部署账号可读（`chmod 600 .env`），不得提交、上传到工单或复制到日志中。两个数据库密码必须不同：`alinksec` 只供初始化、迁移和备份，长期运行的 server 只持无 DDL 权限的 `alinksec_app`。`HOST_IP` 或 `ALINKSEC_BIND_ADDRESS` 缺失会使配置/迁移失败；保留示例值、通配绑定、回环接入地址或无效地址会阻止正常上线。单机部署不设置 `ALINKSEC_JWT_SECRET` 也能启动，服务端会把随机密钥写入 `server-data` 卷；但显式设置能让灾备恢复和未来多实例部署更可控。

### 4.1 轻量模式配置与启动

轻量模式使用独立 `.env.lite`，不需要数据库密码。生产部署请跳过本节并继续第 5 节。

```bash
cd ~/alinksec/deploy/docker
cp .env.lite.example .env.lite
vim .env.lite
chmod 600 .env.lite

docker compose --env-file .env.lite -f docker-compose.lite.yml config -q
docker compose --env-file .env.lite -f docker-compose.lite.yml build
docker compose --env-file .env.lite -f docker-compose.lite.yml up -d --wait
docker compose --env-file .env.lite -f docker-compose.lite.yml ps
docker compose --env-file .env.lite -f docker-compose.lite.yml logs --tail=100 server
```

预期只有 `alinksec-lite-server` 与 `alinksec-lite-web` 两个长期容器。首次启动会自动执行 SQLite 版本化迁移；迁移脚本校验和变化时服务会拒绝启动。验证健康和表种子：

```bash
docker compose --env-file .env.lite -f docker-compose.lite.yml cp \
  server:/app/data/certs/ca.crt ./alinksec-ca.crt
curl --cacert ./alinksec-ca.crt https://<HOST_IP>:8443/api/health
# 期望 {"code":0,"msg":"ok","data":null}
```

后续控制台、TLS 与 Agent 接入步骤和生产模式一致；所有 `docker compose` 运维命令需继续带 `--env-file .env.lite -f docker-compose.lite.yml`。

### 4.2 不使用 Docker 的本地 SQLite 验证

开发机只验证服务端接口时，可以直接运行打包后的 JAR，不需要安装 PostgreSQL。数据库、证书和上传物料会写入当前 `server/data/`；该方式不包含前端 Nginx，REST 健康检查使用 `http://127.0.0.1:8080`。

Linux/macOS：

```bash
cd ~/alinksec/server
mvn -B -pl alinksec-bootstrap -am package -DskipTests
mkdir -p data
export SPRING_PROFILES_ACTIVE=sqlite
export ALINKSEC_SQLITE_PATH="$PWD/data/alinksec-dev.db"
export ALINKSEC_BOOTSTRAP_ADMIN_PASSWORD='<替换为至少 12 位的本地验证密码>'
export ALINKSEC_BOOTSTRAP_ENROLL_TOKEN='ENROLL-local-dev'
export ALINKSEC_METRICS_ENABLED=false
java -jar alinksec-bootstrap/target/alinksec-bootstrap.jar
```

Windows PowerShell：

```powershell
cd .\server
mvn -B -pl alinksec-bootstrap -am package "-DskipTests"
New-Item -ItemType Directory -Force .\data | Out-Null
$env:SPRING_PROFILES_ACTIVE = 'sqlite'
$env:ALINKSEC_SQLITE_PATH = (Join-Path (Resolve-Path .\data).Path 'alinksec-dev.db')
$env:ALINKSEC_BOOTSTRAP_ADMIN_PASSWORD = '<替换为至少 12 位的本地验证密码>'
$env:ALINKSEC_BOOTSTRAP_ENROLL_TOKEN = 'ENROLL-local-dev'
$env:ALINKSEC_METRICS_ENABLED = 'false'
java -jar .\alinksec-bootstrap\target\alinksec-bootstrap.jar
```

首次启动日志应包含 `Applied SQLite migration V001`。停止后用相同命令重启，迁移不应重复执行；随后访问健康检查并使用 `admin` 与上面设置的密码登录。此流程仅用于开发验证，不替代生产模式的 PostgreSQL、Compose、TLS 入口和最小权限验收。

## 5. 第四步：构建镜像 + 初始化/迁移 PostgreSQL

> 【做什么】先只起 PG，验证初始化完成后再起业务（分层排障，出问题好定位）

```bash
cd ~/alinksec/deploy/docker

# 构建两个镜像（server 镜像内 Maven 构建；web 镜像内 npm ci + vite build，首次约 3~5 分钟）
docker compose build

# 先起 PG，再运行一次性 migrate 服务
docker compose up -d postgres
docker compose up migrate
docker compose ps -a
# 期望 postgres 为 healthy，migrate 为 Exited (0)
```

**验证 ①：容器健康 + 关键表建全**

```bash
docker exec alinksec-pg pg_isready -U alinksec -d alinksec
# 期望输出：accepting connections

docker exec -it alinksec-pg psql -U alinksec -d alinksec -c "\dt"
# 期望可见 t_agent、t_user、t_alert、t_command、t_audit_log、t_policy_state 等关键表

docker compose logs migrate
# 期望包含 Database migrations and application grants are current.
```

精确计数（更快）：

```bash
docker exec -it alinksec-pg psql -U alinksec -d alinksec \
  -c "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
# 期望：大于 0；表数量会随版本演进，不能作为跨版本部署的唯一判据
```

> 空库先执行 `deploy/sql/001_init.sql`，随后 `migrate` 按文件名执行 `deploy/migrations/V*.sql`，并在 `t_schema_migration` 保存版本与校验和。已有卷不会重跑空库脚本，但仍会执行未记录的版本化迁移。任何迁移失败都会阻止 server 启动；不要修改已发布迁移，应新增更高版本文件。

## 6. 第五步：启动服务端 + 前端

```bash
cd ~/alinksec/deploy/docker
docker compose up -d
docker compose ps
# 期望 4 个长期服务 running，migrate 为 Exited (0)：
#   alinksec-pg / alinksec-vm / alinksec-server / alinksec-web / migrate(exited 0)
```

**验证 ②：服务端启动日志（关键信息都在里面）**

```bash
docker compose logs server | grep -E "gRPC|Bootstrap"
# 期望出现：
#   gRPC 服务已启动: port=9443 (mTLS)
#   Bootstrap administrator created: admin
#   Bootstrap enrollment token created
```

> 启动前必须在 `.env` 设置 `ALINKSEC_BOOTSTRAP_ADMIN_PASSWORD`（至少 12 位）和
> `ALINKSEC_BOOTSTRAP_ENROLL_TOKEN`（随机 `ENROLL-` 前缀字符串）。服务端不会把这两个敏感值写入日志。

**验证 ③：三个端口在监听**

```bash
ss -tlnp | grep -E '9443|8081|8443'    # 期望三行 LISTEN
```

**验证 ④：证书已生成**

```bash
docker exec alinksec-server ls /app/data/certs
# 期望：ca.crt  ca.key  server.crt  server.key
docker cp alinksec-server:/app/data/certs/ca.crt ./alinksec-ca.crt
```

**验证 ⑤：前端可访问 + REST 反代通**

```bash
# 前端页面（平台 CA 为自签 CA，curl 使用导出的 CA 验证）
curl --cacert ./alinksec-ca.crt -s -o /dev/null -w "%{http_code}\n" https://<HOST_IP>:8443/
# 期望：200

# REST API 经 nginx 反代到 server（将下方密码替换为 .env 中配置的初始密码）
curl --cacert ./alinksec-ca.crt -s https://<HOST_IP>:8443/api/auth/login -X POST \
  -H "Content-Type: application/json" -d '{"username":"admin","password":"<bootstrap-password>"}'
# 期望返回 JSON 含 "code":0 和 token（说明 nginx→server→PG 整条链路通）
# 404/502 说明反代或服务端没起来 → 查 docker compose logs server / web
```

**验证 ⑥：按来源网段限制发布端口（联调前必做）**

```bash
# Docker 启动后执行；将网卡和两个网段替换为真实值
sudo EXTERNAL_INTERFACE=eth0 \
  MANAGEMENT_CIDR=10.10.0.0/24 \
  AGENT_CIDR=10.20.0.0/16 \
  bash ../firewall/alinksec-docker-user.sh

sudo iptables -S ALINKSEC-INGRESS
# 管理网可访问 8443/8081；受管主机网可访问 9443/8443；其余来源被 DROP
```

Docker 发布端口可能绕过只配置在主机 INPUT 链上的 ufw/firewalld 规则，因此这里使用 Docker 官方入口 `DOCKER-USER`。规则需纳入主机防火墙持久化配置，并在 Docker 启动后恢复。回退规则：`sudo EXTERNAL_INTERFACE=eth0 bash ../firewall/alinksec-docker-user.sh remove`。必须从管理网、受管主机网和一个非授权网段分别实测连接结果。

## 7. 第六步：登录控制台

1. 浏览器打开 `https://<服务器IP>:8443/`；将 `/app/data/certs/ca.crt` 导入浏览器或操作系统信任库。
2. 登录：`admin / ALINKSEC_BOOTSTRAP_ADMIN_PASSWORD`（仅首次无用户时创建）
3. **立刻改密**：右上角头像 → 修改密码
4. 安全大屏：`https://<服务器IP>:8443/screen`（暗色投屏版，只读）

> 建议同时建两个测试角色账号用于 RBAC 联调（§9.8）：
> 「系统管理 → 用户管理」分别建 `operator01`（角色选 operator）和 `viewer01`（角色选 viewer）。

## 8. 第七步：目标主机安装 Agent

> Agent 安装三件事：① 拿到注册码 → ② install（写配置 + gRPC 注册 + 领客户端证书）→ ③ run 常驻

### 8.1 Linux 目标主机

```bash
# ---- 上传 alinksec-agent-linux-amd64 到目标主机后 ----
chmod +x alinksec-agent-linux-amd64
sudo mv alinksec-agent-linux-amd64 /usr/local/bin/alinksec-agent

# 从服务端导出 CA，并通过受控渠道复制到每台目标主机。
# docker cp alinksec-server:/app/data/certs/ca.crt ./alinksec-ca.crt
# 安装 + 注册（--server 是服务器地址，注意端口是 9443）
```

### 11.1 上线前备份

首次真机上线前，以及每次升级前，至少备份业务库和 `server-data` 卷。后者包含平台 CA、JWT 密钥（未显式配置时）、特征库和上传的 Agent 物料，丢失后会影响已安装 Agent 的信任链。

```bash
cd ~/alinksec/deploy/docker
mkdir -p ../../backups
stamp=$(date +%F-%H%M%S)

# PostgreSQL 一致性备份（建议用自定义格式，恢复时使用 pg_restore）
docker exec alinksec-pg pg_dump -U alinksec -Fc alinksec > "../../backups/alinksec-${stamp}.dump"

# 服务端持久化数据；保留该文件和 .env 到受控的离线位置
docker run --rm -v alinksec_server-data:/source:ro -v "$(cd ../../backups && pwd)":/backup \
  alpine tar czf "/backup/server-data-${stamp}.tgz" -C /source .
sha256sum "../../backups/alinksec-${stamp}.dump" "../../backups/server-data-${stamp}.tgz"
```

> `vm-data` 是可重建的性能时序数据，按保留期和合规要求另行做卷级备份。不要执行 `docker compose down -v`，该命令会删除所有持久化数据卷。

#### SQLite 轻量模式备份与恢复

维护脚本通过临时 SQLite 工具容器执行 `VACUUM INTO`，因此服务运行中也能得到一致备份；备份默认写入仓库根目录的 `backups/`，可用 `ALINKSEC_BACKUP_DIR` 指向受控的绝对路径。

```bash
cd ~/alinksec
bash deploy/sqlite-maintenance.sh backup
bash deploy/sqlite-maintenance.sh verify <备份文件名.db>

# 恢复会先校验备份并创建 pre-restore 快照，再停 server、恢复并做 integrity_check；失败时自动回滚。
bash deploy/sqlite-maintenance.sh restore <备份文件名.db> --yes
```

必须同时备份 `server-data` 中的证书、JWT 密钥和上传物料。禁止直接复制运行中的主数据库文件，禁止使用 `docker compose -f deploy/docker/docker-compose.lite.yml down -v`。

### 11.2 升级与回滚

`001_init.sql` 仍只用于空库。已有数据卷由一次性 `migrate` 服务读取 `deploy/migrations/V*.sql` 升级；每个成功版本及规范化 SHA-256 会写入 `t_schema_migration`。迁移在事务中执行，失败不会记录版本并会阻止 server 启动；已发布文件校验和变化也会直接失败。

```bash
# 1. 按 11.1 备份数据库和 server-data，并保留旧发布目录与旧 .env
# 2. 将新包解压到新目录，不要覆盖唯一可回滚副本
cd ~/alinksec
unzip -q -o /path/to/alinksec-release.zip

# 3. 从旧 .env 补入新增变量：旧数据库密码继续作为初始化/迁移密码
cd deploy/docker
chmod 600 .env
docker compose config -q
docker compose build

# 4. 只启动数据库并执行迁移；迁移成功前不要启动新 server
docker compose up -d postgres
docker compose up migrate
docker compose ps -a
docker compose logs migrate

# 5. 确认版本记录和关键列，再启动业务
docker exec alinksec-pg psql -U alinksec -d alinksec -c \
  "SELECT version, checksum, applied_at FROM t_schema_migration ORDER BY version;"
docker exec alinksec-pg psql -U alinksec -d alinksec -c \
  "SELECT isolation_status FROM t_agent LIMIT 1;"
docker compose up -d --remove-orphans
docker compose ps
docker compose logs --tail=100 server web
```

`V001` 只做向后兼容的加表/加列和历史脱敏，旧二进制可忽略新增结构；但正式回滚仍以升级前备份为准：停止新 server，恢复 PostgreSQL 备份和匹配的 `server-data`，再从旧发布目录启动。不得手工删除 `t_schema_migration` 记录冒充回滚。恢复后执行登录、主机列表、心跳、指令 ACK 和审计查询冒烟验证。

**环境变量速查**（docker-compose.yml 中按需改）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOST_IP` | 必填 | 服务器 IP（证书 SAN + 特征库下载地址） |
| `ALINKSEC_BIND_ADDRESS` | 必填 | Docker 发布端口绑定的本机 IPv4；禁止 `0.0.0.0`/`::` |

## 12. 常见问题排查表

| 现象 | 原因 | 处置 |
|---|---|---|
| Agent 报 TLS 错误（x509: cannot validate / SAN 不含 IP） | .env 的 HOST_IP 没在**首次启动前**配好，证书 SAN 缺服务器 IP | 核对 `.env` 与现有证书 SAN；确需重置时按 §12.1 操作（CA 重签，**已装 Agent 需重装**） |
| Agent 报 `token 无效` (20001) | 注册码抄错/过期/用尽 | Web「主机管理→+ 安装 Agent」生成新码；或查 `SELECT * FROM t_enroll_token;` |
| Agent 报 `20003 该主机已注册` | machine_id 重复（重装系统不变） | `psqla -c "DELETE FROM t_agent WHERE machine_id='<该机>';"` 后重装；或删目标机工作目录换新码重装 |
| server 容器反复重启：Connection refused | PG 未 ready 就被依赖 / 密码不符 | `docker compose ps` 看 PG 是否 healthy；核对 compose 的 PG_PASSWORD 与 PG 容器环境一致 |
| 注册成功但主通道连不上 | 9443 未放行 / IP 不对 | 服务器 `ss -tlnp \| grep 9443`；目标主机 `telnet <IP> 9443`；防火墙放行 |
| 前端 HTTPS 打不开 | 绑定地址、防火墙或端口占用 | 核对 `ALINKSEC_BIND_ADDRESS` 是本机地址；用 `curl --cacert ./alinksec-ca.crt https://<HOST_IP>:8443/` 自测；查看 web 日志 |
| 前端登录 404/502 | server 未起 / 反代断 | `docker compose logs server`；使用 `https://<HOST_IP>:8443/api/auth/login` 自测反代链路 |
| 登录提示密码错误 | admin 密码已改过/记错 | `psqla -c "SELECT username,status FROM t_user;"` 确认账号状态；密码不可逆（bcrypt），新建账号或重置环境 |
| Agent 心跳 db_version 一直空 | 特征库从未导入 / ALINKSEC_SIG_BASE 错 | 先导入特征库（§9.6①）；检查 Agent 侧能否通过 `https://<HOST_IP>:8443/...` 下载 |
| 特征库导入报「版本已存在」 | 重复导入同版本 | 属正常防重；换新版本号重新打 zip |
| `docker compose build` 失败 | Maven 依赖下载失败或网络受限 | 检查构建日志；镜像已在内部完成 Maven 构建，无需预生成 jar |
| t_agent 一直 status=0 | Agent 只 install 没 run | `systemctl status alinksec-agent`；`journalctl -u alinksec-agent -f` |
| 隔离后主机在平台也失联 | 目标主机无 iptables/权限不足导致放行规则没生效，或 iptables 后端不兼容 | 目标主机 `sudo iptables -L ALINKSEC_ISO -n` 看链内是否有服务器 IP 放行行；应急手动恢复：`sudo iptables -D INPUT -j ALINKSEC_ISO; sudo iptables -D OUTPUT -j ALINKSEC_ISO; sudo iptables -F ALINKSEC_ISO; sudo iptables -X ALINKSEC_ISO` |
| 卸载口令总报「未布防」 | 没在平台点「卸载」就执行 / Agent 不在线没收到布防指令 | 先确认主机在线 → Web 点卸载 → **15 分钟内**执行 |
| Windows Agent 服务起不来 | sc create 的 binPath 路径带空格没引号 | `sc.exe create ... binPath= "\"C:\alinksec\alinksec-agent.exe\" run"` |

### 12.1 接入地址变更后的 TLS 重置

先确认 Agent 使用的接入地址与 `.env` 中的 `HOST_IP` 一致，并检查当前证书 SAN：

```bash
cd ~/alinksec/deploy/docker
docker cp alinksec-server:/app/data/certs/server.crt ./server-before-reset.crt
openssl x509 -in ./server-before-reset.crt -noout -ext subjectAltName
```

只有确认需要重新签发时才继续。先按 §11.1 备份数据库、`server-data` 卷和 `.env`，再把 `.env` 中的 `HOST_IP` 改为真实可达的 IPv4 或 DNS 名称。下列步骤会删除 **整个** `alinksec_server-data` 卷（包括 CA、未显式配置的 JWT 密钥、特征库和上传物料），也会删除共享给 nginx 的旧证书卷。旧 CA 签发的 Agent 证书及信任链随之失效，**所有已安装 Agent 均需重新安装和注册**；数据库中的既有 Agent 记录也需按运维流程处理。

```bash
cd ~/alinksec/deploy/docker
docker compose config -q
docker compose stop web server
docker compose rm -f web server
docker volume rm alinksec_server-data alinksec_web-tls
docker compose up -d
docker compose ps
docker compose logs --tail=100 server web
```

确认新证书 SAN 包含接入地址后，通过新 CA 检查 HTTPS 健康接口，再重新安装 Agent。执行前将 `YOUR_HOST` 换成 `.env` 中的真实接入地址：

```bash
docker cp alinksec-server:/app/data/certs/ca.crt ./alinksec-ca.crt
docker cp alinksec-server:/app/data/certs/server.crt ./server-after-reset.crt
openssl x509 -in ./server-after-reset.crt -noout -ext subjectAltName
curl --fail --cacert ./alinksec-ca.crt https://YOUR_HOST:8443/api/health
```
