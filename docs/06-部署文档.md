# ALinkSec 部署文档（详细版）

> 适用版本：M1-M4 全量功能（含卸载口令防护 / 断网落盘队列 / RBAC 三角色）
> 部署形态：**服务端全家桶 Docker 部署**（PostgreSQL 17 + VictoriaMetrics + 服务端 + 前端 Nginx），**Agent 裸装**到每台目标主机
> 每一步都附【做什么】【为什么】【怎么验证】，照抄命令即可完成部署与联调

---

## 0. 架构总览与端口清单

先建立全局认知，后面每一步都在往这张图里填东西：

```
                        ┌────────────────── 服务器（Docker Compose）──────────────────┐
                        │                                                             │
  浏览器 ──8443──►  nginx(web容器) ──/api/ 反代──► server:8080 (REST + JWT + RBAC)    │
                        │                              │            │                 │
                        │                    PostgreSQL:5432   VictoriaMetrics:8428   │
                        │                      (37张业务表)      (时序指标,90天)       │
                        └─────────────────────────────▲─────────────▲─────────────────┘
                                                      │ gRPC mTLS 双向证书
                                        9443 ──────────┘             │
                                              │                     │
                                    ┌─────────┴─────────┐   ┌───────┴────────┐
                                    │ 目标主机 A (Linux) │   │ 目标主机 B (Win)│
                                    │ alinksec-agent    │   │ alinksec-agent │
                                    └───────────────────┘   └────────────────┘
```

| 端口 | 协议 | 用途 | 谁访问 | 是否放行防火墙 |
|---|---|---|---|---|
| **9443** | gRPC mTLS | Agent 接入（注册/心跳/上报/指令） | 目标主机 | ✅ 必须 |
| **8443** | HTTPS | Web 控制台、API 与 Agent 包下载 | Agent、浏览器 | ✅ 必须 |
| 8081 | HTTP | 仅重定向至 HTTPS | 浏览器 | 可选 |
| 5432 | PostgreSQL | 仅 compose 内网 | server 容器 | ❌ 不暴露 |
| 8428 | VM | 仅 compose 内网 | server 容器 | ❌ 不暴露 |

**组件职责一句话**：
- `postgres`：业务库（主机/资产/基线/漏洞/病毒/告警/审计等 37 张表，SQL 自动初始化）
- `victoriametrics`：Agent 心跳性能指标的时序存储（大屏图表数据源）
- `server`：Java 21 服务端（gRPC 9443 + REST 8080，首次启动自动生成 CA/服务端证书 + admin 账号 + 注册码）
- `web`：Vue3 前端静态资源 + nginx（8443 HTTPS 入口，`/api/` 反代 8080）

## 1. 前置条件

### 1.1 服务器（跑 Docker 的那台）

| 项 | 要求 | 检查命令 |
|---|---|---|
| 操作系统 | Linux x86_64（CentOS 7+/Ubuntu 20.04+ 均可） | `uname -m` → `x86_64` |
| Docker | ≥ 20.10 | `docker -v` |
| docker compose | v2（`docker compose` 子命令形式） | `docker compose version` |
| 内存 | ≥ 4GB（JVM 默认拿 75%） | `free -h` |
| 磁盘 | ≥ 20GB（PG 数据 + VM 90 天指标 + 特征库） | `df -h` |
| 端口 | 9443/8080/8081 未占用 | `ss -tlnp \| grep -E '9443\|8080\|8081'` 应无输出 |

### 1.2 目标主机（装 Agent 的每台）

- Linux x86_64 或 Windows x64（Agent 两种都支持）
- 能访问服务器的 **9443**（gRPC）和 **8443**（HTTPS 下载与控制台）
- Linux 需 `systemd`；Windows 需管理员权限

### 1.3 构建机（你现在的 Windows 开发机）

- JDK 21 + Maven（构建服务端 jar）
- Node.js ≥ 20（仅本地调试用；前端在 Docker 里构建，本机可不装）
- Go ≥ 1.22（交叉编译 Agent）

## 2. 第一步：本机构建发布包

> 【做什么】在 Windows 开发机上产出 `alinksec-release.zip` + Agent 二进制
> 【为什么】服务器不需要装 JDK/Maven/Node/Go，镜像在服务器上由 Docker 构建

### 2.1 构建服务端 jar

```powershell
# 在仓库根目录 d:\项目代码-临时\alinksec 执行
cd server
mvn -q -DskipTests clean package
# -q 只输出错误；clean 清掉旧产物避免缓存干扰
# 成功标志：无 ERROR 输出，且生成下面这个 jar
dir alinksec-bootstrap\target\alinksec-bootstrap-0.1.0-SNAPSHOT.jar
cd ..
```

### 2.2 交叉编译 Agent（Linux 版 + Windows 版各一份）

```powershell
cd agent

# ---- Linux amd64 版 ----
$env:GOOS="linux";   $env:GOARCH="amd64"
go build -trimpath -ldflags "-s -w" -o ..\release-bin\alinksec-agent-linux-amd64 ./cmd/agent
# -trimpath/-s -w：去掉调试信息减小体积（约 10MB）

# ---- Windows amd64 版（如有 Windows 目标主机）----
$env:GOOS="windows"; $env:GOARCH="amd64"
go build -trimpath -ldflags "-s -w" -o ..\release-bin\alinksec-agent-windows-amd64.exe ./cmd/agent

# 还原环境变量（重要！否则后续本机 go 命令会编译出错误平台的包）
$env:GOOS=""; $env:GOARCH=""
cd ..
```

### 2.3 打服务端发布包（jar + 前端源码 + 部署物）

```powershell
# 建立与仓库根同构的发布目录（docker build 的上下文依赖这个层级结构，不能变）
$items = @(
  "server\alinksec-bootstrap\target\alinksec-bootstrap-0.1.0-SNAPSHOT.jar",  # 服务端 jar
  "deploy",                                                                   # sql/ + docker/ 部署物
  "proto"                                                                     # proto（镜像构建不需要，留档备查）
)
foreach ($i in $items) { New-Item -ItemType Directory -Force -Path "release\$i" | Out-Null }
foreach ($i in $items) {
  $dest = "release\$i"
  if (Test-Path $i -PathType Leaf) { Copy-Item $i $dest }        # 单文件直接拷
  else { Copy-Item "$i\*" $dest -Recurse -Force }                # 目录整棵拷
}

# 前端源码（排除 node_modules 和 dist，镜像构建时容器内自己 npm ci + build）
New-Item -ItemType Directory -Force -Path "release\web" | Out-Null
robocopy web release\web /E /XD node_modules dist | Out-Null
# robocopy 退出码 <8 都算成功，PowerShell 不会中断

Compress-Archive -Path release\* -DestinationPath alinksec-release.zip -Force
# 产物：仓库根下 alinksec-release.zip（约几 MB，不含 node_modules）
```

**发布清单自查**：

```
alinksec-release.zip
├── server/alinksec-bootstrap/target/alinksec-bootstrap-0.1.0-SNAPSHOT.jar   ← Dockerfile.server COPY 的路径
├── web/            （package.json + src/ + public/，无 node_modules）
├── deploy/sql/     （001~006 六个 SQL，PG 首启自动执行）
└── deploy/docker/  （docker-compose.yml + Dockerfile×2 + nginx.conf + .env.example）

release-bin/
├── alinksec-agent-linux-amd64        ← 传到每台 Linux 目标主机
└── alinksec-agent-windows-amd64.exe  ← 传到每台 Windows 目标主机
```

> 如果你打算把**整个代码仓库**直接 scp 到服务器也可以（结构天然满足），
> 但建议先删掉 `web/node_modules`、各 `target/`、`tools/` 目录（几百 MB 不必要传输）。

## 4. 第三步：配置 .env（⚠️ 首次启动前必做，改晚要重建）

> 【做什么】把服务器真实 IP 写进 .env
> 【为什么】服务端 **gRPC 证书只在首次启动生成一次**，证书 SAN（可访问主体名单）里必须包含
> 服务器 IP，否则目标主机的 Agent 连 `IP:9443` 时 TLS 校验必失败。
> 证书一旦生成不会自动更新——忘配的后果是删 volume 重来（见 §12 排障表第 1 条）。
> 同时该 IP 也被用作特征库/补丁包下载地址（Agent 走 `https://<HOST_IP>:8443/...` 并校验平台注册 CA）。

```bash
cd ~/alinksec/deploy/docker
cp .env.example .env

# 把 HOST_IP 改成服务器真实 IP（必须是目标主机 ping 得通的那个 IP，不能写 127.0.0.1）
# 查本机 IP：ip addr 或 hostname -I
vim .env
```

`.env` 至少需要以下三项：

```ini
HOST_IP=192.168.1.100    # ← 改成你的服务器 IP
ALINKSEC_BOOTSTRAP_ADMIN_PASSWORD=<至少12位的高强度密码>
ALINKSEC_BOOTSTRAP_ENROLL_TOKEN=ENROLL-<随机字符串>
ALINKSEC_POSTGRES_PASSWORD=<随机数据库密码>
```

## 5. 第四步：构建镜像 + 启动 PostgreSQL

> 【做什么】先只起 PG，验证 37 张表建全了再起业务（分层排障，出问题好定位）

```bash
cd ~/alinksec/deploy/docker

# 构建两个镜像（server 镜像内 Maven 构建；web 镜像内 npm ci + vite build，首次约 3~5 分钟）
docker compose build

# 先只起 PG
docker compose up -d postgres
docker compose ps        # 等 STATUS 变为 (healthy)，约 10~15 秒
```

**验证 ①：容器健康 + 37 张表建全**

```bash
docker exec alinksec-pg pg_isready -U alinksec -d alinksec
# 期望输出：accepting connections

docker exec -it alinksec-pg psql -U alinksec -d alinksec -c "\dt"
# 期望列出 37 张表（t_agent / t_user / t_baseline_* / t_virus_* / t_audit_log 等）
```

精确计数（更快）：

```bash
docker exec -it alinksec-pg psql -U alinksec -d alinksec \
  -c "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
# 期望：37
```

> 表数不符合预期？说明初始化脚本执行中断了，查初始化日志定位：
> `docker logs alinksec-pg` 找 ERROR 行。
> 初始化仅使用 `deploy/sql/001_init.sql`，且只适用于空数据库；修复后应重建数据库卷再执行。

## 6. 第五步：启动服务端 + 前端

```bash
cd ~/alinksec/deploy/docker
docker compose up -d
docker compose ps
# 期望 4 个容器全部 running（postgres 显示 healthy）：
#   alinksec-pg / alinksec-vm / alinksec-server / alinksec-web
```

**验证 ②：服务端启动日志（关键信息都在里面）**

```bash
docker compose logs server | grep -E "gRPC|Bootstrap"
# 期望出现：
#   gRPC 服务已启动: port=9443 (mTLS)
#   Bootstrap administrator created: admin
#   Bootstrap enrollment token created
```

> `ALINKSEC_BOOTSTRAP_ENROLL_TOKEN`（随机 `ENROLL-` 前缀字符串）。服务端不会把这两个敏感值写入日志。

**验证 ③：三个端口在监听**

```bash
ss -tlnp | grep -E '9443|8081|8443'    # 期望三行 LISTEN
```

**验证 ④：证书已生成**

```bash
docker exec alinksec-server ls /app/data/certs
# 期望：ca.crt  ca.key  server.crt  server.key
docker cp alinksec-server:/app/data/certs/ca.crt ./alinksec-ca.crt
```

**验证 ⑤：前端可访问 + REST 反代通**

```bash
# 前端页面（平台 CA 为自签 CA，curl 使用导出的 CA 验证）
curl --cacert ./alinksec-ca.crt -s -o /dev/null -w "%{http_code}\n" https://127.0.0.1:8443/
# 期望：200

# REST API 经 nginx 反代到 server（将下方密码替换为 .env 中配置的初始密码）
curl --cacert ./alinksec-ca.crt -s https://127.0.0.1:8443/api/auth/login -X POST \
  -H "Content-Type: application/json" -d '{"username":"admin","password":"<bootstrap-password>"}'
# 期望返回 JSON 含 "code":0 和 token（说明 nginx→server→PG 整条链路通）
# 404/502 说明反代或服务端没起来 → 查 docker compose logs server / web
```

**验证 ⑥：防火墙放行（联调前必做）**

```bash
# CentOS/RHEL
firewall-cmd --permanent --add-port=9443/tcp --add-port=8443/tcp
firewall-cmd --reload
# Ubuntu/ufw：ufw allow 9443/tcp && ufw allow 8443/tcp
```

## 8. 第七步：目标主机安装 Agent

> Agent 安装三件事：① 拿到注册码 → ② install（写配置 + gRPC 注册 + 领客户端证书）→ ③ run 常驻

### 8.1 Linux 目标主机

```bash
# ---- 上传 alinksec-agent-linux-amd64 到目标主机后 ----
chmod +x alinksec-agent-linux-amd64
sudo mv alinksec-agent-linux-amd64 /usr/local/bin/alinksec-agent

# 从服务端导出 CA，并通过受控渠道复制到每台目标主机。
# docker cp alinksec-server:/app/data/certs/ca.crt ./alinksec-ca.crt
# 安装 + 注册（--server 是服务器地址，注意端口是 9443）
sudo /usr/local/bin/alinksec-agent install \
  --server 192.168.1.100:9443 \
  --token <ALINKSEC_BOOTSTRAP_ENROLL_TOKEN> \
  --ca-file /path/to/alinksec-ca.crt
```

**验证 ⑦：安装成功输出 + 身份文件落盘**

```bash
# 期望输出：
#   安装完成：agent_id=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
#   配置: /var/lib/alinksec-agent/agent.yml

sudo ls /var/lib/alinksec-agent/
# 期望 5 个文件：agent.yml  ca.crt  client.crt  client.key  state.yml
# （client 证书是注册时服务端签发的，mTLS 双向认证的客户端凭证）
```

**验证 ⑧：前台跑通主通道（确认无 TLS/网络问题）**

```bash
sudo /usr/local/bin/alinksec-agent run
# 期望日志依次出现：
#   agent 启动 agent_id=... server=192.168.1.100:9443
#   主通道已建立
#   策略已同步 policy_version=...
# Ctrl+C 退出，进入下一步常驻
```

**验证 ⑨：systemd 常驻**

```bash
sudo tee /etc/systemd/system/alinksec-agent.service <<'EOF'
[Unit]
Description=ALinkSec Agent
After=network-online.target

[Service]
ExecStart=/usr/local/bin/alinksec-agent run
Restart=always          # 崩溃自动拉起
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now alinksec-agent
systemctl status alinksec-agent     # 期望 active (running)
journalctl -u alinksec-agent -f     # 实时看日志（Ctrl+C 退出）
```

### 8.2 Windows 目标主机

管理员 PowerShell：

```powershell
# 假设 exe 已放到 C:\alinksec\alinksec-agent.exe
mkdir C:\alinksec -Force
cd C:\alinksec

# 安装 + 注册（工作目录默认 C:\ProgramData\alinksec-agent）
.\alinksec-agent.exe install --server 192.168.1.100:9443 --token <ALINKSEC_BOOTSTRAP_ENROLL_TOKEN> --ca-file C:\alinksec\ca.crt

sc.exe description alinksec-agent "ALinkSec Agent"
sc.exe start alinksec-agent

sc.exe query alinksec-agent    # 期望 STATE: 4 RUNNING
```

> Windows 防火墙如拦了出站，放行 `C:\alinksec\alinksec-agent.exe` 或放行 9443/8080 出站。

## 9. 第八步：端到端联调验证（按域逐个打通）

> 统一约定：涉及 SQL 的都在**服务器**上执行。先设个别名少打字：

```bash
alias psqla='docker exec -it alinksec-pg psql -U alinksec -d alinksec'
```

### 9.1 注册与心跳（M1 链路）

```sql
-- 注册落库：1 行，hostname/ip 为目标主机真实值
SELECT agent_id, hostname, ip, os_type, status FROM t_agent;

-- 心跳在线：status=1，age 持续 < 15s（隔 30s 再查一次应刷新）
SELECT agent_id, status, agent_version, policy_version, last_heartbeat,
       now() - last_heartbeat AS age FROM t_agent;
```

Web 验证：控制台「主机管理」→ 该主机状态绿点「在线」。

### 9.2 资产采集

```sql
-- 30 秒后查三类资产（行列数 > 0 即通）
SELECT '软件' t, count(*) FROM t_asset_software
UNION ALL SELECT '端口', count(*) FROM t_asset_port
UNION ALL SELECT '账户', count(*) FROM t_asset_account;
```

### 9.3 性能指标（大屏图表）

```bash
# Agent 心跳指标写入 VictoriaMetrics（指标名前缀 alinksec_）
curl -s "http://127.0.0.1:8428/api/v1/query?query=alinksec_cpu_usage" | head -c 300
```

### 9.6 病毒查杀 + 特征库热更新（M4 核心链路）

**① 导入特征库**（zip 格式：`manifest.json` + `hashes.txt`，打包示意）：

```bash
# manifest.json 示例内容：
# { "db_version": "v2026.08.26", "hash_count": 2, "rule_count": 1, "sha256": "" }
# hashes.txt 示例内容（sha256 大写 + 文件路径，空格分隔）：
# 44D6B4F8...C1A3  C:/Windows/System32/evil1.exe
# 9F2E77A0...B4D2  /tmp/evil2.sh

zip virusdb-v2026.08.26.zip manifest.json hashes.txt
```

Web：病毒查杀 → 特征库页签 → **导入** → 选 zip → 提示成功并自动推送全部 Agent。

```sql
SELECT db_version, hash_count, rule_count, imported_at FROM t_virus_db ORDER BY id DESC;
```

**② 验证 Agent 已拉到特征库**：

```sql
-- 心跳会带上 db_version；等一个心跳周期（≤60s）后：
SELECT agent_id, db_version FROM t_agent;
-- 期望 db_version = v2026.08.26（说明：心跳比对→指令下发→Agent 下载安装 全链路通）
```

目标主机侧可查特征库落盘：`sudo ls /var/lib/alinksec-agent/signature/`

**③ 下发扫描任务**：Web 病毒查杀 → 新建任务（快速模式）→ 完成。

### 9.7 主机隔离 / 解除隔离

Web：主机管理 → 目标主机行 → **隔离** → 确认。

```sql
-- 隔离指令的 ACK 闭环
SELECT type, status, result FROM t_command
 WHERE type='protect_action' ORDER BY id DESC LIMIT 1;
-- 期望 status=4（已完成），result 含 "host isolated"
```

目标主机验证网络隔离效果（隔离语义：阻断业务网卡，仅保留 Agent↔平台通道）：
```bash

```
回 Web 点「解除」恢复，再 ping 验证恢复。

### 9.8 卸载口令防护（防恶意卸载）

**正向链路**（平台布防 → 主机消费）：

1. Web：主机管理 → 目标主机行 → **卸载** → 弹窗显示 16 进制口令 + 用法（15 分钟有效、一次性）
2. 15 分钟内在目标主机执行：

```bash
sudo /usr/local/bin/alinksec-agent uninstall --token <弹窗里的口令>
# 期望：卸载完成（自动停服务、清 /var/lib/alinksec-agent、删自身二进制）
```

**防护验证**（没口令 / 错口令 / 过期口令都拒）：

```bash
sudo /usr/local/bin/alinksec-agent uninstall --token deadbeef
# 期望：ERROR: 卸载口令不匹配（或：未布防卸载口令 / 已过期）
```

> 卸载后该主机 Agent 消失（心跳超时后转离线）；重装需重新生成注册码走 §8。

## 12. 常见问题排查表

| 现象 | 原因 | 处置 |
|---|---|---|
| Agent 报 TLS 错误（x509: cannot validate / SAN 不含 IP） | .env 的 HOST_IP 没在**首次启动前**配好，证书 SAN 缺服务器 IP | `docker compose down server && docker volume rm alinksec_server-data && docker compose up -d server`（CA 重签，**已装 Agent 需重装**） |
| Agent 报 `token 无效` (20001) | 注册码抄错/过期/用尽 | Web「主机管理→+ 安装 Agent」生成新码；或查 `SELECT * FROM t_enroll_token;` |
| Agent 报 `20003 该主机已注册` | machine_id 重复（重装系统不变） | `psqla -c "DELETE FROM t_agent WHERE machine_id='<该机>';"` 后重装；或删目标机工作目录换新码重装 |
| server 容器反复重启：Connection refused | PG 未 ready 就被依赖 / 密码不符 | `docker compose ps` 看 PG 是否 healthy；核对 compose 的 PG_PASSWORD 与 PG 容器环境一致 |
| 注册成功但主通道连不上 | 9443 未放行 / IP 不对 | 服务器 `ss -tlnp \| grep 9443`；目标主机 `telnet <IP> 9443`；防火墙放行 |
| 前端 8081 打不开 | 防火墙/端口占用 | `curl 127.0.0.1:8081` 本机自测；`docker compose logs web` |
| 前端登录 404/502 | server 未起 / 反代断 | `docker compose logs server`；`curl 127.0.0.1:8081/api/auth/login -X POST ...` 自测反代链路 |
| 登录提示密码错误 | admin 密码已改过/记错 | `psqla -c "SELECT username,status FROM t_user;"` 确认账号状态；密码不可逆（bcrypt），新建账号或重置环境 |
| Agent 心跳 db_version 一直空 | 特征库从未导入 / ALINKSEC_SIG_BASE 错 | 先导入特征库（§9.6①）；检查 Agent 侧能否通过 `https://<HOST_IP>:8443/...` 下载 |
| 特征库导入报「版本已存在」 | 重复导入同版本 | 属正常防重；换新版本号重新打 zip |
| `docker compose build` 失败 | Maven 依赖下载失败或网络受限 | 检查构建日志；镜像已在内部完成 Maven 构建，无需预生成 jar |
| t_agent 一直 status=0 | Agent 只 install 没 run | `systemctl status alinksec-agent`；`journalctl -u alinksec-agent -f` |
| 隔离后主机在平台也失联 | 目标主机无 iptables/权限不足导致放行规则没生效，或 iptables 后端不兼容 | 目标主机 `sudo iptables -L ALINKSEC_ISO -n` 看链内是否有服务器 IP 放行行；应急手动恢复：`sudo iptables -D INPUT -j ALINKSEC_ISO; sudo iptables -D OUTPUT -j ALINKSEC_ISO; sudo iptables -F ALINKSEC_ISO; sudo iptables -X ALINKSEC_ISO` |
| 卸载口令总报「未布防」 | 没在平台点「卸载」就执行 / Agent 不在线没收到布防指令 | 先确认主机在线 → Web 点卸载 → **15 分钟内**执行 |
| Windows Agent 服务起不来 | sc create 的 binPath 路径带空格没引号 | `sc.exe create ... binPath= "\"C:\alinksec\alinksec-agent.exe\" run"` |
| 磁盘涨得快 | VM 90 天保留 + 审计/上报增长 | 正常；可下调 `-retentionPeriod`（compose 里 victoriametrics 命令）后 `docker compose up -d victoriametrics` |
