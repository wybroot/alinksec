# Linux 弱口令字典检测与覆盖证据

本模块对 Linux 本地 `/etc/passwd` 与 `/etc/shadow` 做有限字典的离线哈希比对。无在线登录、网络探测、口令修改或自动账户处置。完成仅代表本次支持范围和预算内的核对，未命中不代表口令安全，也不证明某账户能通过 PAM、SSH 或其他服务认证。LDAP、AD、NIS 等外部身份源不在范围内；Windows 返回未支持。

## 字典和算法

内置 `linux-common-v1` 含 100 个固定候选，源码为 `agent/internal/scan/dictionary.go`，不是统计排名。当前字典 SHA256 为 `53fc7bc25cc081fa37e598afbde408f68b066d5dc139e16fa31c7c9ce9640a40`。任务固定版本；Agent 拒绝不匹配版本。字典不经策略任意替换，更新须改版本并重新验收。

| 哈希 | 当前支持范围 |
|---|---|
| MD5 crypt `$1$` | 标准盐与摘要格式，盐最多 8 字符 |
| SHA-256/SHA-512 crypt `$5$` / `$6$` | 隐式 5000 轮，或显式 1000–100000 轮；盐最多 16 字符 |
| bcrypt `$2a$` / `$2b$` / `$2y$` | 成本 4–10，固定编码长度 |
| yescrypt `$y$` | 仅 `j9T` 参数（N=4096、r=32、p=1，约 16 MiB 工作区） |

其余算法、成本参数及超出成本上限的记录计入未支持；异常哈希计入失败，均不能形成完整核对结论。算法使用固定版本的 [go-crypt](https://github.com/sergeymakinen/go-crypt/tree/v1.0.3) 与 [Openwall yescrypt-go](https://github.com/openwall/yescrypt-go/tree/25b8ddb667c08550c094763c9c7e1cef6d9138ed)，不自行重写密码算法。

## 身份文件和资源边界

固定读取本地两个身份文件，打开时拒绝符号链接、FIFO、设备和非 root 所有或组/其他可写文件；每文件最多 4 MiB，每行最多 8192 字节，最多 4096 账户。必须完整解析、无重复账户，passwd 使用 shadow 占位且两份账户清单一致，否则失败。空 shell 按潜在本地登录账户核对；已知 nologin/false/sync shell 排除，不把其余 shell 当作已验证的登录入口。

锁定字段（`!` 或 `*` 开头）排除，不尝试去除锁定前缀。空口令计为已检查并保留风险；具有 UID=0 的非 root 账户和超 90 天未修改口令的参考风险继续保留，但均不自动证明认证或提权可行。

扫描单线程执行，与采集、基线和病毒扫描共用一个批处理槽。每次最多 10000 次候选比对，总期限 2 分钟；每次算法调用前检查成本与期限，算法调用本身不可中途取消。真实命令按计算耗时额外等待，并接入资源反馈间隔；心跳、隔离租约和保护事件继续独立处理。Go 内存目标及现有资源反馈仍生效，操作系统资源硬上限仍需部署方配置。

扫描结束重新读取两份身份文件；内容变化或重新读取失败会丢弃本次发现并标记失败。此为两次文件快照的一致性检查，不承诺检测期间所有瞬时变更，亦不建立 NSS 或真实认证事务。不会为扩大覆盖尝试读取其他凭据源。

## 报告、任务和界面

新指令及结果使用扫描契约 1，结果绑定任务主机成员与派发指令编号。任务创建时对 Linux/Agent 能力做逐主机判断，未支持目标记为未覆盖且不下发该目标的 Agent 扫描；混合任务中其余目标继续。只选端口识别时不要求 Linux 弱口令能力。重新连接会重建能力，派发前复核，避免降级 Agent 沿用旧能力。

`complete`、`partial`、`failed`、`unsupported` 与 `not_requested` 各自表示有限核对完成、覆盖不完整、检测失败、未支持、未请求。报告记录字典版本和摘要、总账户、已检查、排除、未支持、失败、实际候选次数、耗时及固定原因码。达到预算不会作为成功；读取失败不会变为零发现通过。

首次结果（包括零发现）不可被重放覆盖；进度按终态主机数量精确计算，外部主机或错误指令结果不产生发现。并发接受以任务行锁排序。失败 ACK 只影响对应任务成员，全部成员结束后汇总；超时后结果可补充历史证据并标为晚到，不能重开已结束任务。

旧 Agent 缺失指令编号的报告，仅允许把其自身已派发且待处理的任务成员记为未支持失败，不接受发现或通过结论；该安全回执同样不可被后续报告覆盖。显式携带错误指令编号的报告直接拒绝。

口令明文和 shadow 哈希不会由新 Agent 写入报告、离线队列或日志。服务端忽略旧协议遗留 password 字段，只以固定安全说明落库；证据仅序列化明确选定字段。V019 清空历史发现的 remark，避免继续展示旧口令或不明内容，原发现记录仍保留。此不追溯删除部署方已有备份或日志。

漏洞页“弱口令”提供逐主机覆盖、人工刷新、失败重试、详情和手机宽度对话框，并将历史风险发现标明为历史信息。覆盖读取 API 为 `/api/vuln/scan-coverage`，沿用认证读取权限；扫描写入沿用管理员/运维权限。无发现与覆盖完成分别展示，不推断历史风险已修复。

## 验证范围

本地有界测试覆盖字典命中、错口令、锁定排除、空口令、未知算法、成本拒绝、取消、重复账户、格式异常、符号链接/FIFO/权限及身份文件变化。原生验收从系统 libcrypt 独立生成五类公开测试哈希，核对正确/错误候选及完整扫描路径，只操作临时合成身份文件，不修改真实账户。

数据库验证覆盖首次/零发现不可覆盖、凭据字段不落库、错误主机/指令、混合未支持主机、预算失败、晚到证据及并发重复结果。CI 在独立 amd64/arm64 Linux runner 执行原生对照和生产页面验证，在 Windows 验证未支持边界，在 PostgreSQL 应用角色与 SQLite 验证任务契约。

实现 `779d07f4faba0024cd89c96fa2875d1c7d8f0f87` 的 [CI39093209101](https://github.com/wybroot/alinksec/actions/runs/39093209101) 四作业全部通过。两种 Linux 架构各五类原生哈希对照与五项生产页面检查、三平台配置/升级/隔离/资源回归各 13/7/11/8 项，以及双数据库完整维护恢复产物均已下载验收；桌面及手机截图已实看。PostgreSQL 应用角色下 83 项集成测试通过，含 11 项弱口令测试。

本地 Agent 全包、扫描与通信 race、libcrypt 原生对照、22 项 SQLite 与四项连接注册测试、十项前端单元检查通过；与最终生产源码一致的 CI 页面在本机通过五项浏览器检查。升级稳定窗口测试夹具采用单一时间基准，并覆盖恰好五秒和少一纳秒边界，相关回归连续 1000 次通过。合并后源码及检查核对记录见 [PR #12](https://github.com/wybroot/alinksec/pull/12)。
