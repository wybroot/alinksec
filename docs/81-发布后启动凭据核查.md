# 发布后启动凭据核查

本轮在 v0.0.3 发布之后复查首次启动与备份恢复链路。以下为 main 的源码修正，未重新发布或替换 v0.0.3 标签、附件及镜像；正式产物仍以 [Release](https://github.com/wybroot/alinksec/releases/tag/v0.0.3) 和清单为准。

## 已复现的问题与修正

| 场景 | 原行为 | 修正后 |
| --- | --- | --- |
| 证书目录为 `certs` 等单段相对路径 | JWT 初始化取不到父目录，启动空指针 | 按绝对路径确定 JWT 文件位置；隔离子进程验证首次生成和重启复用 |
| 已有 `jwt.secret` 为空或仅含空白 | 初始化成功，后续登录签名失败 | 初始化报 `jwt_secret_empty`，保留原文件，等待恢复有效密钥 |
| `ca.crt` 与 `ca.key` 来自不同部署 | 初始化成功，后续签发的 Agent 证书无法用配置 CA 公钥验证 | 加载时对实际私钥签名和 CA 公钥验签，不匹配则阻止启动 |
| 恢复的 CA 对与现有 `server.crt` 不匹配 | 初始化成功，平台与 Agent 的信任链不一致 | 加载时验证服务端证书签名，不属于当前 CA 则阻止启动 |

凭据不匹配时，在复制材料到 Web TLS 目录、签发新 Agent 证书之前失败。不会自动重新生成或轮换已有 CA、JWT 及其他备份材料。处置应核对同一部署的成套备份和恢复记录，见[部署维护与成套恢复](54-部署维护与成套恢复.md)。

环境变量 `ALINKSEC_JWT_SECRET` 仍优先于文件；已有单机环境变量配置的兼容行为保留。集群模式仍要求预置共享 JWT／PKI，不在各副本首次启动时生成。CA 的 PKCS#8 及已有 EC PEM 格式继续支持。

## 验证范围

针对实际生产类增加行为回归：旧源码运行 9 项测试时 5 项通过、上述 4 项失败；修正后同一组 9 项全部通过。测试使用真实本地文件系统与 EC 签名／证书验证，包含正常重启、环境变量优先级、集群不自动生成、旧格式 CA 与已签发客户端证书验证，以及错误恢复时原材料字节保持不变。

单段相对路径在独立临时工作目录的真实 Java 子进程中验证，避免依赖测试进程当前目录。异常场景只使用临时生成的测试凭据，不读取或修改现有服务卷。

这些检查验证启动材料一致性，不构成生产恢复或真机稳定性验收。第 25／26／27 项现场待办仍按[交付清单](80-发版准备与现场交付.md)后续执行。
