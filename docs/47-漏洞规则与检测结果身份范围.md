# 漏洞规则与检测结果身份范围

在 `vulnerability-applicability` 分支，将[资产身份与采集证据](46-软件包身份与采集完整性.md)用于规则匹配、检测记录和漏洞列表。整个漏洞模块仍在开发中。

## 规则声明

RPM/DPKG 包规则必须同时声明 `source`、同名的 `version_scheme`、`distro_id`、`distro_version` 和 `architecture`。软件名精确匹配并区分大小写；导入时没有 `match` 的规则补为 `exact`，原生包不接受子串匹配。发行版ID和版本逐字相等，不从显示名称、发行版家族或主机编译架构补猜身份。

```json
{
  "name": "fixture-package",
  "match": "exact",
  "source": "dpkg",
  "version_scheme": "dpkg",
  "distro_id": "ubuntu",
  "distro_version": "24.04",
  "architecture": "amd64",
  "ranges": [">=1.0-1", "<2.0-1"],
  "fixed_version": "2.0-1"
}
```

这是字段示例，版本与范围来自导入者声明，不能据此证明厂商已确认该 CVE 或修复。架构可以显式声明 `*`，表示该规则覆盖所有已知包架构；缺失架构不能借通配通过。发行版和版本不支持通配；`all`、`noarch`、`amd64`、`x86_64` 等保持各包数据库的字面值。

不完整原生范围可以保留为库元数据，但不会生成原生包漏洞记录，新导入的 `matchable` 为0。历史数据库规则在运行时接受相同约束，不自动补填范围。NVD上游范围仍不能应用到发行版包版本。注册表应用保留既有名称/版本匹配；声明了身份约束的规则必须有对应采集证据，未知Windows应用架构不被推断为通配命中。

## 结果与历史

V009 在 SQLite/PostgreSQL 为检测结果增加来源、包架构、发行版、系统和身份状态。新记录保存匹配时身份，查询不从当前主机信息回填。历史记录默认 `legacy`，需要重新扫描；历史忽略、已修复及待审批引用保持原ID和状态。

忽略、已修复或待执行引用只抑制同一 CVE、包名、安装版本、来源、架构、发行版和系统身份的重复结果。另一个架构、安装版本或发行版不会被遮住。多个规则命中同一身份只生成一条记录；修复版本声明不一致时结果不提供自动修复版本。

## 查询、展示与修复

列表按 CVE、包名、已安装/修复版本以及匹配时完整身份聚合，读取全部分页，重复记录去重，主机按 Agent ID计数。页面展示发行版、来源和包架构；历史结果、库存失败、资产身份已变化和缺修复版本的项不进入修复提交集合。统计中的软件排行也保留身份维度。

服务端创建任务时独立核对检测记录保存的身份与当前完整库存；审批或维护窗口派发时再检查检测记录、当前资产和已保存目标，结果被处置、目标或身份变化均阻断派发。历史finding不能借新库存取得自动修复资格。当前安装仍必须是唯一的同名记录；检测能区分多架构，但按包名执行的Agent安装链尚不能自动修复这类歧义。

厂商来源和回移证据、确认修复版本、真实补丁内部发行版/架构元数据、历史规则迁移、Agent安装前后复核、审批权限和并发派发仍在后续阶段。因此本阶段的范围匹配和库存对应关系不证明补丁内容适用性。

## 验证

- 规则单元测试覆盖发行版、版本、来源、架构、显式架构通配、未知身份、大小写和原生版本范围。
- 真实SQLite事务测试覆盖分架构保留决定、历史未知结果、重叠/冲突规则、查询身份不回填、任务创建及派发时finding身份/目标变化。
- 迁移回归保留旧finding状态与未知身份；真实SQLite恢复及生产镜像重启采用V009。
- 浏览器使用生产bundle与合成API验证范围展示、主机去重、历史/歧义阻断与对话框身份；真实Nginx/API浏览器验证历史拒绝和带身份的单项/批量任务。
- 实际Agent采集后，通过服务端扫描生成作用域明确的finding，再审批安装并回写漏洞状态。Linux amd64/arm64、Windows及PostgreSQL由对应CI runner验证。

本阶段验收以最终提交的完整CI及独立证据目录为准，不将历史CI或未完成本机检查计为本批成功。
