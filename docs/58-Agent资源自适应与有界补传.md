# Agent 资源自适应与有界补传

本模块覆盖 Linux amd64/arm64 与 Windows amd64 的 Agent 进程资源反馈。它调节可延后的资产、主机指标采集和主动病毒扫描读取，不是 CPU 配额、进程 RSS 硬上限或全主机压力调度器。常驻 RSS <100MiB、扫描峰值 <250MiB 和参考机平均 CPU 指标仍须在第 26 项规模与长稳性能验收中实测。

## 反馈与恢复

每 10 秒通过原生进程接口读取累计用户态/内核态 CPU 时间及 RSS。CPU 百分比按一个逻辑核计算，100% 表示占满一个核，不除以主机核数，不包含子进程。首次采样或计数中断时 CPU 未知；对应 CPU 指标不发布，不能用零冒充实测。

默认 CPU 连续 5 分钟高于 3% 后，退避倍率依次为 2、4、8；每再持续一个窗口升一级。RSS 达到 100MiB 时立即进入 8 倍退避，主动病毒扫描执行期间使用 250MiB 阈值，结束后恢复常驻阈值。RSS 触发时释放最多两个 64KiB 读取缓冲并请求 Go 回收/归还可释放内存，每分钟最多一次。策略、特征库、检测基线、指令去重和离线安全事件不会为回收而清除。

CPU 不高于阈值的 80%，且 RSS 低于当前阈值的 80%，共同持续 2 分钟后，倍率逐级减半直至正常。RSS 高、采样错误、时间间隔超过 30 秒、时间倒退或 CPU 计数重置会中断连续窗口。采样失败至少进入 2 倍保守退避；恢复采样后须重新积累恢复窗口。

运行时将 Go 内存软目标收紧到常驻 RSS 阈值的 70%，保留已有更低的 `GOMEMLIMIT`。主动扫描不抬高软目标。Go 软目标不能约束文件映射、所有系统分配或不可回收的活对象；持续高 RSS 会持续显示在指标中，不会通过退出、重启或清空安全状态掩盖。

## 调整范围

- 周期资产采集及其最小间隔乘以退避倍率；已有暂停采集命令继续生效。忙时自动采集稍后重试。显式即时采集异步执行并受共同名额限制，不等待周期定时器。
- 主机指标快组/慢组的 10 秒/60 秒间隔乘以倍率。资源自检仍每 10 秒采样。
- 资产采集、基线核查、安全扫描、主动病毒扫描共用一个批量执行名额。并发扫描命令明确返回忙，不积累无界任务；本地防护、修复处置、隔离、策略接收和升级健康确认不等待该名额。
- 主动病毒扫描各模式的源文件读取共用一个速率控制器，默认上限 10MiB/s，随倍率下降到 5、2.5、1.25MiB/s。目录/路径访问也计入小额预算，文件之间没有突发额度。等待可取消，计入原有任务时限；耗尽预算返回不完整覆盖证据，不报告完整扫描成功。

心跳、配置恢复、主机隔离租约和本地响应不主动降频。周期病毒检测保留原有单文件 2 秒/20MiB 与窗口预算；签名下载、解压、隔离复制、包管理器及外部基线命令不受源文件读取速率控制。上述路径和操作系统文件访问仍可能产生资源峰值，模块没有宣称整机 I/O 硬配额。

忙时失败回执会立即将相应基线/安全扫描任务标为部分失败，保留既有结果和进度，不再等待 30 分钟超时。只接受绑定当前认证主机、持久指令和任务范围的失败；已完成或已取消的任务不回退。病毒任务沿用既有逐主机失败汇总。

## 离线队列和长连接

生产补传每次只读取一条 JSONL（最多 4MiB），发送成功后推进内存游标，循环让出控制定时器。失败保留磁盘记录；进程重启可能重发上次压缩前已经发送的记录，沿用稳定 report ID 和服务端幂等语义，不保证恰好一次。队列清理通过两遍流式处理保留有效数据，不将整个 500MiB 队列加载到内存。过期/容量淘汰沿用 24 小时/500MiB 环形预算；一个正在发送的记录期间延后压缩，以保持字节游标有效。单条 JSON 解析仍可能产生大于编码长度的临时分配。

配置、升级、隔离的长连接“已发送”记录只保留仍在相应持久结果中的身份。历史结果淘汰时同步删除内存身份；重连仍重放有界持久结果，稳定报告 ID 不变。

## 配置和可见性

以下均为本地可信配置，继承配置防篡改保护；合法改配使用停服务后的 `config apply`，不接受影子 YAML 或未认证的资源策略覆盖。

```yaml
resources:
  cpu_percent: 3
  cpu_window: 5m
  recovery_window: 2m
  rss_mib: 100
  scan_rss_mib: 250
  scan_mib_per_sec: 10
```

CPU 范围 1–25%，窗口 10 秒–30 分钟，常驻 RSS 32–250MiB，扫描 RSS 从常驻阈值至 500MiB，读取速率 1–10MiB/s。缺省或零使用默认值；负值、未知字段、非有限浮点数与越界值拒绝加载。不存在关闭资源保护的开关。

状态变化使用 `self_defense` / `agent-resources` 安全事件，包含倍率、原因、采样有效性、CPU 单核口径、RSS 和扫描状态。断网经现有队列保全。指标为 `alinksec_agent_resource_factor`、`alinksec_agent_resource_sampling_ok`、`alinksec_agent_rss_bytes` 和计数连续时的 `alinksec_agent_cpu_percent_single_core`；指标沿用可丢弃语义。

## 验收方法

确定性测试覆盖连续窗口、瞬时峰值、逐级恢复、采样失败/重置/停顿、扫描 RSS 阈值、回收限频、共享限速取消、忙任务拒绝、心跳独立、离线事件、逐条补传和流式队列清理。Linux 在资源 watchdog 下串行执行全量 Go 测试与相关 race 检查。

CI 在 Linux amd64、Linux arm64、Windows amd64 分别执行 `TestNativeResourceFeedback`，以原生测试进程中的实际 CPU 工作负载、空闲恢复、驻留内存和 I/O 等待产生 `resource-validation-*` 证据。此证据明确标记测试进程范围；现有 systemd/SCM 原生服务、配置防篡改、隔离和升级验收继续验证真实 Agent 服务，不能把合成状态测试等同于生产长稳性能结果。
