# 旧 Linux 基线内容审核与迁移

审核覆盖旧 `DJBH2.0-LINUX` 全部60项。旧定义存在错误传播、历史编码损坏和观察范围过度声明，不能继续作为默认通用合规结论。`V006__retire_legacy_baseline.sql`停用旧模板与检查项、清除旧自动修复、修正当前名称和人工说明，保留旧迁移、任务快照、指令及结果；用户自建模板不受影响。V007追加日志最终目标类型和数值属主检查。当前通用审核参考包为不可变版本20，各产品检查使用独立候选。

审核记录与确切定义在[reviewed-linux-definitions.json](../deploy/baseline/reviewed-linux-definitions.json)。8项提供通用只读观测，40项进入明确产品范围的独立候选，12项尚未实现。通用包仍列出52项未包含规则；各包未支持项不进入下发项与得分分母。源码审核、协议夹具和工具查询均不代表主机通过完整等保、CIS或STIG标准。逐项范围见下表。

截至2026-10-10，旧60项累计48项具有限定范围实现、12项未支持；新增0036/0038独立IPv4主机候选，必须具有可信本机非路由/对称路由声明。通用review版本20仍8项/52排除，其中40项指向独立候选。下文此前批次的数量描述记录各批当时状态，当前范围以本段及[IPv4核查](39-IPv4主机角色与全部接口当前参考核查.md)为准。

## 使用新的候选

默认基础包升级为不可变版本 `2`：Linux 为四项当前内核参数观测，不再把所有主机当作非路由主机；Windows 保留四项原生观察，防火墙查询要求三个配置实际存在。新范围排除空版本、unknown 和其他未覆盖产品。Linux 参考范围为 Ubuntu 22.04/24.04、Debian 12/13、RHEL/Rocky 9；Windows 为 10/11 与 Server 2019/2022/2025。版本文本使用 Agent 实际上报格式。这是候选的匹配范围，仍需在具体版本与组件上完成管理员测试，不能把 CI 平台测试扩大成全版本原生认证。

旧 60 项的审核候选另外构建：

```bash
python3 -B deploy/baseline/build-package.py \
  --definitions deploy/baseline/reviewed-linux-definitions.json --platform linux \
  --output-dir .tmp/reviewed-linux-candidate
```

也可导入版本 20 的 [审核候选包](../deploy/baseline/packages/reviewed/linux-baseline.json)。它要求 GNU stat、procps sysctl、util-linux findmnt、IPv6 参数和 `/var/log/messages` 路径，**不是所有上述发行版的默认配置都具备这些组件**。例如未配置 messages 日志路径的主机不具备此项条件；不具备条件的主机将返回执行异常并阻止发布，必须准备相应产品的候选子集和新版本，不得用默认值代替失败。候选不自动导入、启用或发布；管理员确认范围，明确审核、选主机测试、评估证据后发布，参见 [模板流程](18-基线模板审核与系统适配.md)。

移除的旧 Shell 选择器在新版 Agent 和服务端都拒绝执行；下发前、审核和发布时按当前策略重新校验，旧的成功测试不能恢复已移除选择器。必须更新两端，并用新候选版本重新测试；不能继续依赖旧 Agent 的危险查询实现。

`/tmp` 使用 `findmnt --target` 查询当前挂载命名空间，包含覆盖该目录的父挂载。叠加挂载可能返回多条记录，检查要求每条记录都有独立的 nosuid 和 nodev 选项；旧记录未满足时保守判为未满足，管理员查看完整实测值确认。单独一个选项、相似字符串或只满足一条记录均不通过；查询失败保持执行异常。该规则不证明独立分区、noexec 或临时文件清理。

## 来源与验证边界

内核参数含义和 all/default/接口差异依据 [Linux 内核 IP sysctl 文档](https://www.kernel.org/doc/html/latest/networking/ip-sysctl.html)；挂载查询依据 [util-linux findmnt 手册源文件](https://github.com/util-linux/util-linux/blob/master/misc-utils/findmnt.8.adoc)；属主观察依据 [GNU coreutils 手册源文件](https://github.com/coreutils/coreutils/blob/master/doc/coreutils.texi)。这些文档用于确定观察含义，检查阈值是本项目的参考策略，并非上游认证要求。

PAM 与 SSH 的未支持原因依据 [Linux-PAM faillock 文档](https://github.com/linux-pam/linux-pam/blob/master/modules/pam_faillock/pam_faillock.8.xml)和 [OpenSSH 配置手册](https://man.openbsd.org/sshd_config)中的配置链与适用条件；匹配单个文本不能替代实际生效判断。其余未支持规则的原因来自对本项目旧定义的源码审核，尚未提供对应产品的原生有效策略解释器。

Windows 检查依据 Microsoft 的 [Get-NetFirewallProfile](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallprofile)、[Get-MpComputerStatus](https://learn.microsoft.com/en-us/powershell/module/defender/get-mpcomputerstatus)、[Get-Service](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-service)及 [UAC 设置说明](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/settings-and-configuration)。UAC 注册表值不代表所有配置已生效；EventLog 运行不代表完整审计策略。
