## 除代码缺陷外的生产准入缺口

以下为能力边界或尚缺证据的事项，不全部等同于新增程序缺陷；应按实际部署范围判定。

### 1. 目标系统和主动防护的业务兼容性

现场应明确操作系统、内核、架构、现有安全软件及实际启用功能。需要真实业务负载下的误报、误封和资源影响验证，尤其文件自动恢复、进程终止、文件隔离、主机隔离和补丁安装。测试应先覆盖监测和证据链，再在可恢复的专用主机上逐项验证主动动作与撤销。

只部署已验证的某一 Linux 范围时，其他 Windows 或国产系统待验收不必阻塞该限定范围；也不能因此宣称那些系统已通过。

### 2. 真实规模、长期稳定性和容量

当前短时模拟负载只能支撑已记录的范围。生产前应针对预计主机数、资产规模、日志量、指标量和动作频率进行持续验证，记录内存、CPU、磁盘增长、积压、丢弃、重连、执行失败及尾部延迟。

若按项目既定“200 台真实主机／72 小时”和指标时延目标交付，须完成相应现场项目；若先做更小规模试点，应单独声明主机数、时长和支持功能，不能将 F26 项改记为通过。不能简单要求所有小规模测试都先达到 200 台，也不能用小规模结果反向证明大规模可用。

长期运维还需给审计、告警、任务和运行日志分别制定容量、归档及保留策略；不能从原始日志已有保留机制推断所有数据都自动有界。标准 Compose 与宿主机的资源和日志轮转配置也应按现场容量核验。

### 3. 灾备与冷恢复

[维护说明](54-部署维护与成套恢复.md) 和 [operations.py](../deploy/operations.py) 明确约束：普通 `restore` 会先执行 `preflight()`，要求应用容器运行并通过健康检查，快照还绑定原 Docker engine、卷、镜像和配置。应用已经无法启动或整台宿主丢失时，不能直接依靠该入口完成恢复。

生产前应为实际故障模型准备并演练可执行的恢复方案：数据库损坏／应用无法启动、宿主丢失、身份材料丢失、恢复后 Agent 继续连接。可以是经验证的独立离线流程，不强制所有能力都写入现有工具，但不能只提供“已有备份文件”的证明。记录允许丢失多久的数据（RPO）及最长恢复时间（RTO），并用实测核对。

现有快照不包含 VictoriaMetrics 时序卷或 PostgreSQL 集群全局角色；指标历史是否需要恢复、这些材料如何备份和恢复应明确。自动检查点会暂停应用，备份频率与停机预算也要匹配。

### 4. 集群与故障切换范围

[集群示例](../deploy/cluster/README.md) 的两个副本处于同一宿主，单入口、单 Web 以及外部数据库、Redis、RabbitMQ、POSIX 共享存储仍需现场设计。需要主机级 HA 时，必须验证相应依赖、入口和共享存储故障切换，不能只测试杀掉一个 Java 进程。

当前集群配置摘要不支持任意直接变更，PKI、JWT、依赖地址或业务配置变更需要专项离线迁移方案；混合版本滚动更新也未作承诺。生产运维必须知道允许停机多久、怎样轮换凭据及怎样回退。单实例部署不必为了测试强行引入集群，但应明确接受的停机边界。

### 5. 实际通知、情报源和扫描引擎

只验收实际启用的依赖。默认静态 Agent 不包含原生 YARA，ClamAV 需要本机服务及实际病毒库，SCAP 需要受审核运行时与内容，不能把功能开关打开当作可用性证明。

[NotifyService.java](../server/alinksec-service/src/main/java/com/alinksec/service/notify/NotifyService.java) 当前将 HTTP 2xx 作为通用 Webhook 接纳成功，并丢弃响应体；这不能证明特定通知机器人业务成功或用户收到消息。实际通知通道应核对提供方响应契约和接收回执；如需业务响应校验，应实现相应适配或通过经验证的网关完成。不能将模拟 HTTP 返回 200 当作现场通知成功。

私有情报源、S3、WSUS／Windows Update 等按实际启用范围完成真实权限、失败保留、重试及恢复检查。对外发送测试通知要明确测试接收方和授权。

### 6. 运维可观测性、安全回归和交接

REV-010／009 原始发现分别涉及业务就绪和指标容量；当前源码已补依赖读写探测及有界指标队列，限定本地回归见 87 号。除修复外，还需在现场验证数据库不可用、存储满、队列积压、备份失败、Agent 离线和关键引擎失效能够被运维发现，并有对应处置入口。

统一审计当前采用失败不阻断业务的策略（[AuditService.java](../server/alinksec-service/src/main/java/com/alinksec/service/audit/AuditService.java)）；如果现场要求关键操作不可丢审计，需要补充持久化保障或经验证的外部审计方案。仅观察告警页面不能证明平台自身健康或完整审计。

候选产物应进行角色越权、Agent 身份绑定、上传／下载边界、敏感信息与依赖风险检查。当前 CI 包含前端生产依赖 `npm audit`，不能由此推定 Java、Go、基础镜像及运行时依赖都已完成同等检查。本次未执行依赖漏洞扫描，也没有据版本号宣称发现具体 CVE。

## 后续执行顺序与验收记录

1. **明确范围并建立隔离测试环境。** 记录部署模式、系统与架构、主机规模、启用引擎／来源、拟启用主动动作及可接受停机时间。使用独立身份材料和数据，准备测试主机恢复手段。
2. **复现并关闭相关缺陷，补齐目标差距。** 对照 REV-001～014 及 BKL-001～055 跟踪；优先身份边界、数据可靠性、状态顺序、资源上限和主动响应的准确性。没有执行的验收项保留待验证，范围取舍单独记录。
3. **生成固定候选并跑集成回归。** 绑定源码提交、镜像 digest 与 Agent SHA256，核查同一提交的完整必需 CI。验证安装、重启、证书、三角色、任务、结果、告警、异常与恢复。测试只能证明该候选，不复用历史 CI 替代。
4. **目标环境试点与故障演练。** 从明确的小范围开始，按启用功能验证实际系统与业务兼容性；执行持续负载、断网重连、后端故障、升级回退、备份及冷恢复。试点结果只覆盖实际规模和时长。
5. **生产准入评审。** 上线范围内 P1 清零，剩余 P2 写明影响、补偿和责任；核对现场证据、运维告警、备份／恢复目标、交接和回退方案。用户另行决定发布与生产部署。

## 防护效果与设计目标的对照

同日补充评估：依据[总体设计](01-总体架构与技术选型.md)中的用户态主机防护定位、断网自治、处置时延与诱饵响应目标，以及当前实现，结论是**基础监测、核查和有限场景响应已经具备，尚不能证明整体达到设计中的可靠阻断效果**。功能入口、受控样例通过和真实威胁覆盖率是不同证据，不能互相替代。

| 能力 | 当前实现与已记录证据 | 防护效果边界 |
| --- | --- | --- |
| 资产、基线、漏洞 | 原生采集、结构化核查、包身份和规则匹配、受控修复及复核 | 能支持已覆盖风险的发现与整改；不是漏洞利用实时阻断。旧资产覆盖、结果可靠性已做本地修复与限定回归，完整远端验收待办，见 87 号记录 |
| 登录与关键文件 | Linux SSH 日志检测、指定文件核验／恢复；Windows 指定登录事件检测和 WFP 响应 | Linux 内置登录／文件规则默认仅告警，封禁／恢复需明确启用；Windows 登录规则默认停用，不覆盖所有认证来源 |
| 进程规则 | 每 2 秒枚举，以路径／命令行规则检查新发现的进程实例 | 短命进程可能落在轮询间隙；启动和策略变更时已有进程被设为基线。不能按此承诺所有恶意行为一秒内阻断 |
| 病毒查杀 | 默认 SHA256 与内部模式规则，可选 ClamAV／原生 YARA；有扫描、隔离和恢复证据 | 受实际情报／规则和扫描范围限制。默认构建不含原生 YARA，ClamAV 需独立服务；受控无害样例未证明真实恶意软件覆盖率 |
| 勒索检测与响应 | 诱饵、速率快照、Windows 文件 ETW 归因和本地响应 | 不承诺阻止首次修改；速率条件依赖变更数量与扩展名变化比例。Linux 已移除猜测终止，没有可信写入者证据时保留告警／取证；可信归因与准确阻断仍由 BKL-055 跟踪 |
| 断网与隔离 | 本地规则继续运行、专用隔离看护和租约撤销 | 主机隔离依赖认证往返续租，失联后按期限撤销；不能解读为离线仍无限期隔离。新 Agent 普通报告先落盘并等待持久回执；旧服务端兼容、保留预算和集群接收边界见 87 号，完整验收仍待办 |
| 配置自保护 | 私有可信状态、配置检测和恢复、授权更新 | 用户态范围不保证抵御 root／Administrator 控制、Agent 进程被控制或操作系统被替换 |

进程路径见 [edr.go](../agent/internal/guard/edr.go) 与 [guard.go](../agent/internal/guard/guard.go)；勒索判定见 [ratemon.go](../agent/internal/guard/ratemon.go)。不改变扩展名的原地修改无法满足当前扩展名比例条件，该路径本身不会触发速率规则；诱饵或其他检测能否补充发现取决于实际触发，不可自动假定。Linux 原始错误归因与已实施的安全降级见 REV-011／87 号；后续可信归因能力见 BKL-055。

需要补充一组针对设计目标的受控效果验收，逐场景记录：

- 是否检出、未检出原因，以及命中的规则／情报版本；正常业务对照是否误报。
- 是否关联正确的文件和进程实例，是否误伤只读或无关进程。
- 从动作发生到检测、到实际阻断、到平台可见的分别耗时；不得用命令 ACK 代替威胁停止。
- 阻断前实际受影响文件数量、内容损坏情况及可恢复性；不把告警条数当作防勒索成功。
- 断网、Agent 重启、事件积压、引擎不可用及后端失败下的降级行为和证据完整性。

优先使用无害测试文件、受控操作和正常业务对照，在可恢复隔离主机执行。样本集合、平台和负载范围未固定且未完成测试前，不给出“达到设计的百分之多少”、检出率或零误报结论。REV-011 本地修复已取消 Linux 无证据自动终止，完整验收尚待 CI；可信写入者采集与准确阻断仍由 BKL-055 跟踪，不能作为已可靠验收的能力。

当前仍处于“已有验证基础，可以开展隔离测试，生产准入及完整防护效果证据不足”的阶段。初次评估仅更新复查文档；后续已经进行源码修复和限定本地回归。当前未关闭 REV、运行修复提交的完整远端 CI、改变现场验收状态或部署服务。
