# Windows 勒索进程归因与安全响应

本模块替换 Windows 的“最近启动进程”启发式。诱饵哈希检查仍每 60 秒执行，速率检测仍使用配置的快照周期；文件 ETW 用于记录操作证据，不直接产生勒索判定，也不承诺阻止第一次文件修改。

## 归因与响应

Windows amd64 Agent 在勒索防护启用时创建自有实时 ETW 会话，订阅 `Microsoft-Windows-Kernel-File`。通过 TDH 读取实际安装的提供程序元数据，关联文件打开、写入、重命名和成功完成事件。重命名以打开时的原路径关联，新路径保留在速率检测变更列表；成功改名后清除该句柄的旧路径映射，避免后续写入错误沿用旧名。记录文件路径、操作时间、执行线程所属 PID、原生进程创建时间和映像路径。创建时间以十进制字符串上报，避免浏览器数字精度丢失。

只有检测窗口完整处于有效采集期间、全部受影响路径都有成功操作证据、且证据指向同一个可核实的进程实例时，才允许按配置终止。事件头中的来源进程必须与执行线程的原生归属相符，或属于内核系统上下文；普通文件打开者、操作进程实例和完成事件也要保持一致，拒绝仅由事件载荷提供的身份。缓存回写可以使用由系统或 Agent 打开的内部文件对象，但其打开线程的原生归属与事件来源仍须核实，实际写入者也须独立核实；未核实的打开记录不享有该例外。终止前再次核对当前策略与归因证据，并在同一个进程句柄上重新核对创建时间和映像路径，拒绝 Agent 自身、系统 PID 和系统关键进程，等待退出确认。Windows 只终止已关联的进程，不推断终止父进程或后代；父链仍用于取证。

没有证据、进程已退出或无法访问、多个写入者、身份变化、采集缺口、过期、容量超限和事件丢失均跳过进程终止。排除进程降级为仅告警，保留证据。`kill_and_isolate` 的主机隔离独立由文件触发与配置决定，未归因时仍可能隔离；沿用认证隔离租约与失联撤销机制。

记录的是文件操作与进程实例的关联，不能单凭这些操作证明进程恶意或证明它是唯一修改来源。受控测试使用普通文件写入与重命名，不运行真实勒索软件。

## 系统范围与资源边界

需要 Windows amd64 原生 ETW/TDH API，以及允许创建和消费内核文件会话的 Agent 运行权限（通常为 LocalSystem/管理员）。不调用 Restart Manager，不修改审计策略、文件 SACL 或他人的 ETW 会话，也不安装驱动。

当前关联本机 DOS 驱动器目录路径。UNC/远程共享、映射网络盘、路径别名/硬链接、内存映射写入、跨进程继承或共享句柄、采集前已打开且未取得路径映射的句柄，以及事件到达前就结束的线程/进程，可能无法归因。缺少可核实证据时保留文件告警并跳过终止，不回退到最近进程或持有句柄进程猜测。

最多 64 个去重目录根、4096 个打开文件对象、4096 个待完成操作、4096 条成功操作、120 秒证据；速率周期超过 110 秒时停止精确归因。单次关联最多检查 4096 个受影响路径，上报最多 100 条文件操作。请求的 ETW 缓冲为 4–16 个 64 KiB 缓冲，并查询实际丢失计数。容量超限或采集异常后清空证据，停止会话并至少等待 30 秒重试；新会话建立新的证据时间边界。二进制哈希使用流式读取，超过 64 MiB 的文件不生成该取证哈希。

自有会话名称随机且与工作目录绑定，所有权记录和锁使用私有恢复目录。正常关闭释放会话；异常退出后，下一实例只有核实旧所有者已退出或 PID 已被复用，才清理该记录对应的会话。记录损坏、旧所有者仍存在或无法核验时拒绝接管，并报告采集不可用。

启动、关闭和异常状态通过 `windows-ransom-attribution` 自保护事件及 Agent 日志记录。它是发生时的状态历史，不代表逐主机当前覆盖证明，也不能据此把旧 Agent、离线主机或尚未收到状态的主机视为已覆盖。

## 告警证据

告警中心提供“查看归因证据”，展示当时的归因结果、进程实例、实际响应、排除与终止失败原因，以及有界文件操作。查看者可读证据，操作员保留原告警处置权限；手机使用适配视口的对话框。

服务端按归因状态、原因、进程实例和文件集合区分聚合，避免 PID 复用或未归因事件覆盖已确认实例的记录。勒索事件的去重记录与告警在同一事务内提交；失败后可重传，去重键绑定经过认证的 Agent 身份。

## 验证

2026-10-19 完成限定范围的模块验收。完整 CI：[CI39196235924](https://github.com/wybroot/alinksec/actions/runs/39196235924)（提交 `6ee165a`）；Windows amd64 在原生系统上连续三次执行以下 10 个受控场景，原始记录为 `windows-ransom-validation-windows-amd64/result.json`：

- 已关闭文件句柄的写入者能关联并终止，较新启动的无关进程存活。
- 只读和无关进程、多写入者、排除进程、创建时间不符时均拒绝终止。
- 仅改名关联原路径，批量写入与改名通过实际速率检测只终止关联写入者。
- 停止采集后旧证据失效，正常重启释放会话，所有者崩溃后只恢复自有会话。

原生单元测试另行验证事件来源与实际线程归属、进程/线程时间、普通共享对象与系统/Agent 缓存对象的信任边界。Linux amd64/arm64 的 Go 完整测试与竞态检查、现有 Agent 生命周期回归、SQLite/PostgreSQL 的告警保存/身份聚合/事务回滚重传，以及两个架构的生产页面检查均通过。手机检查展开文件证据并测量实际内容面板，验证横向与纵向边界；归因结果、完整实例字符串、查看者权限、操作员入口和失败重试均已核对。原生最高级别 `SEV_CRITICAL=5` 正确显示为“严重”，纳入严重筛选、总览和大屏统计；现有控制台 1–4 级映射保持兼容。截图保存在对应 `browser-validation-*` 产物。

本机约 2 GiB 的构建和浏览器尝试触发资源限制后停止；上述完整前端和跨平台验收以相同提交的 CI 为准，未提高本地内存上限。
