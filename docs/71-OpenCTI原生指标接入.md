# OpenCTI 原生指标接入

> 版本基线：v0.0.4。已按本版核对「OpenCTI 原生指标接入」的操作、实现引用与适用边界；历史日期及验证结果仍只对应其原始提交。版本差异见[发布说明](releases/v0.0.4.md)，全部资料见[文档索引](README.md)。

`opencti` 来源通过只读 GraphQL 查询拉取账号可见的完整 Indicator 集合，在本地应用明确的审核条件，再替换该来源的文件 SHA-256 特征。完整空集合也能撤销旧贡献。人工来源和其他来源继续按既有规则合并；多来源可信度策略属于后续第 18 项。

本模块实现服务端接入、来源身份固定、完整分页校验、事务发布、已知过期撤出和指标依据页面。无需修改 Linux/Windows Agent；Agent 仍使用已发布的哈希库。本模块的 HTTP、数据库和浏览器验证使用受控数据；官方 Schema 契约验证也不等于部署方真实 OpenCTI 实例联调，后者属于第 27 项。

## 配置与纳入条件

完整示例见 [libraries.example.yml](../deploy/libraries.example.yml)，默认关闭。部署方应使用受限只读账号，并保护配置文件和环境中的密钥：

```yaml
alinksec:
  libraries:
    sources:
      - id: opencti
        type: opencti
        enabled: false
        url: https://opencti.example.invalid/graphql
        api-key: ${ALINKSEC_OPENCTI_KEY:}
        opencti-tag: alinksec:malicious-file
        opencti-min-confidence: 75
        opencti-severity: 4
        interval-ms: 1800000
```

正式地址必须是 HTTPS，包含完整 `/graphql` 路径；可以有实例路径前缀。不允许 URL 用户信息、查询串、片段、路径百分号或点段。HTTP 只保留回环测试用途。不跟随重定向，不提供跳过 TLS 验证开关。密钥仅通过 `Authorization: Bearer` 请求头发送，不返回到来源状态、执行错误或治理记录。

账号须能读取自身身份、版本和 Indicator。接口和认证依据 [OpenCTI 集成文档](https://docs.opencti.io/latest/deployment/integrations/)与 [GraphQL API 文档](https://docs.opencti.io/latest/reference/api/)。查询契约固定核对官方 `7.261021.1` 的提交 `8588d03505b09f10ef8dfa3032f29697317b940f`；部署其他版本时仍应核对实际 Schema 和授权范围。

只有同时满足下列条件的指标才贡献哈希：

| 条件 | 处理 |
|---|---|
| 带配置的审核标签 | 按 `objectLabel.value` 完整匹配；不会把任意可见指标直接纳入 |
| `revoked=false` 且 `x_opencti_detection=true` | 撤销或关闭检测的指标保留判定依据 |
| 置信度达到阈值 | 缺失置信度不纳入；阈值允许 0～100，默认 75 |
| 模式为 `stix`，版本为 `2.0` 或 `2.1` | 其他模式或版本不猜测解释 |
| 完整单一等式 `[file:hashes.'SHA-256' = '64位十六进制哈希']` | 允许空白和哈希大小写；AND/OR/NOT、比较运算、时间限定及其他条件不纳入 |
| 已到 `valid_from` 且未到 `valid_until` | 缺少生效时间不纳入；结束时间允许为空 |

不同指标的相同 SHA-256 去重。本地严重程度由 `opencti-severity` 独立配置，允许 1～5，默认 4；它不表示上游置信度。未来才生效的指标不会在断网时自动激活，需要后续完整同步重新核验。

## 完整分页与事务

每轮查询所有可见 Indicator，在本地筛选审核标签。没有把标签文本误传为 OpenCTI 标签 ID 过滤器，也没有用“最近修改页”替换全库。查询使用 `created_at` 升序、每页 200 条，检查每页 `globalCount`、`hasNextPage`、`endCursor`、边游标和节点 ID。

任一请求失败、GraphQL `errors` 非空、身份或版本跨页变化、总数变化、重复 ID/游标、游标不前进、页数或字节数超界、字段类型/日期非法、最终数量不完整，都拒绝整个候选集合。HTTP 304 不作为成功完整集合。对合法但不支持的模式记录筛选原因，对无法可靠识别的损坏记录拒绝本轮。

OpenCTI 分页查询不是跨请求的原子数据库快照。以上检查能发现计数、身份和分页异常，但不能证明拉取期间所有已读取指标均未被并发修改；后续定时完整同步继续核对变化。账号权限调整也会改变该账号的可见集合。

拉取在数据库事务外进行。进入现有来源锁和发布事务后，再核对来源配置、账号身份、上次快照修订号与退役状态，然后一起提交当前指标依据、筛选结果、来源哈希、库版本和审计。另一轮已提交、来源已退役、容量超限或文件/对象存储发布失败，都保留之前的当前依据与有效库。不会边拉边删除旧贡献。

首次成功后固定来源类型、URL、审核标签、置信度阈值、严重程度和 OpenCTI 账号 ID。相同账号可以轮换密钥；改变账号或范围须使用新来源标识，并按需退役旧来源。不能把已经固定的来源改成通用 `hashes` 来绕过边界，也不允许复用已有特征或漏洞数据的标识进行首次绑定。

## 撤销、过期与交付

- 完整集合中消失、被撤销、关闭检测、失去审核标签、降低置信度或不再有效的指标，不再贡献本来源哈希。其他来源仍贡献相同哈希时，它仍会存在于合并库。
- 通过全部完整性校验的零指标集合、或零有效哈希集合，可以清空本来源；最后一个有效来源清空时发布受控零特征版本。人工空包和通用远端空包仍遵循原有拒绝规则。
- 已纳入指标的结束时间持久化保存。串行任务空闲时，服务端每分钟优先检查已知过期指标；正在执行的有界任务会先完成。暂停同步、移除来源配置或远端不可用时仍能撤出。未设置结束时间的指标必须等待下一次成功完整同步才能获知上游撤销。
- 已知过期撤出和发布仍是一个事务。发布失败保留之前已发布状态，页面显示待撤出及固定错误并继续重试；不会把失败描述为撤销已送达。
- 发布成功后的即时推送失败会显示“Agent 下发待重试”；相同快照的后续同步也会重试，已有定时分发和连接时更新继续工作。离线 Agent 在收到正常库更新前仍可能使用旧特征，不保证主机在有效期瞬间清除旧库。
- 来源退役保留指标依据和历史，阻止晚到同步提交；移除配置后仍可从“来源治理”查看保留的指标依据。

## 容量、依据和页面

| 边界 | 默认值及硬上限 |
|---|---|
| 每页节点 | 200 |
| 每来源当前指标 / 单轮页数 | 25,000 / 128，可向下配置 |
| 单页响应 / 单节点保留字段 | 4 MiB / 16 KiB |
| 单轮响应和当前节点总字节 | 各最多 32 MiB，可向下配置单轮上限 |
| 单请求 / 全轮时间 | 默认 10 秒、最多 30 秒 / 最多 180 秒 |
| 所有来源当前节点总量 | 最多 100,000 个、128 MiB |
| 保留的原生来源身份 | 最多 64 个，包括退役来源 |
| 原生快照及过期审计 | 每来源合计保留最近 50 条；其他治理事件不由此清理 |

保留的是查询返回的所选指标字段 JSON、对应 SHA-256、纳入原因和已知结束时间，不是完整 STIX 对象或每次 HTTP 原始响应。审计另保留每页响应摘要、完整集合摘要、决策数量和发布版本；当前节点随成功快照替换，不承诺全部旧节点版本永久归档。读取当前节点时校验其保留字段摘要。退役来源仍计入容量，超过上限时拒绝新提交，不静默删除旧依据。

管理员、运维和只读角色均可查看指标列表与所选字段；只有管理员可同步、修改计划或退役来源。界面显示审核条件、可见指标和有效哈希数量、模式筛选原因、上游版本、快照摘要、最近拉取与有效期检查时间。请求错误不显示为合法空集合，关闭页面后拒绝晚到详情覆盖。

新增读取接口：

```text
GET /api/libraries/sources/{id}/indicators?page=1&size=20
GET /api/libraries/sources/{id}/indicators/{indicatorId}
```

分页大小最多 100。已有同步、计划和来源治理接口继续使用既有授权。SQLite/PostgreSQL 共同迁移 `V030` 增加两张表；总迁移数 30、表数 86，迁移与镜像冒烟仍保留严格数量检查。

## 验证与范围

`OpenCtiAdapterTest` 检查完整模式、生命周期、字段类型、严格 JSON、配置和身份摘要；`OpenCtiIntegrationTest` 使用真实 HTTP、多连接 SQLite/PostgreSQL 和实际控制器，覆盖完整分页、重复哈希、撤销、空集合、失败保留、发布回滚、并发旧快照、到期重试、退役竞争、角色权限和依据完整性。

`deploy/tests/opencti-schema-capture.py` 下载固定官方提交中的三个原始 SDL，核对 Git blob 和 SHA-256。`deploy/tests/opencti-contract/check.mjs` 从原始类型中提取实际查询字段、参数类型、空值限制和枚举，验证生产查询并用数据库捕获的节点执行受控响应；错误字段、枚举和变量类型须被拒绝。它没有启动真实 OpenCTI，也不冒称完整服务 Schema 验证。

生产构建页面检查读取上述真实 SQLite REST 响应，覆盖管理员同步、运维/只读访问、手机页面、请求错误、空集合、待过期撤出、推送重试和晚到响应。后四类异常状态由浏览器明确注入。完整 CI 和最终提交证据完成前，本模块不标记验收完成。

不包含通用 STIX 解释器、TAXII/SSE、OpenCTI 写入或连接器注册、CVE 到包适用性推断，以及真实外部实例、规模或长期运行验收。备用 `opencti-export` 桥接继续可用，同一数据集应选择一种来源路径，避免重复贡献。
