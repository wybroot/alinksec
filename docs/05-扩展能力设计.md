> 版本：V1.0（设计评审稿）
> 日期：2026-08-25
> 关联文档：01（架构）、02（proto）、03（表结构）、04（Agent 模块）

## 1. 病毒查杀

### 1.1 引擎架构（双层）

```
文件对象
   │
   ▼
L1 哈希情报层（纯 Go，零依赖）
   ├─ SHA256 精确匹配情报库（平台特征库包内 hash list）
   ├─ clean 缓存：path+size+mtime 未变 → 跳过（增量扫描加速，命中率 > 95%）
   └─ 命中 → 直接产出 finding
   │ 未命中
   ▼
L2 YARA 规则层（CGO 静态链接 libyara，go-yara v4）
   ├─ 规则按平台分片加载（linux/windows 规则集）
   ├─ 扫描对象过滤：仅 PE/ELF/脚本/office 文档类扩展 且 < 50MB
   └─ 命中 → 产出 finding（规则名即检出名）
```

- **许可合规**：YARA 为 BSD-3，可嵌入闭源商业产品。
- **构建**：CGO 交叉编译需 musl（linux/amd64、arm64）与 mingw（windows/amd64）工具链，CI 固化；提供 `yara` 构建标签，受限环境可降级为 **hash-only 构建**（功能降级但可交付）。
- **明确边界**：本引擎定位"已知恶意样本查杀"（挖矿/蠕虫/后门/勒索家族），**不做未知启发式判定**（零日检出依赖勒索诱饵与行为防护补位）。

### 1.2 特征库管理

| 项 | 设计 |
|----|------|
| 组成 | 哈希情报清单（文本）+ YARA 规则源（或预编译）+ manifest（版本、计数、sha256） |
| 更新 | 平台侧离线导入（客户内网场景）→ 存储 MinIO `alinksec-signature` 桶 → `CmdSignatureUpdate{db_version, download_url(预签名1h), sha256}` 下发 |
| Agent 侧 | 限速下载（2MB/s）→ sha256 校验 → 本地原子替换 → ACK；断网沿用本地库 |
| 增量 | 一期为**全量包**（包体 < 20MB，1.x 万哈希 + 数百规则）；二期演进 manifest diff 增量 |
| 版本追踪 | 心跳可扩展上报 db_version（与 policy_version 同机制），低于平台当前版本即触发更新指令 |

### 1.3 扫描模式

| 模式 | 范围 | 触发 | 说明 |
|------|------|------|------|
| 快速扫描 | 关键路径：Linux `/tmp /var/tmp /dev/shm /root /home` 下载目录、cron/systemd unit 目录；Windows `%TEMP%`、Downloads、启动文件夹、ProgramData | 手动 / 定时策略（默认每周一次） | 分钟级完成 |
| 全盘扫描 | 全部本地盘 | 手动（需维护窗口建议） | **IO 限速默认 10MB/s**（可配），排除目录/扩展名/超限大文件（默认 >500MB 跳过）可配 |
| 实时防护 | guard 文件事件通道监听目录（= 快扫路径 + 防篡改路径） | 文件 CLOSE_WRITE 事件 | L1 缓存命中跳过；仅疑似对象进 L2；单文件扫描超时 2s 放行并计数告警 |
| 自定义 | 指定路径 | 手动 | `CmdVirusScan(mode=CUSTOM, paths)` |

### 1.4 处置动作

| 动作 | 实现 |
|------|------|
| 隔离（默认） | 移动至本地隔离目录（权限 000 / Windows 拒绝 ACL），记录原路径+哈希；样本限速上传 MinIO 证据桶（可关闭，内网带宽敏感） |
| 删除 | 直接删除（需二次确认，默认不启用） |
| 恢复 | 从隔离区移回原路径（人工发起，`CmdVirusAction(RESTORE)`） |
| 加白 | path 或 hash 白名单，**平台全局生效**（`t_virus_whitelist`），不做 Agent 本机持久白名单（防绕过） |

实时防护检出复用 `RptSecurityEvent(type=virus)` 走告警聚合；任务扫描走 `RptVirusResult`。

### 1.5 表与指令

- 表：`t_virus_db`（特征库版本）、`t_virus_scan_task`、`t_virus_finding`、`t_virus_whitelist`（详见 03 §2.7）
- 指令/上报：`CmdVirusScan` / `CmdVirusAction` / `CmdSignatureUpdate` / `RptVirusResult`（详见 02 proto）

## 2. 勒索诱饵防护

### 2.1 原理

用户态实现，双触发、本地秒级响应，**不依赖服务端在线**：

1. **诱饵篡改**（高置信）：诱饵文件被写入/修改——正常业务几乎不可能触碰
2. **加密行为速率**（行为侧）：受监听目录树 10s 滑动窗口内 >50 个文件被写入/重命名、且扩展名变化率 >80% —— 典型加密拖尾特征

### 2.2 诱饵部署

- **本地生成**（不依赖平台下载）：文件名模板池随机组合——"财务报表 / 2026合同 / 备份 / 密码本 + 日期 + xlsx/docx/pdf/sql.zip"，内容为随机字节 + 对应格式文件头。
- 投放目录由防护策略下发：默认 Linux `/home/*`、`/srv`、`/opt`（共享目录）；Windows 公共文档/桌面/共享目录；每目录默认 4 个。
- 定期健康检查（60s）：诱饵**丢失** → 低危告警（可能是正常清理）；诱饵**被改** → 触发响应链。

### 2.3 触发响应链（本地立即执行）

```
诱饵被写 / 速率异常触发
   ├─ ① 归因：Linux 经 /proc/*/fd 反查写入进程 inode；
   │        Windows 经 Restart Manager API 查锁定进程
   ├─ ② kill 涉事进程（含进程链取证：pid/ppid/exe/cmdline/SHA256）
   ├─ ③ 主机隔离（复用 ISOLATE_HOST 机制，含 10s ACK 超时自动回滚安全垫）
   ├─ ④ 证据快照：进程链 + 最近改动文件列表（前 100 个，含前后哈希）
   └─ ⑤ RptSecurityEvent(type=decoy_tamper / ransom_behavior, severity=critical)
```

- 响应级别可配：`alert_only` / `kill` / `kill_and_isolate`（默认 `kill_and_isolate`——勒索场景晚一秒多加密一批文件）。

### 2.4 误报防护

| 措施 | 说明 |
|------|------|
| 进程排除清单 | 备份/杀毒/索引/同步盘类进程按 exe 路径排除（内置常见备份软件路径，平台可配） |
| 诱饵目录选址 | 避开业务工作区与代码目录，只投文档/共享类目录 |
| 速率阈值可调 | 高写入业务（日志汇聚节点）单独调阈值或关闭速率触发，保留诱饵触发 |
| 隔离回滚安全垫 | 复用现有 10s ACK 机制，误隔离自动回滚 + 告警说明 |

### 2.5 规则存储

复用防护规则表：`t_protect_rule.type` 扩展 `decoy` / `ransom_behavior`，match 结构：

```yaml
- id: PR-0010
  type: decoy
  match: {dirs: ["/home", "/srv"], count_per_dir: 4,
          exclude_exes: ["/usr/bin/rsync", "D:\\backup\\agent.exe"]}
  actions: [kill, isolate_host, alert]
  severity: critical
- id: PR-0011
  type: ransom_behavior
  match: {rate_window_sec: 10, rate_threshold: 50, ext_change_ratio: 0.8,
          watch_trees: ["/srv/share", "/home"]}
  actions: [kill, isolate_host, alert]
  severity: critical
```

## 3. 漏洞一键修复

### 3.1 两类修复，两种风险等级

| 类别 | 对象 | 方式 | 风险控制 |
|------|------|------|----------|
| **配置类** | 基线核查项、配置型漏洞 | 真正"一键"：Agent 自动修复 | 改前备份 → 执行 → 复核（重跑 check）→ 失败自动回滚 |
| **软件包类** | CVE 对应软件包 | 审批 + 维护窗口 | 人工审批 + 窗口约束 + 修复后自动重扫验证 CVE 清除；**不自动回滚**（降级风险大于收益） |

### 3.2 配置类修复规范（t_baseline_item.fix_spec JSONB）

```json
{
  "risk": "auto",
  "steps": [
    {"action": "sysctl_set", "key": "net.ipv4.tcp_syncookies", "value": "1"},
    {"action": "file_line_ensure", "path": "/etc/pam.d/sshd",
     "line": "auth required pam_faillock.so preauth", "position": "append"},
    {"action": "chmod", "path": "/etc/passwd", "mode": "0644"}
  ],
  "requires_restart": "sshd"
}
```

- action 集合：`sysctl_set` / `file_line_ensure`（存在性保证）/ `file_replace`（regex 替换）/ `chmod` / `chown` / `service_restart` / `registry_set`（Win）/ `audit_rule`
- **执行器（fixer）事务化**：备份全部目标（文件副本+原属性）→ 按序执行 → 复核（重跑 check）→ 失败全量回滚 → 上报 `rolled_back`
- `requires_restart` 的服务重启动作单独开关（客户可能不接受业务瞬断，默认仅提示）

### 3.3 软件包类修复流程

```
漏洞清单 → 勾选生成修复任务（含目标版本）→ 审批人确认 + 维护窗口
   → 平台校验补丁仓库覆盖率（t_patch_package 是否含目标包；缺 → 任务阻断并提示导入）
   → CmdVulnFix 下发 {fixes: [{ref_id, type=PACKAGE, payload}]}
   → Agent 前置检查（磁盘空间 / 依赖冲突 / 运行中服务提示）
   → 包管理器安装：
       Linux yum/dnf: --repofrompath=alinksec:https://platform-repo/...（临时源，不污染客户 repo 配置）
       Linux apt: 临时 sources.list.d 条目，安装后删除
       Windows: 平台补丁库 MSU → wusa /quiet /norestart；或配置指向客户 WSUS
   → 修复后自动重扫该软件关联 CVE → 复核结果上报
   → 需重启则标记 reboot_required（由客户在窗口内自行重启，平台展示待重启清单）
```

- **不自动重启主机**，一律标记待重启。
- rpm 环境记录旧版本号（供人工降级参考）；deb/msu 不承诺回滚能力，SOW 与报告中明示。

### 3.4 离线补丁仓库（平台侧）

- MinIO `alinksec-patch` 桶，结构：`{os}/{pkg_name}/{version}/`（rpm/deb/msu + 仓库索引）。
- Linux 索引：createrepo_c / dpkg-scanpackages 生成，Agent 侧包管理器直接可用。
- **运营责任**：内网客户无法自动同步上游，补丁导入为实施/运维离线操作——交付 SOW 中明确约定（覆盖常见发行版安全更新，按客户环境定制）。

### 3.5 表与指令

- 表：`t_fix_task`、`t_fix_record`、`t_patch_package`（详见 03 §2.8）
- 指令/上报：`CmdVulnFix` / `RptFixResult`（详见 02 proto）
- 基线表新增 `fix_spec` 列（03 §2.2 已修订）

## 5. 新增风险与对策

| 风险 | 对策 |
|------|------|
| YARA CGO 交叉编译复杂 | CI 固化 musl/mingw 工具链矩阵；保留 hash-only 构建标签降级 |
| 病毒全盘扫描冲击业务 IO | 默认限速 10MB/s + 排除目录；全盘仅手动/定时窗口触发 |
| 诱饵误杀备份作业 | 进程排除清单（内置常见备份软件路径）+ 响应级别可配 + 隔离 10s ACK 回滚安全垫 |
| 补丁仓库运营成本 | SOW 明确导入责任；修复任务前强制仓库覆盖率校验，缺包阻断 |
| 包升级破坏客户业务 | 强制审批 + 维护窗口 + 修复后复核 + 不自动重启；回滚能力在报告中如实标注 |
| 特征库更新滞后 | 版本心跳比对自动触发更新；勒索类风险由诱饵防护补位，不单依赖特征库 |

## 6. 容器安全（后续版本）

首期仅支持 Linux Docker 工作负载清点，不执行容器停止、删除、重启或网络变更。Agent 使用本机 `docker ps` 和 `docker inspect` 的只读查询；Docker CLI 不可用、守护进程不可达或当前账户无权限时，采集器返回空快照且不影响软件、端口、账户等其他资产上报。

### 6.1 数据契约

`RptAssetSnapshot` 新增 `containers`，每项包含 `container_id`、`name`、`image`、`image_id`、`status`、`created_at`、`started_at`、`ports` 与 `labels`。服务端以 `(agent_id, container_id)` 标识当前快照，并在下一次快照时全量替换该主机的容器资产。

镜像名称与标签仅用于盘点和筛选，不解析或展示 Docker 环境变量、挂载内容、命令行中的密钥，避免将容器凭据带入平台数据库和审计日志。

### 6.2 权限与边界

- Linux Agent 仅需执行只读 Docker 查询；不挂载 `/var/run/docker.sock`，也不授予 Docker API 写权限。
- 页面只展示运行状态、镜像、端口和非敏感标签；容器策略和处置动作留待后续安全评审后实现。
- Kubernetes 不通过宿主机 Docker 数据推断。后续采用独立的受限 ServiceAccount、只读 List/Watch 权限和显式集群接入配置，另行设计命名空间隔离与多节点去重。
