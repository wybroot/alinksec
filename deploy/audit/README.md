# 可选 Linux 执行审计输入

此入口消费管理员配置的 auditd 日志，不安装内核探针、不修改主机审计策略。默认关闭。它补充 2 秒进程轮询：已退出进程仍可按已记录的路径／命令行匹配；不是完整 EDR，也不能证明未发生攻击。

1. 在测试 Linux 主机确认 auditd、内核审计和 `/var/log/audit/audit.log` 可用，Agent 有读取权限；日志应仅由可信管理员和审计服务写入。先评估执行事件量、磁盘轮转、audit backlog 和丢失计数。
2. 审阅 `alinksec-exec.rules.example`，按主机架构和现有审计策略安装带 `alinksec_exec` 键的执行规则。示例仅覆盖原生 64 位 syscall；兼容 32 位程序需要另审 b32 规则。遵循发行版的规则加载流程，不清空现有规则。审计 immutable 模式可能需要维护窗口。
3. 将 `process-rules.yaml.example` 合并到现有 Agent 配置后重启 Agent。不要覆盖连接配置。服务端下发 `process_rules` 会替换本地规则，应在平台策略中保留所需规则。两条规则仅为命令行线索，可误报合法矿工、脚本或包含示例字符串的命令；按业务审核，不自动终止。
4. 验证收到 `linux-process-audit` 状态。`reading_unverified` 仅表示可读；`execution_records_observed` 表示见到带指定键的完整执行证据，不证明内核没有丢失事件。
5. 使用无网络的短命命令，例如 `/usr/bin/printf '%s\n' 'stratum+tcp://acceptance.invalid'`，应产生 `linux_audit_exec` 来源、仅告警的匹配；普通 `printf hello` 不应匹配。此例验证检测管道，不能视为真实挖矿检测验收。改名程序、跨日志轮转、服务重启、权限撤销、容量溢出须在目标环境另验。

按节点与 audit 时间／序号关联 SYSCALL 和 EXECVE；必要字段和全部参数收齐即可检查，不依赖 EOE 或仍存在的 `/proc/PID`。历史 PID **永不用于终止**，即使规则包含 kill。最大 128 个待关联事件、256 个参数、16 KiB 参数文本；超限、分片参数和不完整事件不作安全判定。日志不可读、截断和容量缺口上报状态。关联状态保存在 Agent 私有目录，原始参数不上传服务器；告警命令行沿用脱敏，但配置和私有状态仍须限制访问。

此实现不保证完整事件投递：沿用 Agent 现有事件队列语义，崩溃窗口、audit 内核丢失、轮转、未覆盖架构和超限均可能漏检。用户名按当前主机 UID 数据库解析，不代表历史账户名。没有注入、提权、凭据窃取或无命令行线索的通用行为检测；Linux 勒索写入者归因仍不可用。
