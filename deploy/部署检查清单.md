## 1. 发布前检查（构建机）

- [ ] 工作区为预期提交：`git status --short` 无非预期改动，`git rev-parse --short HEAD` 已记录到上表。
- [ ] 服务端测试通过：`cd server && mvn -B test`。
- [ ] Agent 测试通过：`cd agent && go test ./...`。
- [ ] 前端构建通过：`cd web && npm ci && npm run build`。
- [ ] Linux Agent 已生成：`GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o ../release-bin/alinksec-agent-linux-amd64 ./cmd/agent`。
- [ ] 如需 Windows Agent，已生成 `release-bin/alinksec-agent-windows-amd64.exe`。
- [ ] 已按完整部署文档第 2 节生成 `alinksec-release.zip`。压缩包必须包含完整的 `server/`、`web/`、`deploy/`，不能只包含 JAR。
- [ ] 已生成并记录发布包校验：`Get-FileHash .\alinksec-release.zip -Algorithm SHA256`。

## 2. 服务器基础条件

- [ ] 服务器为受支持的 Linux x86_64：`uname -m` 输出 `x86_64`。
- [ ] Docker 与 Compose v2 可用：`docker version`、`docker compose version`。
- [ ] 内存不少于 4 GB：`free -h`；可用磁盘不少于 20 GB：`df -h`。
- [ ] 9443、8443、8081 未被其他服务占用：`ss -tlnp | grep -E '9443|8443|8081'` 无输出。
- [ ] 已确认 Agent 可路由到服务器的部署地址；不要使用 `127.0.0.1` 作为 `HOST_IP`。
- [ ] 已准备防火墙规则：仅对受管主机和管理网放行 TCP 9443、8443；8081 仅用于 HTTP 跳转，可不对外开放。

## 3. 上传与密钥配置

```bash
mkdir -p ~/alinksec
unzip -q /path/to/alinksec-release.zip -d ~/alinksec
cd ~/alinksec
test -f server/pom.xml
test -f web/package-lock.json
test -f deploy/docker/docker-compose.yml
test -f deploy/sql/001_init.sql

cd deploy/docker
cp .env.example .env
chmod 600 .env
```

- [ ] 上述四个 `test` 命令均成功，发布目录结构完整。
- [ ] `.env` 的 `HOST_IP` 已设置为受管主机实际访问的服务器 IP。
- [ ] `ALINKSEC_BOOTSTRAP_ADMIN_PASSWORD` 已设置为长度至少 12 位的随机管理员初始密码。
- [ ] `ALINKSEC_BOOTSTRAP_ENROLL_TOKEN` 已设置为随机、仅限首次测试主机使用的注册码。
- [ ] `ALINKSEC_POSTGRES_PASSWORD` 已设置为随机数据库密码。
- [ ] 建议已设置 `ALINKSEC_JWT_SECRET`：`openssl rand -base64 48`。该文件不会提交到代码仓库或发送到日志、工单。
- [ ] 已通过 Compose 配置预检：`docker compose config -q`。

## 4. 首次启动与容器检查

```bash
cd ~/alinksec/deploy/docker
docker compose build
docker compose up -d postgres
docker compose ps
docker exec alinksec-pg pg_isready -U alinksec -d alinksec
docker exec -it alinksec-pg psql -U alinksec -d alinksec -c "\dt"
docker compose up -d
docker compose ps
```

- [ ] `postgres` 状态为 `healthy`，并可见 `t_agent`、`t_user`、`t_alert`、`t_command`、`t_audit_log`、`t_policy_state` 等关键表。
- [ ] `alinksec-pg`、`alinksec-vm`、`alinksec-server`、`alinksec-web` 均为运行状态。
- [ ] 服务端日志包含 gRPC 启动与 Bootstrap 成功信息：`docker compose logs --tail=100 server | grep -E 'gRPC|Bootstrap'`。
- [ ] 未出现循环重启、数据库认证失败、证书生成失败或 nginx 等待证书超时。
- [ ] 已放行防火墙：CentOS/RHEL 使用 `firewall-cmd --permanent --add-port=9443/tcp --add-port=8443/tcp && firewall-cmd --reload`；Ubuntu 使用 `ufw allow 9443/tcp && ufw allow 8443/tcp`。

## 5. TLS、控制台与大屏

```bash
cd ~/alinksec/deploy/docker
docker exec alinksec-server ls /app/data/certs
docker cp alinksec-server:/app/data/certs/ca.crt ./alinksec-ca.crt
curl --cacert ./alinksec-ca.crt -s -o /dev/null -w "%{http_code}\n" https://127.0.0.1:8443/
curl --cacert ./alinksec-ca.crt -s https://127.0.0.1:8443/api/auth/login -X POST \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<替换为 .env 中的管理员密码>"}'
```

- [ ] `ca.crt`、`ca.key`、`server.crt`、`server.key` 均存在。
- [ ] 首页 HTTPS 请求返回 `200`；登录接口返回 `code: 0` 与 token。
- [ ] 已将导出的 `alinksec-ca.crt` 安全导入管理终端的信任库。
- [ ] 浏览器可打开 `https://<HOST_IP>:8443/` 并以 `admin` 登录。
- [ ] 浏览器可打开 `https://<HOST_IP>:8443/screen`，大屏正常渲染、时间持续刷新。
- [ ] 首次登录后已修改管理员初始密码，并从密码管理器或受控密钥库取回，不在部署记录中明文保存。

## 6. 首台 Agent 接入

### Linux

```bash
sudo install -m 0755 /path/to/alinksec-agent-linux-amd64 /usr/local/bin/alinksec-agent
sudo /usr/local/bin/alinksec-agent install \
  --server <HOST_IP>:9443 \
  --token <ALINKSEC_BOOTSTRAP_ENROLL_TOKEN> \
  --ca-file /path/to/alinksec-ca.crt
sudo /usr/local/bin/alinksec-agent run
```

- [ ] 安装命令返回 `agent_id`，`/var/lib/alinksec-agent/` 包含 `agent.yml`、`ca.crt`、`client.crt`、`client.key`、`state.yml`。
- [ ] 前台运行日志出现“主通道已建立”和策略同步完成；确认后按完整部署文档第 8.1 节配置 systemd 常驻。
- [ ] `systemctl status alinksec-agent` 显示 `active (running)`。

### Windows（如适用）

```powershell
New-Item -ItemType Directory -Force C:\alinksec | Out-Null
Copy-Item .\alinksec-agent-windows-amd64.exe C:\alinksec\alinksec-agent.exe
Copy-Item .\alinksec-ca.crt C:\alinksec\ca.crt
& C:\alinksec\alinksec-agent.exe install --server <HOST_IP>:9443 --token <注册码> --ca-file C:\alinksec\ca.crt
```

- [ ] Windows 安装命令成功，并按完整部署文档第 8.2 节创建和启动服务。
- [ ] Windows 服务状态为 `RUNNING`，且可从平台看到主机在线。

## 7. 接入链路与功能冒烟验证

在服务器执行：

```bash
alias psqla='docker exec -it alinksec-pg psql -U alinksec -d alinksec'
psqla -c "SELECT hostname, status, last_heartbeat FROM t_agent ORDER BY last_heartbeat DESC;"
psqla -c "SELECT type, status, result FROM t_command ORDER BY id DESC LIMIT 10;"
psqla -c "SELECT token, used_count, max_uses, status FROM t_enroll_token;"
```

- [ ] 目标主机在控制台“主机管理”中显示在线；`t_agent.status=1`，`last_heartbeat` 持续更新。
- [ ] 最新 `policy_sync` 指令已闭环完成，`t_command.status=4`，执行结果无错误。
- [ ] 注册码 `used_count` 已增长；完成首台验证后，在控制台创建用途和有效期受限的新注册码，避免继续共用 bootstrap token。
- [ ] 首页的在线主机、资源趋势和告警数据可加载；安全大屏的主机数与控制台一致。
- [ ] 至少执行一次低风险的业务验证（例如资产采集或基线核查），并确认结果、审计记录和告警中心均有对应数据。
- [ ] 如启用了实时防护，先在测试主机验证策略下发和 ACK，不在未验证主机上直接执行隔离、查杀、修复或 Agent 卸载。

## 8. 备份、交接与上线结论

```bash
cd ~/alinksec/deploy/docker
mkdir -p ../../backups
stamp=$(date +%F-%H%M%S)
docker exec alinksec-pg pg_dump -U alinksec -Fc alinksec > "../../backups/alinksec-${stamp}.dump"
docker run --rm -v alinksec_server-data:/source:ro -v "$(cd ../../backups && pwd)":/backup \
  alpine tar czf "/backup/server-data-${stamp}.tgz" -C /source .
sha256sum "../../backups/alinksec-${stamp}.dump" "../../backups/server-data-${stamp}.tgz"
```

- [ ] 已在首次上线前完成 PostgreSQL 与 `server-data` 备份，校验和已记录，并将备份与 `.env` 存放在受控位置。
- [ ] 已确认不会使用 `docker compose down -v`；该命令会删除 PostgreSQL、指标、证书和应用数据卷。
- [ ] 已记录日志入口：`docker compose logs -f server`、`docker compose logs -f web`、`docker compose logs -f postgres`，以及 Linux Agent 的 `journalctl -u alinksec-agent -f`。
- [ ] 已明确升级前先备份。`001_init.sql` 只用于空数据库首启，不会自动迁移已有生产库。
- [ ] 已完成部署记录，管理员账号、CA 文件、备份、注册码和升级责任人已交接。

## 9. 未通过时停止条件

- [ ] 若 `HOST_IP` 写错或证书 SAN 不含实际地址，停止后续 Agent 接入。只有在尚未接入生产 Agent 时，才可按完整部署文档的 TLS 排障步骤重建 `server-data`；重建后所有已签发客户端证书均失效。
- [ ] 若 PostgreSQL 初始化失败或关键表缺失，停止业务容器启动，先查 `docker compose logs postgres`；不要在已有生产卷上反复删除数据。
- [ ] 若 HTTPS、gRPC 或 Agent 主通道未验证通过，禁止开始批量安装和任何高风险处置操作。
